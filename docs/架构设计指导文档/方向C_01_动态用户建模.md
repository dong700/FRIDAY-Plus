## 1. 摘要

模块 1（M1，动态用户建模）是 Lucy "活着感" 的**感知基础**。新架构下主脑是外部 LLM API（DeepSeek/OpenAI 兼容），被调用才说话、权重只读、无自发主动性；副脑（M2，Qwen2.5-3B + V30 ckpt）要决定"现在该不该说、该说什么方向"，必须先知道**用户与他人现在是什么状态**——在场吗、注意 Lucy 吗、情绪如何、在想什么、和 Lucy 是什么关系、之前说过什么。这些信息由 M1 持续维护，以 `Dict[user_id, PersonState]` 的形式写入共享内存，供 M2 以纯内存读（~5μs）的方式无阻塞获取。

M1 的核心特征是**AI 驱动的实时建模 + 多人物支持**：

- **10Hz 本地基线**：情绪/注意力/在场检测走本地轻量管线（<80ms/tick），用规则 + TFGR 时间流图维护实时字段，**不调主脑 API**，绝不阻塞 α 路径。
- **β 路径异步深度建模**：当本地规则置信度不足（意图模糊、关系漂移），M1 经 M3 的"分析通道"异步调主脑 API 做意图/关系推断，结果回写 `PersonState`，失败则回退本地规则。
- **多人物建模**：`PersonState` 按人物隔离，主用户固定 `user_id="user"`，他人按识别 id 索引；参考 v18 的 `SEED_DIALOGUE` 多人物设定（小明/小红/老王），让 Lucy 能区分"现在和小红聊画展"与"问老王病情"。
- **解耦降级**：M1 不依赖 M2/M3 完成自身 10Hz 更新；M1 挂了，M2 用最后快照降级运行（主文档 §5.2 要求）；M3/API 不可用时，M1 退回纯本地规则。

### 1.1 核心数据契约

```python
@dataclass
class PersonState:
    """单人物状态。字段与主文档 §5.2 UserState 严格一致（12 字段）。"""
    user_id: str
    name: str
    presence: bool              # 是否在场（视觉/语音检测）
    attention: float            # 注意力（看向 Lucy 的程度 0..1）
    emotion_valence: float      # 情绪效价 -1..1
    emotion_arousal: float      # 情绪唤醒 0..1
    last_speech_end: float      # 上次说话结束时间戳（单调秒）
    silence_duration: float     # 沉默时长（秒）
    current_topic: str          # 当前话题
    unresolved_intents: List[str]  # 未解决意图
    known_facts: Dict[str, str]     # 已知事实（来自 TFGR 图检索 + 当轮提取）
    relationship: str           # 关系类型（friend/colleague/mentor/family/stranger）

# 共享内存契约：多人物状态表，主用户固定 key="user"
UserStateMap = Dict[str, PersonState]
```

> **与主文档 §5.2 的一致性**：`PersonState` 的 12 个字段与主文档 §5.2 `UserState` 完全对齐（字段名、类型、取值范围逐项一致）。本文档将主文档的单人物 `UserState` 扩展为多人物 `Dict[user_id, PersonState]`，是主文档 §5.2 契约在多人物场景下的超集——单人物退化为 `{"user": PersonState}`，不破坏原契约。

|------|------|------|------|---------|------|

| β 路径 | 事实深度抽取（经 M3 调主脑 API，分析模式） | 2-5s | 2s | 否 | 异步，复杂句触发 |

## 2. 模块定位

### 2.1 在整体架构中的位置

M1 位于主文档分层架构的 **Layer 3**（动态用户建模），向下消费 Layer 2（M4 全模态 I/O pipeline）的原始流与 Layer 1（M6 物理身体）的传感器事件，向上为 Layer 4（M2 副脑）提供决策所需的用户/他人状态。M1 是**状态生产者**，M2 是**状态消费者**；M1 不生成 Lucy 的语言，不直接编排主脑 API 的生成调用。

```
┌──────────────────────────────────────────────────────────────────┐
│ Layer 6: 主脑 API（外部 LLM，被调用才说话，不直接读 UserState）       │
├──────────────────────────────────────────────────────────────────┤
│ Layer 5: M3 主脑API调用与身份守卫                                   │
│         ├─ 生成通道：M2→M3，身份prompt注入 + W_probe生成后异己检测     │
│         └─ 分析通道：M1→M3，β异步深度推断（无身份守卫，分析prompt）    │
├──────────────────────────────────────────────────────────────────┤
│ Layer 4: M2 副脑 ──读──▶ 共享内存 Dict[user_id, PersonState]        │
│         (Qwen2.5-3B+V30)         ◀──写── M1 (10Hz + 事件驱动)       │
│         读后序列化 PersonState 进主脑 API system prompt             │
├──────────────────────────────────────────────────────────────────┤
│ Layer 3: M1 动态用户建模（本模块）                                   │
│         10Hz 本地基线 + β 异步深度建模 + TFGR 图读写                  │
├──────────────────────────────────────────────────────────────────┤
│ Layer 2: M4 全模态 ──推原始流──▶ M1                                  │
│         (视觉帧/音频流/ASR文本/键盘文本/语音起止事件)                  │
├──────────────────────────────────────────────────────────────────┤
│ Layer 1: M6 物理身体 ──推传感器事件──▶ M1                            │
│         (PresenceEvent/IMU 跌倒/接近传感器)                          │
├──────────────────────────────────────────────────────────────────┤
│ 横切: TFGR 时间流图 ◀──M1 写事件节点 / M1 读长期事实──▶ M1           │
│       Chroma 向量库 ◀──M1 写事实 embedding / M1 检索──▶ M1          │
└──────────────────────────────────────────────────────────────────┘
```

### 2.2 模块边界

**M1 做的事**：
- 实时维护 `Dict[user_id, PersonState]`（10Hz + 事件驱动），写入共享内存
- 多人物识别、注册、对话对象切换
- 视觉/语音/文本三路多模态特征融合（情绪、注意力、在场）
- 话题分类、意图推断（本地规则基线）、事实抽取
- 用户事件写入 TFGR 时间流图（`EventNode.speaker` 区分人物）
- 从 TFGR 图 + Chroma 检索组装 `known_facts`
- β 路径异步深度建模（经 M3 分析通道调主脑 API，做意图/关系/事实深度推断）

**M1 不做的事**：
- 生成 Lucy 的语言（交给 M2→M3→主脑 API）
- 维护 Lucy 的身份锚 `identity_cache`（交给 M2 副脑）
- 直接持有主脑 API 的生成客户端或做 W_probe 异己检测（交给 M3）
- 直接编排主脑 API 的生成调用（交给 M2）
- 物理身体控制（交给 M6）

### 2.3 与三路径的关系

| 路径 | M1 角色 | 时延要求 | 阻塞? |
|------|---------|---------|-------|
| α 快速响应 | M2 读 M1 的 `PersonState` 做 α 判定（情绪/在场/未解决意图） | M2 内存读 ~5μs；M1 自身 10Hz 不阻塞 α | 否（M1 后台） |
| β 主动发起 | M1 提供 `silence_duration` / `known_facts` / `relationship` 给 M2 做主动触发决策；M1 自身可经 M3 调主脑 API 做深度推断 | 异步，2-10s 可接受 | 否（后台） |
| γ 身体控制 | M1 不参与；M6 传感器事件可推送 `PresenceEvent` 给 M1 更新在场状态 | 事件订阅，非阻塞 | 否 |

**核心原则**：M1 的 10Hz 循环是**纯本地、纯后台**，不依赖任何网络调用（主脑 API、ASR/TTS 云），保证 M2 永远能快速读到一致的 `PersonState`。深度推断走 β 异步路径，结果晚到不阻塞实时字段。

## 3. UserState 数据模型

### 3.1 PersonState 字段详解

`PersonState` 的 12 个字段与主文档 §5.2 严格一致。M1 在内部可维护额外缓存（如 EMA 中间态、话题中心向量），但对外暴露的共享内存结构必须字段对齐。

| 字段 | 类型 | 取值 | 来源 | 更新频率 | 阻塞 α? |
|------|------|------|------|---------|---------|
| `user_id` | str | "user" / "person_xxx" / 注册名 | 视觉人脸识别 / 首次注册 | 会话级 | 否 |
| `name` | str | 用户自述 / 注册库 | 用户自述 / 注册库 | 会话级 | 否 |
| `presence` | bool | True/False | M4 视觉人脸 + VAD + M6 接近传感器 | 10Hz（防抖 3 帧） | 否 |
| `attention` | float | 0..1 | 视觉头部姿态 + 注视估计 | 10Hz | 否 |
| `emotion_valence` | float | -1..1 | 视觉表情 CNN + 语音情感 SVM（EMA α=0.3） | 10Hz 平滑 | 否 |
| `emotion_arousal` | float | 0..1 | 视觉表情 + 语音能量/语速（EMA α=0.4） | 10Hz 平滑 | 否 |
| `last_speech_end` | float | 单调秒 | M4 VAD `SpeechEndEvent` | 事件驱动 | 否 |
| `silence_duration` | float | 秒 | `time.monotonic() - last_speech_end` | 10Hz 派生 | 否 |
| `current_topic` | str | "面试"/"画展"/"辞职"... | ASR 文本 + 句向量话题分类 | 事件驱动（说完一句） | 否（异步） |
| `unresolved_intents` | List[str] | FIFO ≤5 | 意图推断管线（规则→小模型→β API） | 事件驱动 | 否（异步） |
| `known_facts` | Dict[str,str] | ≤20 条 LRU | 事实抽取 + TFGR 图检索 | 事件驱动 + 会话级刷新 | 否（异步） |
| `relationship` | str | friend/colleague/mentor/family/stranger | 用户自述 + TFGR 图边 + β API 关系推断 | 会话级 + 漂移检测 | 否 |

### 3.2 字段语义补充

- **`emotion_valence` / `emotion_arousal`**：与 TFGR `EventNode.valence` / `EventNode.arousal` 同口径，M1 写图节点时直接复用。高唤醒事件在 TFGR 阻力因子 R(e) 中有"闪回"效应（深刻记忆易回忆），见 [time_flow_graph.py#L121-L153](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py)。
- **`silence_duration`**：M1 每个 tick 用 `time.monotonic() - last_speech_end` 重算，供 M2 判断"沉默 5 分钟该 check in"。**单调时钟**，不受系统时间回拨影响。
- **`current_topic`**：短文本标签，跨轮维持，用户切换话题时更新。M2 读它来给主脑 API 注入"当前在聊面试"的语境。
- **`unresolved_intents`**：FIFO 队列，最多 5 条；Lucy 响应闭合后出队（规则 + 句向量相似度判定闭合）。M2 读它判断"用户还有未解决的诉求"。
- **`known_facts`**：键值对，键为事实主题（"面试结果"），值为内容（"通过了，下周上班"）。M2 读它组装"你之前说面试通过了"这类记忆注入主脑 API prompt（参考 v18 的 `"你之前说："` 机制，[v18_deepseek_500_turns.py#L151](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/v18_deepseek_500_turns.py)）。
- **`relationship`**：枚举字符串，影响 Lucy 的语气和主动发起频率（家人可更频繁 check in，陌生人需克制）。来源见 §5.5。

### 3.3 多人物支持：Dict[user_id, PersonState]

#### 3.3.1 共享内存契约

主文档 §5.2 的单人物 `UserState` 在本文档扩展为多人物状态表。**主用户固定 `user_id="user"`**，其他人物按识别 id 索引：

```python
# 共享内存结构（M1 单写，M2 多读，无锁）
UserStateMap = Dict[str, PersonState]

# 示例：场景中有主用户 + 小红 + 老王
{
    "user":     PersonState(user_id="user", name="小明", ...),     # 主对话对象
    "xiaohong": PersonState(user_id="xiaohong", name="小红", ...),
    "laowang":  PersonState(user_id="laowang", name="老王", ...),
}
```

**主用户的特殊性**：`"user"` 是固定 key，即使场景中没人也能读到一个空状态的 `PersonState(presence=False)`。M2 永远能从 `state_map["user"]` 读到主用户状态，避免 KeyError。其他人物在首次识别时动态加入。

#### 3.3.2 PersonRegistry（M1 内部）

M1 内部维护多人物注册表，管理识别、切换、关系网络：

```python
class PersonRegistry:
    """多人物注册表（M1 内部，非共享内存）"""
    def __init__(self):
        self.persons: Dict[str, PersonState] = {}
        self.current_speaker_id: str = "user"           # 当前主对话对象
        self.presence_order: List[str] = []              # 在场人物按出现顺序
        self.last_active_time: Dict[str, float] = {}     # 每人最后说话时间
        self.relations: List[PersonRelation] = []         # 多人物关系网络（§5.5）
        # 主用户预初始化（保证 M2 永远能读到）
        self.persons["user"] = PersonState(
            user_id="user", name="", presence=False,
            attention=0.0, emotion_valence=0.0, emotion_arousal=0.0,
            last_speech_end=time.monotonic(), silence_duration=0.0,
            current_topic="", unresolved_intents=[],
            known_facts={}, relationship="stranger",
        )

    def get_or_create(self, user_id: str, name: str = "") -> PersonState:
        if user_id not in self.persons:
            self.persons[user_id] = PersonState(
                user_id=user_id, name=name, presence=False,
                attention=0.0, emotion_valence=0.0, emotion_arousal=0.0,
                last_speech_end=time.monotonic(), silence_duration=0.0,
                current_topic="", unresolved_intents=[],
                known_facts={}, relationship="stranger",
            )
        return self.persons[user_id]

    def switch_speaker(self, new_id: str):
        """对话对象切换（M4 检测到新人物开口）"""
        self.current_speaker_id = new_id
        self.last_active_time[new_id] = time.monotonic()
        # 共享内存指针原子切换（见 §7.1）
```

#### 3.3.3 身份识别管线

身份识别由 M4 视觉管线提供人脸 embedding + 声纹 embedding，M1 在 `PersonRegistry` 中匹配：

```python
def identify_person(face_embedding: np.ndarray, voice_embedding: np.ndarray = None) -> str:
    """人脸 + 声纹融合 -> user_id"""
    # 1. 主用户优先匹配（user 永远存在）
    best_id, best_sim = "user", 0.0
    # 视觉匹配（SQLite 存已知人物 embedding）
    vis_id, vis_sim = face_db.search(face_embedding, top_k=1)
    if vis_sim > 0.6:
        best_id, best_sim = vis_id, vis_sim
    # 声纹匹配（语音对话场景必备，用户背对摄像头时关键）
    if voice_embedding is not None:
        voice_id, voice_sim = voice_db.search(voice_embedding, top_k=1)
        if voice_sim > 0.7 and voice_sim > best_sim:
            best_id, best_sim = voice_id, voice_sim
    # 2. 新人物注册
    if best_sim < 0.5:
        new_id = f"person_{uuid4().hex[:8]}"
        face_db.register(new_id, face_embedding)
        if voice_embedding is not None:
            voice_db.register(new_id, voice_embedding)
        registry.get_or_create(new_id)
        return new_id
    return best_id
```

## 4. 输入信号

M1 不直接接触传感器，所有原始数据经 M4 预处理后推送，或经 M6 传感器事件总线订阅。输入信号分四路：

### 4.1 麦克风（音频流，16kHz）

M4 推送音频块给 M1，用于语音活动检测（VAD）、语音情感特征：

```python
@dataclass
class AudioChunk:
    samples: np.ndarray        # 16kHz mono, ~32ms (512 samples)
    timestamp: float
    vad_active: bool           # M4 已算好的 VAD 结果
    energy: float              # 短时能量
    zcr: float                 # 过零率
```

- **用途**：`presence`（VAD 任一检测即在场）、`emotion_arousal` 辅助（能量/语速）、语音情感 SVM 输入
- **频率**：M4 以 ~30Hz 推送；M1 10Hz 轮询最新块（丢旧帧，不反压 M4）
- **降级**：M4 音频断 → 语音路停，`presence` 仅靠视觉 + M6 接近传感器，情绪用视觉路（主文档 §8.1 L4）

### 4.2 摄像头（视觉帧，30Hz）

M4 推送视觉帧给 M1，用于人脸检测、身份识别、情绪识别、注意力估计：

```python
@dataclass
class VisualFrame:
    image: np.ndarray          # BGR, 640x480
    timestamp: float
    faces: List[FaceDetection]  # M4 已检测好的人脸框 + embedding
    # FaceDetection: bbox, landmark, embedding, confidence
```

- **用途**：`presence`（人脸检测）、`attention`（头部姿态 + 注视）、`emotion_valence/arousal`（表情 CNN）、身份识别
- **频率**：M4 以 30Hz 推送；M1 10Hz 轮询最新帧
- **降级**：M4 视觉断/黑暗 → 视觉路停，`attention` 退化为基于 VAD 的粗估（用户在说话则假设 attention=0.6），情绪用语音路（主文档 §8.1 L4）

### 4.3 键盘（文本输入，事件驱动）

文本模式（L4 降级或用户主动选文本输入）下，M4 推送文本事件：

```python
@dataclass
class TextInputEvent:
    text: str
    user_id: str               # 默认 "user"（文本模式通常不区分说话人）
    timestamp: float
```

- **用途**：`current_topic` / `unresolved_intents` / `known_facts` 的文本路输入；`presence` 由文本输入推断（有输入即在场）
- **频率**：事件驱动，用户回车提交时触发
- **降级**：ASR 失效时，文本输入是主要意图/事实来源（主文档 §8.1 L4 纯文本交互）

### 4.4 M6 传感器事件（订阅式）

M6 物理身体的传感器经事件总线推送环境信号给 M1：

```python
@dataclass
class PresenceEvent:           # 接近传感器（超声波/PIR）
    user_id: str               # 若 M6 能识别则给，否则 None
    present: bool
    distance_m: float          # 估计距离
    timestamp: float

@dataclass
class IMUEvent:                # 跌倒/剧烈动作检测
    event_type: str            # "fall" / "rapid_movement" / "stationary"
    confidence: float
    timestamp: float
```

- **用途**：`presence` 补充（视觉/语音失效时的兜底）、`emotion_arousal` 辅助（跌倒/剧烈动作 → arousal 升高）、M2 主动触发依据（用户长时间静止可能需要 check in）
- **频率**：事件驱动，M6 在状态变化时推送
- **耦合**：M6→M1 是弱耦合（事件订阅），M1 处理慢了丢事件不影响 M6 控制环

### 4.5 输入信号汇总与融合策略

| 信号源 | 频率 | 主要贡献字段 | 融合方式 |
|--------|------|-------------|---------|
| 麦克风 | 30Hz 推 / 10Hz 采样 | presence, emotion_arousal | 视觉主导 0.6 + 语音辅助 0.4 |
| 摄像头 | 30Hz 推 / 10Hz 采样 | presence, attention, emotion_valence/arousal, identity | 视觉路主导 |
| 键盘 | 事件驱动 | current_topic, unresolved_intents, known_facts, presence | 文本路独立，事后修正情绪 |
| M6 传感器 | 事件驱动 | presence（兜底）, emotion_arousal（辅助） | 仅视觉/语音失效时生效 |

## 5. 状态估计（五子模型）

### 5.1 presence（在场检测）

融合视觉人脸检测 + VAD + M6 接近传感器，防抖输出：

```python
def update_presence(frame: VisualFrame, audio: AudioChunk, m6_event: PresenceEvent = None) -> bool:
    """10Hz 调用，输出防抖后的在场状态"""
    face_detected = len(frame.faces) > 0
    voice_active = audio.vad_active
    m6_present = m6_event.present if m6_event else False
    # 任一检测到即视为在场
    raw_presence = face_detected or voice_active or m6_present
    # 防抖：连续 3 帧不一致才切换，避免瞬间误判
    self._presence_buffer.append(raw_presence)
    if len(self._presence_buffer) > 3:
        self._presence_buffer.pop(0)
    return sum(self._presence_buffer) >= 2
```

**降级**：视觉断 → 仅 VAD + M6；语音断 → 仅视觉 + M6；两者都断 → M6 接近传感器兜底；全断 → `presence` 保持上一值（最多 5s 后回 False）。

### 5.2 attention（注意力估计）

注意力 = 用户看向 Lucy 的程度，融合头部姿态与注视估计：

```python
def estimate_attention(frame: VisualFrame) -> float:
    """0..1, 1=完全注视 Lucy。~10ms"""
    if not frame.faces:
        return 0.0
    face = frame.faces[0]                                   # 取最大人脸
    # 头部姿态（yaw/pitch）-> 是否朝向 Lucy
    head_pose = head_pose_estimator(face)                   # ~10ms
    facing_lucy = 1.0 - min(1.0, abs(head_pose.yaw) / 45.0)
    # 注视点（可选，更准但更慢）
    gaze = gaze_estimator(face)                             # ~20ms
    gaze_on_lucy = gaze.target == "lucy"
    attention = 0.6 * facing_lucy + 0.4 * (1.0 if gaze_on_lucy else 0.0)
    return clip(attention, 0.0, 1.0)
```

**降级**：视觉断 → `attention` 退化为基于 VAD 的粗估（用户在说话则 attention=0.6，否则 0.3）。

### 5.3 emotion（情绪效价 + 唤醒）

情绪是 M1 最重的实时计算。采用**特征级融合 + EMA 平滑**：

```python
class EmotionRecognizer:
    """视觉表情 CNN + 语音情感 SVM -> valence/arousal，EMA 平滑"""
    def __init__(self):
        self.face_cnn = MobileFaceNetFer()                 # ~3M params, CPU ~15ms
        self.voice_svm = VoiceEmotionSVM()                  # IS09 + RBF SVM, ~20ms
        self.ema_val = 0.0
        self.ema_arou = 0.0
        self.alpha_val = 0.3                                # 时间常数 ~1s
        self.alpha_arou = 0.4                               # 更敏感，对突变快响应

    def update(self, frame: VisualFrame, audio: AudioChunk) -> Tuple[float, float]:
        # 视觉路
        v_val, v_arou = 0.0, 0.0
        if frame.faces:
            face = frame.faces[0]
            fer = self.face_cnn(face)                       # ~15ms
            v_val, v_arou = FER_TO_VA[fer.label]            # Russell 环形模型映射
        # 语音路
        s_val, s_arou = self.voice_svm(audio)               # ~20ms
        # 融合（视觉主导 0.6，语音辅助 0.4）
        raw_val = 0.6 * v_val + 0.4 * s_val
        raw_arou = 0.6 * v_arou + 0.4 * s_arou
        # EMA 平滑
        self.ema_val = self.alpha_val * raw_val + (1 - self.alpha_val) * self.ema_val
        self.ema_arou = self.alpha_arou * raw_arou + (1 - self.alpha_arou) * self.ema_arou
        return self.ema_val, self.ema_arou
```

**FER 标签到 valence/arousal 映射**（Russell 环形模型）：
- happy → valence=+0.8, arousal=0.6
- sad → valence=-0.7, arousal=0.3
- angry → valence=-0.6, arousal=0.9
- surprise → valence=+0.3, arousal=0.9
- fear → valence=-0.5, arousal=0.85
- disgust → valence=-0.6, arousal=0.5
- neutral → valence=0.0, arousal=0.3

**情绪突变检测**：M1 检测 `emotion_arousal` 在 1s 内变化 >0.4（如平静→愤怒），立即向 M2 推送 `EmotionShiftEvent`，不等下一个 10Hz tick。这让 M2 快速响应用户情绪变化（改变语气、提前 check in）。

**降级**：视觉断 → 纯语音情感；语音断 → 纯视觉；两者都断 → 保持上一值（最多 5s 后回中性 valence=0, arousal=0.3）。

### 5.4 intent（话题 + 未解决意图）

#### 5.4.1 current_topic 推断

话题分类走**轻量本地话题分类器**（不调 LLM，避免阻塞）：

```python
def classify_topic(asr_text: str) -> str:
    """ASR 文本 -> 话题标签。~30ms"""
    emb = sentence_encoder.encode(asr_text, normalize_embeddings=True)   # ~30ms
    # 与预定义话题中心向量检索（Chroma 本地 collection）
    hits = topic_collection.query(query_embeddings=[emb], n_results=1)
    if hits[0][0].score > 0.5:
        return hits[0][0].metadata["topic"]
    # 未命中预定义话题，用关键词规则兜底
    return keyword_topic_fallback(asr_text)
```

预定义话题库随会话积累：当 ASR 文本无法命中现有话题中心，且文本长度 >10 字，触发"新话题注册"——把该句 embedding 作为新话题中心写入 Chroma，标签用关键词抽取命名（如"面试"、"画展"、"辞职"）。

#### 5.4.2 unresolved_intents 维护（本地规则基线 + β 深度推断）

意图队列采用 FIFO + 闭合检测。本地三级管线（详见 §6）：

```python
def update_intents_local(asr_text: str, user_state: PersonState):
    """本地规则基线（<30ms），10Hz/事件驱动均可用"""
    # Tier 1: 规则匹配（<5ms）
    rule_intents = rule_based_intents(asr_text)
    # 例: "帮我..." -> REQUEST, "为什么..." -> QUESTION, "我想..." -> DESIRE
    if rule_intents and confidence(rule_intents) > 0.8:
        _merge_intents(user_state, rule_intents)
        return
    # Tier 2: 小模型分类（~30ms）
    emb = sentence_encoder.encode(asr_text)
    model_intents = intent_classifier.predict(emb)
    if model_intents and confidence(model_intents) > 0.6:
        _merge_intents(user_state, model_intents)
        return
    # Tier 3: 置信度不足 -> 触发 β 异步深度推断（见 §6）
    schedule_deep_intent_inference(asr_text, user_state.user_id)
    # α 路径先用 Tier 1/2 结果兜底
    _merge_intents(user_state, rule_intents or model_intents or ["UNKNOWN"])
```

**闭合检测**：Lucy 回完后，M2 推 `LucyReplyEvent` 给 M1，M1 检测回复是否闭合了某意图：

```python
def check_intent_closure(user_state: PersonState, lucy_reply: str):
    """Lucy 回完后调用，闭合已响应的意图"""
    for intent in list(user_state.unresolved_intents):
        if intent_resolved(intent, lucy_reply):             # 规则 + 句向量相似度
            user_state.unresolved_intents.remove(intent)
    user_state.unresolved_intents = user_state.unresolved_intents[-5:]  # 限长
```

**意图分类体系**（参考 ChMapData/MapDia）：`QUESTION` / `REQUEST` / `DESIRE` / `COMPLAINT` / `SHARING` / `EMOTION_VENT` / `FOLLOW_UP_REQUEST` / `GOODBYE`

### 5.5 relationship（关系推断）

`relationship` 字段由三路信号融合：

#### 5.5.1 首次注册时的关系抽取

用户首次自述关系时（"我是你妈妈"/"我是小明同事小红"），用规则 + 命名实体抽取关系标签：

```python
def extract_relationship_from_utterance(asr_text: str, user_id: str) -> Optional[str]:
    """从用户自述抽取关系标签"""
    for pattern, rel in RELATION_PATTERNS:                  # "妈妈"->family, "同事"->colleague
        if re.search(pattern, asr_text):
            return rel
    return None
```

#### 5.5.2 TFGR 图边的关系推断（§10 TFGR 资产复用）

`relationship` 也可从 TFGR 时间流图的**关联边**推断。当 M1 写入跨人物关联事件（如"小明去祝贺小红的画展"），关联边的类型与权重暗示人物关系：

```python
def infer_relationship_from_graph(user_id: str) -> Optional[str]:
    """从 TFGR 图边推断与 Lucy 的关系"""
    # 取该人物与 Lucy(assistant) 节点之间的边
    edges = tfgr_graph.get_edges_between(user_id, "assistant")
    if not edges:
        return None
    # 边类型/频次/情感倾向 -> 关系
    positive_count = sum(1 for e in edges if e.valence > 0)
    total = len(edges)
    if total >= 5 and positive_count / total > 0.7:
        return "friend"
    if total >= 3 and positive_count / total > 0.5:
        return "colleague"
    return "stranger"
```

#### 5.5.3 漂移检测 + β 深度关系推断

长期交互中，若 Lucy 主动发起被频繁拒绝、或用户语气变冷淡，关系可能漂移。M1 每 N 轮（N=20）用规则检查：

```python
def detect_relationship_drift(user_state: PersonState, history: List) -> bool:
    """规则检测关系漂移，触发 β 深度推断"""
    recent_rejections = count_recent_rejections(history, window=20)
    avg_valence = avg_emotion_valence(history, window=20)
    if recent_rejections > 0.5 or avg_valence < -0.3:
        return True
    return False
```

漂移触发时，M1 经 M3 调主脑 API 做深度关系重判（见 §6）。

## 6. AI 驱动的深度建模（β 路径异步）

### 6.1 设计原则：10Hz 本地基线 + β 异步深度

**核心原则**：M1 的 10Hz 循环**纯本地**（规则 + TFGR 图 + 本地小模型），绝不调主脑 API，保证 M2 永远快速读到一致状态。深度推断（意图/关系/事实）走**β 异步路径**，经 M3 的"分析通道"调主脑 API，结果晚到回写 `PersonState`，失败回退本地规则。

```
10Hz 本地基线（不阻塞，永远可用）
  ├─ presence/attention/emotion（视觉+语音+M6融合，~80ms/tick）
  ├─ current_topic（句向量话题分类，~30ms）
  ├─ unresolved_intents Tier1/2（规则+小模型，<30ms）
  └─ known_facts 当轮规则抽取（命名实体+模式匹配，~20ms）

β 异步深度建模（经 M3 分析通道调主脑 API，不阻塞 10Hz）
  ├─ 意图深度推断（Tier3，置信度<0.6 时触发，2-5s）
  ├─ 关系漂移推断（漂移检测触发，5-10s）
  └─ 事实深度抽取（复杂句、规则不足时触发，2-5s）
```

### 6.2 M1 不直接调主脑 API：经 M3 分析通道

M1 **不持有主脑 API 的生成客户端**，也不做身份守卫（那是 M3 生成通道的职责）。深度推断需求经 M3 的**分析通道**执行：

- **生成通道**（M2→M3）：身份 prompt 注入 + W_probe 生成后异己检测，生成 Lucy 风格语言
- **分析通道**（M1→M3）：分析 prompt（非 Lucy 身份），无身份守卫，返回结构化推断结果

**设计依据**：
- M1 不直接调主脑 API，保证 M1 的 10Hz 不依赖网络（M1 挂了不影响 M2，API 挂了 M1 退回本地规则）
- API 客户端管理（连接池/限流/备用切换）集中在 M3，避免 M1/M2 各持客户端造成资源竞争
- 分析模式调用的 prompt 与生成模式不同（分析模式不注入 Lucy 身份，只传用户文本 + 推断任务），无需 W_probe 守卫

```python
# M1 -> M3 分析通道的请求契约
@dataclass
class AnalysisRequest:
    task: Literal["intent_inference", "relationship_inference", "fact_extraction"]
    user_text: str                       # ASR 文本
    user_id: str                         # 目标人物
    context: Dict                        # 已有 PersonState 摘要 + TFGR 相关节点
    deadline_s: float = 5.0             # 超时放弃，回退本地规则

# M3 -> M1 异步返回
@dataclass
class AnalysisResult:
    task: str
    user_id: str
    result: Dict                         # 结构化结果（意图列表/关系标签/事实字典）
    confidence: float
    elapsed_s: float
```

### 6.3 深度意图推断（Tier 3）

当本地 Tier 1/2 置信度 <0.6 时触发：

```python
def schedule_deep_intent_inference(asr_text: str, user_id: str):
    """提交深度意图推断到 M3 分析通道（异步，不阻塞 10Hz）"""
    req = AnalysisRequest(
        task="intent_inference",
        user_text=asr_text,
        user_id=user_id,
        context={"current_topic": registry.persons[user_id].current_topic,
                 "known_facts": dict(list(registry.persons[user_id].known_facts.items())[:5])},
        deadline_s=5.0,
    )
    m3_analysis_queue.submit(req, callback=self._on_intent_result)

def _on_intent_result(self, result: AnalysisResult):
    """异步回调：深度意图结果回写 PersonState"""
    if result.user_id not in registry.persons:
        return                                            # 人物已离开，丢弃
    state = registry.persons[result.user_id]
    if result.confidence > 0.7:
        # 高置信度：替换本地低置信结果
        state.unresolved_intents = result.result["intents"][:5]
    # 低置信或超时：保持本地 Tier 1/2 结果（已在 α 路径兜底）
```

**触发条件**：
- 本地规则与小模型均不命中（Tier 1/2 confidence <0.6）
- 句子复杂度 >阈值（长度 >20 字 + 含"该不该"/"怎么办"等决策词）
- **频率限制**：每用户每分钟最多 3 次深度意图推断，防止 API 滥用

### 6.4 深度关系推断

关系漂移检测触发时（§5.5.3）：

```python
def schedule_deep_relationship_inference(user_id: str):
    """关系漂移 -> 提交深度关系推断到 M3 分析通道"""
    state = registry.persons[user_id]
    req = AnalysisRequest(
        task="relationship_inference",
        user_text="",                    # 不基于单句，基于历史摘要
        user_id=user_id,
        context={
            "current_relationship": state.relationship,
            "recent_valence_avg": avg_valence(state, window=20),
            "rejection_rate": compute_rejection_rate(user_id, window=20),
            "recent_topics": get_recent_topics(user_id, n=5),
        },
        deadline_s=10.0,
    )
    m3_analysis_queue.submit(req, callback=self._on_relationship_result)

def _on_relationship_result(self, result: AnalysisResult):
    if result.user_id not in registry.persons:
        return
    state = registry.persons[result.user_id]
    if result.confidence > 0.75:
        new_rel = result.result["relationship"]
        if new_rel != state.relationship:
            # 关系变化写入 TFGR 图（§10）
            tfgr_graph.add_event(make_relationship_change_node(
                result.user_id, state.relationship, new_rel))
            state.relationship = new_rel
```

### 6.5 深度事实抽取

复杂句（长度 >20 字 + 规则未抽到事实）触发：

```python
def schedule_deep_fact_extraction(asr_text: str, user_id: str):
    req = AnalysisRequest(
        task="fact_extraction",
        user_text=asr_text,
        user_id=user_id,
        context={"current_topic": registry.persons[user_id].current_topic},

    if result.user_id not in registry.persons:
        return
    state = registry.persons[result.user_id]
    for key, val in result.result["facts"].items():
        state.known_facts[key] = val
        # 同步写入 TFGR 图（§10）
        write_fact_to_tfgr(result.user_id, key, val, result.result["asr_text"], state)
    _enforce_known_facts_limit(state, max_items=20)       # LRU 淘汰
```

### 6.6 β 深度建模的失败兜底

| 失败模式 | M1 行为 | 对 PersonState 的影响 |
|---------|---------|----------------------|
| M3 分析通道超时（>deadline） | 丢弃结果，保持本地 Tier 1/2 | 用 α 路径已兜底的意图/规则事实 |
| 主脑 API 不可用（M3 L7 降级） | M3 不返回，M1 超时后回退 | 同上 |
| M3 自身失效 | M1 心跳检测，停发请求 | 同上 |
| 结果置信度低（<0.7 意图 / <0.75 关系） | 不回写，保持本地 | 同上 |

**关键**：β 深度建模是**增量增强**，不是必需。M1 的 10Hz 本地基线已经能让 M2 完成基本决策；深度推断只是让意图/关系/事实更准。这与主文档 §8.1 的降级哲学一致——深度能力失效，基线能力保留。

## 7. 与副脑的耦合

### 7.1 共享内存：无锁单写多读的 Dict[user_id, PersonState]

M1 是共享内存的**唯一写者**，M2（及 M3 读取上下文时）是**多读者**。采用"双缓冲 + 原子指针交换"实现无锁：

```python
class LockFreeUserStateMap:
    """无锁单写多读的多人物状态共享"""
    def __init__(self):
        # 双缓冲：M1 写 buffer_a，M2 读 buffer_b，交换时原子切换指针
        self._buffer_a: Dict[str, PersonState] = {"user": PersonState(...)}
        self._buffer_b: Dict[str, PersonState] = copy.deepcopy(self._buffer_a)
        self._ptr = AtomicReference(self._buffer_a)       # 原子指针
        self._write_lock = threading.Lock()                # 仅防 M1 内部并发，不阻塞读

    def publish(self, state_map: Dict[str, PersonState]):
        """M1 写入：写到非当前指针的 buffer，再原子切换"""
        with self._write_lock:
            inactive = self._buffer_b if self._ptr.get() is self._buffer_a else self._buffer_a
            # 字段级浅拷贝（PersonState 是 dataclass，字段都是不可变或独立对象）
            inactive.clear()
            for uid, ps in state_map.items():
                inactive[uid] = copy.copy(ps)             # 浅拷贝 PersonState
            self._ptr.set(inactive)                        # 原子切换指针

    def read(self) -> Dict[str, PersonState]:
        """M2 读取：读当前指针指向的 buffer"""
        return self._ptr.get()

    def read_person(self, user_id: str) -> Optional[PersonState]:
        """M2 读取指定人物（便利方法）"""
        return self._ptr.get().get(user_id)
```

**协议保证**：
- M1 写入不阻塞 M2 读取（M2 永远能读到一致快照——要么上一个 10Hz 周期的完整状态，要么当前周期的完整状态，不会半新半旧）
- M2 读取不阻塞 M1 写入（M1 永远能完成 10Hz 更新）
- M1 挂了，M2 读到最后一个成功发布的快照，降级运行（主文档 §5.2 要求）
- 指针交换是原子操作（x86 `lock cmpxchg` 单指令），无数据竞争

### 7.3 降级运行：M1 挂了 M2 用旧状态

遵循主文档 §5.2 与 §8.1：

| 场景 | M1 状态 | M2 行为 |
|------|---------|---------|
| M1 正常 | 10Hz 发布 | 读最新状态 |
| M1 卡顿（tick >200ms） | 发布延迟 | M2 读到上一周期状态，最多滞后 200ms |
| M1 进程崩溃 | 不再发布 | M2 读最后快照，标记 M1 失效，告警；继续用旧状态完成当前对话 |
| M1 完全失效 + 重启中 | 旧快照 | M2 用旧状态降级运行，新事实不入库（M1 重启后从 TFGR 图恢复） |

**心跳**：M1 每 1s 发心跳到 M2；3s 无心跳，M2 标记 M1 为失效（对应主文档 §8.1 L6 前置保障），用最后快照运行，并告警。

**重启恢复**：M1 重启后从 TFGR 时间流图重建 `known_facts`（按 `speaker` 过滤检索 top 事件），从注册库恢复人物 embedding，5s 内恢复到崩溃前 90% 状态。

## 8. 与身份守卫的接口

### 8.1 接口职责划分

身份一致性由副脑（M2）+ M3 共同保证（主文档 §0、§5.4）。M1 的职责是**提供干净、序列化友好的 `PersonState`**；M2 读取后**选择字段并序列化进主脑 API 的 system prompt**；M3 负责实际的 prompt 注入与 W_probe 生成后异己检测。M1 **不**做身份守卫，**不**注入 Lucy 身份信息。

```
M1 维护 PersonState ──共享内存──▶ M2 读取 ──字段选择──▶ M2 序列化进 system prompt
                                                              │
                                                              ▼
                                                          M3 注入主脑 API
                                                          + W_probe 异己守卫
```

### 8.2 序列化进主脑 API system prompt 的字段选择

并非所有 `PersonState` 字段都该进主脑 API 的 system prompt——有些是 M2 的内部决策信号（如 `silence_duration` 是主动触发依据，不该让 Lucy 在生成时"算计"沉默时长）。M2 按下表选择：

| 字段 | 进 system prompt? | 用途 | 序列化示例 |
|------|------------------|------|-----------|
| `name` | 是 | Lucy 称呼用户 | `"用户叫小明"` |
| `relationship` | 是 | 影响语气（家人更亲昵） | `"与你的关系：朋友"` |
| `emotion_valence` | 是（量化档位） | 共情对齐 | `"用户当前情绪：低落（效价 -0.6）"` |
| `emotion_arousal` | 是（量化档位） | 节奏调整（高唤醒更急） | `"情绪唤醒：偏高（0.75）"` |
| `current_topic` | 是 | 话题对齐 | `"当前话题：面试结果"` |
| `unresolved_intents` | 是（如有） | 提醒 Lucy 有未闭合诉求 | `"用户未解决的诉求：[想问老王病情]"` |
| `known_facts` | 是（top 3-5） | 记忆注入 | `"已知事实：面试通过了，下周上班；考研报名截止周五"` |
| `user_id` | 否 | M1/M2 内部标识 | — |
| `presence` | 否 | M2 决策（是否值得主动发起） | — |
| `attention` | 否 | M2 决策（用户是否在听） | — |
| `last_speech_end` | 否 | M1 派生 silence 用 | — |
| `silence_duration` | 否 | M2 主动触发决策依据 | — |

**M2 侧的序列化伪代码**（M1 不执行，仅展示 M1 提供的数据如何被消费）：

```python
# M2 副脑侧（伪代码，M1 不参与）
def build_user_state_prompt(state: PersonState) -> str:
    facts_str = "; ".join(f"{k}：{v}" for k, v in list(state.known_facts.items())[:5])
    intents_str = ", ".join(state.unresolved_intents) if state.unresolved_intents else "无"
    return (
        f"用户叫{state.name or '未知'}，与你的关系：{state.relationship}。"
        f"当前情绪：效价 {state.emotion_valence:.1f}，唤醒 {state.emotion_arousal:.1f}。"
        f"当前话题：{state.current_topic or '无'}。"
        f"已知事实：{facts_str}。"
        f"用户未解决的诉求：{intents_str}。"
    )
# M3 把这段拼进 system prompt（与 identity_cache 序列化的 Lucy 身份锚并列）
```

### 8.3 多人物的 system prompt 序列化

多人物场景下，M2 把当前对话对象的 `PersonState` 作为主上下文，其他在场人物作为简略背景：

```python
# M2 侧（伪代码）
def build_multi_person_prompt(state_map: Dict[str, PersonState], current_id: str) -> str:
    current = state_map[current_id]
    others = [state_map[uid] for uid in state_map if uid != current_id
              and state_map[uid].presence]
    parts = [build_user_state_prompt(current)]                # 当前对话对象（详细）
    if others:
        others_str = "; ".join(f"{o.name}（{o.relationship}）" for o in others if o.name)
        parts.append(f"场景中还有：{others_str}。")            # 其他人（简略）
    return "\n".join(parts)
```

这让 Lucy 在回答"老王，你认识小明和小红吗？"时，主脑 API 的 system prompt 既有当前对话对象（老王）的详细状态，又有小明/小红的存在背景，生成时能正确处理多人物关系。

### 8.4 M1 的保证

M1 对身份守卫接口提供以下保证：
- **字段完整性**：`PersonState` 12 字段始终有值（缺失则默认值，如 `name=""` / `relationship="stranger"`）
- **取值合法**：`emotion_valence ∈ [-1,1]`、`emotion_arousal ∈ [0,1]`、`attention ∈ [0,1]`（M1 内部 clip）
- **快照一致性**：M2 读到的 `PersonState` 是原子快照，不会出现 `emotion_valence` 是新的但 `current_topic` 是旧的不一致状态
- **不泄露 Lucy 身份**：M1 的 `known_facts` / `relationship` 是关于用户的事实，不含 Lucy 的 `identity_cache` 内容（那是 M2 维护的）

## 9. 时延管理与降级

### 9.1 10Hz 更新预算分解

M1 单个 tick（100ms 预算）的耗时分解：

| 阶段 | 预算 | 实测目标 | 说明 |
|------|------|---------|------|
| 轮询 M4 最新帧/音频 | 1ms | <1ms | 非阻塞 poll，无则跳过 |
| 视觉路（presence + attention + emotion 视觉部分） | 35ms | 25ms | 人脸检测 ~5ms + 头部姿态 ~10ms + 表情 CNN ~15ms |
| 语音路（emotion 语音部分） | 25ms | 20ms | IS09 特征 + SVM |
| EMA 融合 + 字段更新 | 5ms | 3ms | 加权融合 + clip |
| silence_duration 派生 | <1ms | <1ms | 减法 |
| 共享内存原子发布 | 1ms | <1ms | 双缓冲 + 指针交换 |
| **合计** | **~67ms** | **~50ms** | 预算 80ms，留 13ms 余量 |
| 节拍控制 | sleep(剩余) | — | 维持 10Hz |

**关键**：单 tick <80ms，永远在 100ms 内完成，不漂移。即使视觉/语音路偶尔慢（GC 抖动），EMA 平滑保证输出不跳变。

### 9.2 α 路径不阻塞保证

M1 的 10Hz 循环在**独立后台线程**（CPU 后台核，主文档 §8.3 资源隔离），与 α 路径的对话线程隔离：

| α 路径阶段 | M1 是否参与 | 阻塞? |
|-----------|------------|-------|
| ASR 首 chunk → M2 | M1 不参与 | — |
| M2 读 PersonState | M1 已在后台更新，M2 内存读 ~5μs | 否 |
| M2 判定 + 语境组装 | M1 不参与 | — |
| M3 调主脑 API | M1 不参与 | — |
| TTS + 输出 | M1 不参与 | — |

**M1 的更新与 α 路径完全并行**——M1 在后台 10Hz 写共享内存，M2 在对话线程读，两者经无锁双缓冲解耦。M1 的最坏情况（卡顿 200ms）只让 M2 读到滞后 200ms 的状态，不阻塞 α 路径的首音频时延（主文档 §4.1 要求 <2.5s）。

### 9.3 β 深度建模的时延预算

β 路径异步深度建模（§6）的时延预算（用户不感知，可宽松）：

| 任务 | 触发频率 | 预算 | 超时处理 |
|------|---------|------|---------|
| 深度意图推断 | 每用户每分钟 ≤3 次 | 2-5s | 超时丢弃，用本地 Tier 1/2 |
| 深度关系推断 | 每 20 轮检测一次漂移 | 5-10s | 超时丢弃，保持原关系 |
| 深度事实抽取 | 复杂句触发 | 2-5s | 超时丢弃，规则抽取结果 |

**β 与 α 抢资源时**（主文档 §4.2）：β 让步。M3 分析通道的 API 调用可暂停，让 α 路径的生成调用优先。M1 的分析请求超时后回退本地规则，不影响 M2 决策。

### 9.4 降级策略

遵循主文档 §8.1 的降级框架，M1 内部降级分以下级：

| 降级级 | 触发 | M1 行为 | 对 M2 的影响 |
|--------|------|---------|-------------|
| M1-L0 正常 | — | 全功能（视觉+语音+文本+M6+β深度） | M2 读完整 PersonState |
| M1-L1 视觉失效 | 摄像头断/黑暗（对应主文档 L4） | 视觉路停，纯语音+文本+M6 | attention 退化为 VAD 粗估；emotion 用语音路 |
| M1-L2 语音失效 | 麦克风断 | 语音路停，纯视觉+文本 | presence 仅靠视觉+M6；emotion 用视觉路 |
| M1-L3 ASR 失效 | ASR 服务超时 | 不更新 topic/intents/facts；β 深度推断停 | current_topic 保持上一值；unresolved_intents 不变 |
| M1-L4 双模态失效（纯文本） | 视觉+语音都断（对应主文档 L4） | 仅靠键盘文本 + M6 | emotion 5s 后回中性；presence 由文本输入/M6 推断 |
| M1-L5 β 通道失效 | M3 分析通道不可用 / API 不可用 | β 深度推断停，退回本地规则 | 意图/关系/事实用本地规则结果（质量降级，不阻断） |
| M1-L6 TFGR/Chroma 失效 | 向量库/图服务断 | known_facts 不刷新；新事实不入库 | M2 用旧 known_facts；M1 重启后从图恢复 |
| M1-L7 完全失效 | M1 进程崩溃 | 不再写共享内存 | M2 用最后快照降级运行（主文档 §5.2） |

**关键原则**（与主文档 §8.1 一致）：
- M1 任何降级都**不阻塞 α 路径**——α 路径的响应由 M2 + 主脑 API 完成，M1 只提供"最好努力"的状态
- M1 挂了（L7），M2 用旧状态 + 当前 ASR 文本也能完成基本对话
- 多模态失效（L4）→ 纯文本交互（主文档 §8.1 L4 要求）
- β 深度建模失效（L5）→ 退回本地规则，不阻断实时建模

## 10. TFGR 资产复用

### 10.1 known_facts 来自 TFGR 时间流图

`known_facts` 的长期记忆来源是 TFGR 图 + Chroma 向量库的联合检索（复用主文档 §7 资产映射）：

```python
def retrieve_from_tfgr(topic: str, user_id: str = None, top_k: int = 5) -> List[FactNode]:
    """从 TFGR 图检索与当前话题相关的事实"""
    # 1. Chroma 向量检索（语义相似，复用 paraphrase-multilingual-MiniLM-L12-v2）
    query_emb = sentence_encoder.encode(topic, normalize_embeddings=True)
    where = {"user_id": user_id} if user_id else {}
    hits = chroma_collection.query(
        query_embeddings=[query_emb], n_results=top_k * 2, where=where
    )
    # 2. 取 hits 对应的 EventNode，用 TFGR 阻力因子 R(e) 重排
    candidates = []
    now = time.time()
    for hit in hits:
        node = tfgr_graph.get_event(hit.id)
        if node is None:
            continue
        r = tfgr_graph.compute_resistance(node.id, node.id, now)   # 阻力因子
        # 综合分 = 语义相似 × (1 - 阻力) × 重要度
        score = hit.similarity * (1 - r) * node.importance
        candidates.append((node, score))
    candidates.sort(key=lambda x: -x[1])
    return [FactNode.from_event(n) for n, _ in candidates[:top_k]]
```

**阻力因子 R(e) 的意义**：高唤醒事件（`arousal` 高）阻力低、主观时间近、易回忆；低唤醒事件阻力高、主观时间远、易遗忘。这让 `known_facts` 优先召回"用户上周激动地说面试通过了"而非"用户三天前随口提的天气"。

### 10.2 relationship 来自 TFGR 图边

`relationship` 不仅来自用户自述，也从 TFGR 图的**关联边**推断（§5.5.2）：

- **人物-人物边**：M1 写入跨人物关联事件时（"小明去祝贺小红的画展"）建联想边，边类型/权重暗示人物间关系（同事/家人/朋友）
- **人物-Lucy 边**：用户与 Lucy（`assistant` 节点）之间的交互边频次、情感倾向，推断用户与 Lucy 的关系（friend/stranger）

```python
def link_cross_person_events(node_a: EventNode, node_b: EventNode):
    """为跨人物相关事件建联想边（复用 TFGR 图）"""
    sim = sentence_encoder.cos_sim(node_a.content, node_b.content)
    if sim > 0.5:
        tfgr_graph.add_associative_edge(node_a.id, node_b.id, sim)
```

这让 Lucy 能回答"老王，你认识小明和小红吗？"——M2 沿联想边遍历到小明/小红的事件节点，组装进主脑 API 语境包。

### 10.3 用户事件节点写入（EventNode.speaker 区分人物）

M1 是用户事件的主要写入者。每句有意义的话、每个被识别的事实都写入 TFGR 图的 `EventNode`（复用 [time_flow_graph.py#L46-L61](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py)）：

```python
def write_fact_to_tfgr(user_id: str, key: str, value: str, asr_text: str, state: PersonState):
    """把事实写入 TFGR 时间流图"""
    node = EventNode(
        id=f"evt_{uuid4().hex[:8]}",
        content=f"{user_id}提到：{key}是{value}" if key else asr_text,
        speaker=user_id,                                    # 关键：speaker 区分人物
        t_start=time.time(),
        t_end=time.time(),
        t_record=time.time(),
        valence=state.emotion_valence,                      # 复用 M1 实时情绪
        arousal=state.emotion_arousal,                      # 同口径
        importance=estimate_importance(asr_text),           # 规则打分 0..1
        session_id=current_session_id,
        entities=[key] if key else [],
    )
    tfgr_graph.add_event(node)
    tfgr_graph.auto_link_temporal()                         # 自动建 Allen 时序边
    # 写入 Chroma 向量库（供语义检索）
    chroma_collection.add(
        ids=[node.id],
        embeddings=[sentence_encoder.encode(node.content)],
        documents=[node.content],
        metadatas=[{"user_id": user_id, "topic": state.current_topic}],
    )
```

**情绪字段复用**：`EventNode.valence` / `arousal` 直接取自 M1 实时维护的 `PersonState.emotion_valence/arousal`，口径完全一致。这让 TFGR 阻力因子 R(e) 能正确反映"高唤醒事件深刻易回忆"的特性。

### 10.4 多人物图的分离与关联

TFGR 图是**单图多人物**：所有人物的事件节点在同一张图里，通过 `EventNode.speaker` 字段区分。设计理由：
- **关联性**：小明的事件和小红的事件可能有因果/联想边（"小明去祝贺小红的画展"）
- **检索效率**：单图检索比多图联合检索快
- **复用 v18**：v18 的 `SEED_DIALOGUE` 已是单图多人物结构

检索时按 `speaker` 过滤：

```python
def get_person_subgraph(user_id: str, tfgr_graph) -> nx.MultiDiGraph:
    """提取指定人物的事件子图"""
    seed_ids = [n for n in tfgr_graph.G.nodes
                if tfgr_graph.get_event(n) and
                   tfgr_graph.get_event(n).speaker == user_id]
    return tfgr_graph.extract_subgraph(seed_ids, k_hop=2, max_nodes=30)
```

| TFGR 资产 | 主文档 §7 角色 | M1 复用方式 |
|----------|---------------|------------|
| TFGR 时间流图 | M2 主动触发的事件源 + 长期记忆 | M1 写用户事件节点 + 读 known_facts 检索 |
| 阻力因子 R(e) | M2 时间感知（双时钟） | M1 用 R(e) 重排 known_facts 检索结果 |
| EventNode | — | M1 写入时复用结构，speaker 区分人物，valence/arousal 复用 M1 实时情绪 |
| v18 多人物机制 | 副脑调主脑 API 的对话编排基础 | M1 复用 current_speaker 切换 + 记忆注入语义 |
| Chroma 向量库 | — | M1 写事实 embedding + 检索（与 TFGR 图联合） |

**M1 不复用的资产**（属 M2/M3）：
- `identity_cache` / `identity_projection`：Lucy 的身份锚，由 M2 维护，M1 不碰
- `W_probe`：异己检测分类器，由 M3 用于主脑 API 输出守卫，M1 不参与生成故不需要
- `V32 Gram-Schmidt` / `V40 温度约束`：副脑身份状态信号，由 M2/M3 使用
- `self_state_predictor`：副脑自身状态感知，由 M2 使用

## 11. 与主文档的契约一致性说明

### 11.1 数据契约一致性

- §3 的 `PersonState` 12 字段与主文档 §5.2 `UserState` 完全一致（字段名、类型、取值范围逐项对齐）
- 多人物扩展 `Dict[user_id, PersonState]` 是主文档 §5.2 单人物 `UserState` 的超集——单人物退化为 `{"user": PersonState}`，不破坏原契约
- 主用户固定 `user_id="user"`，保证 M2 永远能从 `state_map["user"]` 读到主用户状态
- M1 不增删对外字段（内部 `PersonRegistry` / `RelationGraph` 是内部缓存，不破坏共享内存契约）

### 11.2 时延契约一致性

- **10Hz 更新**：§9.1 单 tick 预算 80ms（实测 ~50ms），严格 100ms/tick（主文档 §4.1、§5.2）
- **<100ms 情绪检测**：§5.3 视觉 ~15ms + 语音 ~20ms，融合 <50ms（主文档要求"情绪/注意力检测延迟 <100ms，不阻塞 α 路径"）
- **M2 读 ~5μs**：§7.1 无锁共享内存的 `read()` 是原子指针读（主文档 §5.2 "纯内存读，不阻塞"）
- **β 深度建模不阻塞**：§6/§9.3 异步路径，超时回退本地规则（主文档 §4.2 β 让步 α）

### 11.3 解耦契约一致性

- **M1 挂了 M2 仍可用旧状态**：§7.1 双缓冲保证 M2 永远能读到最后快照；§7.3 L7 降级明确此行为（主文档 §5.2）
- **M1 更新不依赖 M2**：M1 主循环只读 M4 输入 + TFGR/Chroma，不调用 M2（主文档 §5.2）
- **M1 不直接调主脑 API（生成）**：§6.2 M1 的深度推断经 M3 分析通道，M1 不持有生成客户端；M1 的 10Hz 纯本地不依赖任何网络调用（主文档 §5.2 解耦）

### 11.4 三路径分离一致性

- M1 不出现在 γ 路径（身体控制）中
- M1 的 10Hz tick 支持 α 路径（提供 PersonState 给 M2 快速判定），但自身在后台线程不阻塞 α
- M1 的 β 深度建模走 β 路径（异步，不阻塞用户感知），与 α 抢资源时让步（主文档 §4.2）
- M1 不直接调主脑 API 生成 Lucy 语言（主文档 §1.2 主脑职责）

### 11.5 TFGR 资产复用一致性

- 复用 `EventNode` 结构（[time_flow_graph.py#L46-L61](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py)），`speaker` 字段区分多人物（主文档 §7 TFGR 资产复用映射）
- 复用阻力因子 R(e) 做 `known_facts` 检索重排（§10.1）
- 复用 v18 多人物机制的语义（`current_speaker` 切换、`"你之前说："` 记忆注入），但实现上 M1 提供结构化 `known_facts`，由 M2 组装成自然语言注入主脑 API prompt
- `identity_cache` 是 Lucy 的身份锚（不是用户的），M1 不维护它；M1 写入 TFGR 图的用户事件与 Lucy 的 `assistant` 节点建联想边，间接支撑身份一致性

### 11.6 降级策略一致性

§9.4 的降级表与主文档 §8.1 的 L0-L7 框架对齐：
- M1-L4 双模态失效 → 纯文本交互（对应主文档 L4 "多模态失效降级纯文本"）
- M1-L5 β 通道失效 → 退回本地规则（对应主文档 L7 "主脑API不可用" 时 M1 侧的降级）
- M1-L7 完全失效 → M2 用最后快照降级运行（对应主文档 §5.2 解耦要求）

from dataclasses import dataclass, field
from typing import Dict, List, Optional, Tuple
import time, threading, copy
import numpy as np

# ---- 共享数据契约（严格遵循主文档 §5.2，扩展为多人物）----
@dataclass
class PersonState:
    """单人物状态，字段与主文档 §5.2 UserState 严格一致"""
    user_id: str
    name: str
    presence: bool
    attention: float
    emotion_valence: float

UserStateMap = Dict[str, PersonState]   # 共享内存契约，主用户 key="user"


# ---- 无锁共享内存（双缓冲 + 原子指针）----
class LockFreeUserStateMap:
    def __init__(self):
        self._a: UserStateMap = {"user": _empty_state("user")}
        self._b: UserStateMap = copy.deepcopy(self._a)
        self._ptr = AtomicReference(self._a)
        self._wlock = threading.Lock()

    def publish(self, state_map: UserStateMap):
        with self._wlock:
            inactive = self._b if self._ptr.get() is self._a else self._a
            inactive.clear()
            for uid, ps in state_map.items():
                inactive[uid] = copy.copy(ps)
            self._ptr.set(inactive)

    def read(self) -> UserStateMap:
        return self._ptr.get()


# ---- 多人物注册表 ----
class PersonRegistry:
    def __init__(self):
        self.persons: Dict[str, PersonState] = {"user": _empty_state("user")}
        self.current_speaker_id = "user"

    def switch_speaker(self, new_id: str): ...


# ---- M3 分析通道接口（M1 不直接调主脑 API）----
class M3AnalysisChannel:
    def submit(self, req: AnalysisRequest, callback): ...   # 异步


# ---- M1 主模块 ----
class UserModelingModule:
    def __init__(self, tfgr_graph, chroma_collection, m4_bus, m6_bus, m3_channel):
        self.tfgr = tfgr_graph
        self.chroma = chroma_collection
        self.m4 = m4_bus
        self.m6 = m6_bus
        self.m3 = m3_channel                              # 分析通道（β 深度建模）
        self.registry = PersonRegistry()
        self.shared = LockFreeUserStateMap()
        self.emotion_rec = EmotionRecognizer()
        self.sentence_enc = SentenceTransformer(
            "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
        )
        self._running = False
        self._heartbeat_tick = 0

    def start(self):
        self._running = True
        threading.Thread(target=self._tick_loop, daemon=True).start()       # 10Hz 后台
        threading.Thread(target=self._event_loop, daemon=True).start()       # 事件驱动

    def _tick_loop(self):
        """10Hz 后台：实时字段（presence/attention/emotion），纯本地"""
        while self._running:
            t0 = time.monotonic()
            frame = self.m4.poll_frame()                  # 非阻塞
            audio = self.m4.poll_audio()
            for uid, state in self.registry.persons.items():
                if uid != self.registry.current_speaker_id and not state.presence:
                    continue                              # 不在场且非当前说话人，跳过
                if frame is not None:
                    state.presence = update_presence(frame, audio)
                    state.attention = estimate_attention(frame)
                    v, a = self.emotion_rec.update(frame, audio)
                    state.emotion_valence, state.emotion_arousal = v, a
                state.silence_duration = time.monotonic() - state.last_speech_end
            self.shared.publish(self.registry.persons)
            # 心跳（每 1s = 每 10 tick）
            self._heartbeat_tick += 1
            if self._heartbeat_tick >= 10:
                self._heartbeat_tick = 0
                self.m2_heartbeat.publish("M1 alive")
            elapsed = time.monotonic() - t0
            time.sleep(max(0, 0.1 - elapsed))

    def _event_loop(self):
        """事件驱动：ASR完成/语音起止/人物切换/M6传感器/回复闭合"""
        for ev in self.m4.events() + self.m6.events():
            if isinstance(ev, SpeechEndEvent):
                self.registry.persons[ev.user_id].last_speech_end = time.monotonic()
            elif isinstance(ev, AsrCompleteEvent):
                self._on_asr_complete(ev.text, ev.user_id)
            elif isinstance(ev, NewSpeakerEvent):
                self._on_new_speaker(ev.user_id, ev.first_chunk)
            elif isinstance(ev, LucyReplyEvent):
                self._on_lucy_reply(ev.text, ev.user_id)
            elif isinstance(ev, PresenceEvent):           # M6 接近传感器
                self._on_m6_presence(ev)

    def _on_asr_complete(self, text: str, user_id: str):
        state = self.registry.get_or_create(user_id)
        state.current_topic = classify_topic(text)        # §5.4.1 本地 ~30ms
        update_intents_local(text, state)                  # §5.4.2 Tier1/2 + β触发
        facts = extract_facts_local(text, state)         # §5.4 规则抽取 ~20ms
        for k, v in facts.items():
            state.known_facts[k] = v
            write_fact_to_tfgr(user_id, k, v, text, state)   # §10.3
        refresh_known_facts_from_tfgr(state, user_id)     # §10.1 检索重排
        # 复杂句触发 β 深度事实抽取
        if not facts and len(text) > 20:
            schedule_deep_fact_extraction(text, user_id)

## 13. 结语

M1 动态用户建模是 Lucy 感知世界的眼睛与耳朵。它把 M4 的原始多模态流 + M6 的传感器事件转化为 M2 可决策的结构化 `Dict[user_id, PersonState]`，把用户的每句话写入 TFGR 时间流图成为长期记忆，把场景中的多个人物区分建模让 Lucy 能在"和小红聊画展"与"问老王病情"之间自如切换。

M1 的设计核心是**三层分离**：
1. **10Hz 本地基线**（情绪/注意力/在场，<80ms/tick）支撑 α 路径的快速响应，纯本地不依赖网络
2. **事件驱动更新**（话题/意图/事实，<300ms 异步）支撑 M2 的语境组装
3. **β 异步深度建模**（经 M3 分析通道调主脑 API，2-10s）增量增强意图/关系/事实的准确率，失败回退本地规则

这种分离让 Lucy 既能"秒级回话"又能"记住你上周说的面试"，且 M1 的任何失效都不阻断基本对话——M2 用旧状态降级运行，主脑 API 仍能生成有语境的回复。

M1 的多人物建模能力直接承袭 v18 的 `SEED_DIALOGUE` 多人物实验成果，把"小明/小红/老王"的交错对话场景从评测脚本转化为生产能力；与身份守卫的接口清晰——M1 提供用户状态，M2 选择字段序列化进主脑 API system prompt，M3 注入身份锚与 W_probe 守卫，三者各司其职共同保证 Lucy 的身份一致性与用户感知的细腻度。
