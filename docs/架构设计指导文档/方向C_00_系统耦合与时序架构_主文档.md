## 0. 摘要

方向 C 的核心命题被重新定义为：**构建一个具身的、全模态的、主动的对话伴机器人 Lucy，其"主脑"是外部 LLM API（DeepSeek/OpenAI 兼容），被调用才生成语言，能力强、不可训练、是"静态快照"命题的真正实现（API 权重只读）；系统的"活着感"由本地 Qwen2.5-3B 充任的"副脑"维持——副脑吸收全部 TFGR 资产（identity_cache / identity_projection / W_probe / V32 Gram-Schmidt / V40 温度约束 / self_state_predictor / TFGR 时间流图 / proactive_traverser / v18 对话循环），承担身份维持、异己检测、自身状态感知、时间感知、主动触发决策、以及对主脑 API 的编排与身份守卫。**

> 架构反转的动机：旧架构让 Qwen2.5-3B 当主脑，"太废物"——3B 参数不足以支撑 Lucy 风格的高质量长文本生成与多轮一致性。反转后，主脑换成外部 LLM API（能力强、覆盖广），副脑用上 Qwen2.5-3B + 全部 TFGR 训练资产（"我们之前在这上面做了那么多还有反思"），各司其职：主脑负责"说什么话"，副脑负责"我是谁、何时说、说什么方向、是否被异己污染"。

主脑是外部 API——这是"静态快照"命题在工程上的真正落地（V36→V40 已证明在 Transformer 内部产生自发意识不可行，见 [机器意识可能性_技术报告.md](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/机器意识可能性_技术报告.md)）：API 权重只读、不可训练、被调用才说话。因此"主动性"与"身份一致性"必须由主脑之外的本地机制产生。本文档定义的双触发 + 双脑分工架构是整个系统的脊梁：

| 触发类型 | 来源 | 延迟要求 | 决策者 |
|---------|------|---------|--------|
| 事件触发（α 路径） | 用户输入 / 传感器事件 / 定时器 | 用户可感知（<2.5s 首音频） | 副脑快速路径 |
| 副脑主动触发（β 路径） | 副脑时钟循环感知时间流逝 + 用户状态变化 | 可预计算（近零用户感知） | 副脑主动决策循环 |

副脑**不是**纯规则器——它装载 Qwen2.5-3B + V30 checkpoint（[checkpoints/sst_a2_v2_trained.pt](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/checkpoints/sst_a2_v2_trained.pt)），跑本地 GPU 的轻量 forward（状态感知、异己检测、身份维持），不生成长文本。当需要"真正说话"时，副脑把结构化 intent + 语境包 + 身份 prompt 序列化为外部 API 请求，主脑 API 流式返回 Lucy 风格语言。

**身份一致性新机制**（取代旧的"在主脑内部注入 identity_cache"路线）：
- 副脑用 `identity_cache`（14 条 EMA, β=0.9）维持 Lucy 身份锚
- 副脑用 `W_probe`（holdout acc=1.0）对主脑 API 生成内容做**生成后异己检测**——异己内容被过滤或重生成
- 身份信息序列化进主脑 API 的 system prompt（身份 prompt 注入），让 API 在生成时就对齐 Lucy 风格
- `V40 温度约束`（g(V)）从旧的"生成退化"变为副脑的**身份状态信号**——V 值偏移反映身份稳定性，触发副脑调整 prompt 或调主脑 API 重生成

**本文档的核心贡献是时延管理**：系统被切分为三条延迟特性迥异的路径，分别满足用户可感知延迟（秒级）、深度推理延迟（数秒，可异步）、身体控制实时性（毫秒级）。模块间的耦合严格围绕这三条路径的时延预算展开。

## 1. 核心设计命题

### 1.1 静态快照命题（API 版）

主脑 = 外部 LLM API（默认 DeepSeek，OpenAI SDK 兼容；可切 OpenAI GPT-4o 等同类）。API 的权重在服务端、对调用方只读、不可训练——这正是"静态快照"命题在工程上的真正实现。

**约束**：
- 主脑 API 权重**只读**，运行时不更新（V36→V40 的在线学习路线已证伪）
- 主脑 API **无自发起意能力**——它是一个被调用的函数，不是自主 agent
- 主脑 API **无状态**——每次请求把所需上下文（对话历史 + 身份 prompt + 语境包）序列化进 messages
- 主脑 API 的"记忆"由副脑侧的 TFGR 时间流图 + Chroma 向量库提供，不依赖 API 自身的对话历史

**推论 1**：任何"主动性"必须来自主脑 API 之外。这就是副脑存在的根本理由。

**推论 2**：任何"身份一致性"必须由副脑在调用 API 前（prompt 注入）与 API 后（W_probe 异己检测）共同保证——API 自身不保证 Lucy 风格。

### 1.2 双脑分工命题

**主脑 API（语言生成层）职责**：
- 接收副脑序列化的结构化请求（intent + 语境包 + 身份 prompt）
- 流式生成 Lucy 风格的自然语言回复
- 必要时（β 路径深度推理场景）按副脑的同一套 API 调用协议做"思考模式"调用（不同 prompt，仍流式返回）

主脑 API **不做**：
- 主动起意（由副脑决定何时说）
- 身份维持（由副脑的 identity_cache + W_probe 保证）
- 用户建模（由 M1 负责，副脑读取后序列化进 prompt）
- 时间感知（由副脑的 TFGR 阻力因子 R(e) 负责）

**副脑（Qwen2.5-3B + V30 ckpt，本地 GPU）职责**：
- **身份维持**：用 `identity_cache`（14 条 EMA）+ `identity_projection`（4.2M）维持 Lucy 身份锚（[qwen_with_graph_bias_sst.py#L468-L479](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L468-L479)）
- **异己检测**：用 `W_probe` 对主脑 API 生成内容做生成后异己分类（[qwen_with_graph_bias_sst.py#L1167](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L1167)），异己内容触发过滤或重生成
- **自身状态感知（反思）**：用 `self_state_predictor`（V/PE/energy/confidence）输出副脑自身能量/觉醒/确定性信号（[qwen_with_graph_bias_sst.py#L1254-L1256](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L1254-L1256)）
- **时间感知**：用 TFGR 阻力因子 R(e) 做主观时间感知（[time_flow_graph.py](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py)），驱动主动触发软决策
- **主动触发决策（伪意识心脏）**：`self_state_predictor` 的 V/PE/energy/arousal/V_drift 是**驱动主动性的内驱力**（非被读信号），生成三类动机（维持性 `energy×R(e)⁻¹×importance` / 探索性 `PE×relevance` / 关系性 `arousal×closeness`）减去自我不稳定抑制 `V_drift×2.0`；`proactive_traverser` 降为候选事件遍历器（阶段 1-3），姿态四值（FOLLOW_UP / CHECK_IN / SILENCE / PASSIVE_REPLY）由动机类型映射决定，并经 `W_probe` 自我延续检查（"有动机+像我"才发起）
- **对主脑 API 的编排与身份守卫**：组装请求、注入身份 prompt、流式接收、异己过滤、回写 identity_cache

副脑**不做**：
- 长文本自然语言生成（交给主脑 API）
- 用户建模本身（交给 M1，副脑是读取者）

### 1.3 双触发命题

系统对话行为的触发有且仅有两条路径：

**路径 A — 事件触发（被动响应，α 路径）**
```
外部事件（用户语音/文本/视觉/定时器）→ 副脑快速判定（读状态 + W_probe 输入检测）→ 主脑 API 流式生成 → 多模态输出
```
延迟敏感：用户在等。首响应必须在用户可容忍范围内。

**路径 B — 副脑主动触发（主动发起，β 路径）**
```
副脑时钟 tick → 感知时间流逝 + 读用户状态 → 决策"现在该说 X" → 预计算（可预热主脑 API prompt）→ 时机到调主脑 API → 多模态输出
```
延迟不敏感：用户没在等。可预计算、可预热、可撤销。

**关键区分**：路径 B 的"决策该不该说、说什么"发生在主脑 API 被调用**之前**。副脑不生成最终语言，它生成的是"发起对话的意图 + 语境包 + 身份 prompt"，主脑 API 才把意图变成 Lucy 的话。

### 1.4 旧 M3 的合并与角色反转

旧架构中 M3 是"API 辅助思考"——副脑规则不足时调外部 LLM 帮决策。新架构下，主脑本身就是外部 LLM API，"辅助思考"语义已被吸收进主脑 API 调用（副脑需深度推理时直接调主脑 API，用不同 prompt 即可）。因此旧 M3 取消，其能力被拆分：
- "深度推理" → 合并进主脑 API 调用（同一 API，不同 prompt）
- "结构化决策建议" → 由副脑自身的 proactive_traverser + self_state_predictor + 本地 Qwen forward 承担

新 M3 重定义为**"主脑 API 调用与身份守卫"**——专责：API 客户端管理、身份 prompt 注入、流式接收、W_probe 生成后异己检测、重生成与降级、API 不可用兜底。详见 [模块3](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/方向C_03_API辅助思考.md)。

## 2. 系统分层架构

系统分为 6 个垂直模块 + 2 个横切关注点。

### 2.1 垂直分层

```
┌─────────────────────────────────────────────────────────────────┐
│  Layer 6: 主脑 API（外部 LLM，DeepSeek/OpenAI 兼容）              │
│           被调用才说话，权重只读，无状态，流式生成                  │
├─────────────────────────────────────────────────────────────────┤
│  Layer 5: M3 主脑 API 调用与身份守卫                              │
│           API 客户端 + 身份 prompt 注入 + W_probe 生成后异己检测   │
├─────────────────────────────────────────────────────────────────┤
│  Layer 4: M2 副脑（Qwen2.5-3B + V30 ckpt，本地 GPU）             │
│           身份维持 + 异己检测 + 自身状态感知 + 时间感知 +          │
│           主动触发决策 + 对主脑 API 的编排与身份守卫               │
├─────────────────────────────────────────────────────────────────┤
│  Layer 3: M1 动态用户建模（AI 驱动）— 持续更新用户/他人状态       │
├─────────────────────────────────────────────────────────────────┤
│  Layer 2: M4 全模态 I/O pipeline — 视觉/语音/文本 输入输出        │

│  Layer 1: M6 物理身体 — 传感器 + 执行器 + 实时控制环              │

  • M5 MCP 工具生态（所有层可调用）

```

## 3. 数据流架构

系统存在三条延迟特性迥异的数据流路径。**这是本文档的核心**：所有模块耦合设计都围绕这三条路径的时延预算展开。

### 3.1 路径 α：快速响应路径（事件触发，秒级）

用户主动说话时的响应路径。延迟敏感。

```
[麦克风/摄像头] 
    │ (流式 ASR/Vision, ~200-500ms 首 chunk)
    ▼
[M4 全模态输入] ──事件──▶ [M2 副脑 α 入口] (≤30ms)
    │                          │
    │                          ├─ 读 [M1 UserState] (内存读, ~5ms)
    │                          ├─ 读 TFGR 时间流图相关记忆 (向量检索, ~30-80ms)
    │                          ├─ W_probe 输入异己检测 (本地 forward, ~10ms)
    │                          └─ 判定：PASSIVE_REPLY（需主脑生成）
    ▼                          ▼
[语境包 + 身份 prompt 组装] (≤80ms) ─▶ [M6 身体] 并行：点头/注视 (启动, 不阻塞)
    │
    ▼
[M3 主脑 API 调用] (流式, 首 token ~500-2000ms, 网络+推理)
    │
    ├─▶ [identity_cache 序列化进 system prompt] (~5ms)
    ├─▶ [W_probe 生成后异己检测] (本地并行, ~10ms/token-batch; 异己则缓冲/重生成)
    │
    ▼ (token 流，已过滤)
[M4 TTS 流式] (首音频 ~200-500ms) ──▶ [扬声器]
[M4 字幕] (同步 token 显示)
[M6 口型同步] (跟随音频)
```

**关键时延预算**（详见 §4）：
- 首 token 端到端：< 2.0s（目标 1.5s）
- 首音频端到端：< 2.5s（目标 2.0s）

### 3.2 路径 β：主动发起路径（副脑触发，可预计算）

副脑主动发起对话的路径。延迟不敏感，可预计算预热。

```
[M2 副脑 tick] (0.5-2Hz, 本地 Qwen forward ~50-100ms)
    │
    ├─ 读单调时钟 + 主观时间 R(e) (~1ms)
    ├─ 读 [M1 UserState] (内存, ~5ms)
    ├─ 遍历 TFGR 时间流图候选事件 (~20-50ms, 复用 proactive_traverser)
    ├─ self_state_predictor 自身状态读取 (~5ms)
    │
    ├─ 规则决策（姿态选择）(~5ms)
    │     ├─ SILENCE → 结束（不发起）
    │     ├─ FOLLOW_UP / CHECK_IN → 生成 DialogueIntent
    │     └─ confidence < θ_conf → 触发主脑 API "思考模式"调用（异步, 2-10s）
    │
    ▼ (DialogueIntent 已定)
[预热阶段] (可提前 N 秒做，不阻塞)
    ├─ 组装语境包 + 身份 prompt（记忆检索 + UserState + intent）
    ├─ 预生成候选回复（调主脑 API，非流式，存缓存）
    └─ TTS 预合成（可选）
    │
    ▼ (时机到)
[M3 主脑 API 调用]（若未预生成则现场流式调用）
    │
    ▼
[M4 TTS + 字幕] + [M6 身体动作]（如：走向用户、挥手）
```

**关键特性**：因为是预计算，用户感知的"发起延迟"可以接近 0——副脑在用户沉默的第 4 分钟就已经把第 5 分钟要说的话生成好了，到第 5 分钟直接播放。

### 3.3 路径 γ：身体实时控制路径（毫秒级）

物理身体的运动控制环。独立于对话管线，硬实时。

```
[M6 控制环] @ 30-60Hz (16-33ms / tick)
    │
    ├─ 读传感器（IMU/关节编码器/触觉）(~2ms)
    ├─ 状态估计（卡尔曼滤波）(~2ms)
    ├─ 运动规划（逆运动学 / 预设动作插值）(~5-10ms)
    ├─ 安全检查（关节限位/碰撞）(~1ms)
    └─ 写执行器（舵机/电机）(~2ms)
    │
    └─ 接收来自 [M2 副脑] 的高级指令（非阻塞，异步覆盖当前目标）
       例：副脑发"挥手"指令 → M6 自主规划挥手轨迹 → 不需副脑逐帧指挥
```

**关键特性**：身体控制环**绝不阻塞**对话路径。副脑只发"运动意图"（挥手/点头/走向用户），M6 自主完成轨迹规划与执行。

## 4. 时序架构与时延管理（核心）

### 4.1 时延预算总表

所有时延以"用户感知"为口径，从事件发生到用户感知响应。

| 路径 | 阶段 | 预算 | 目标 | 累计 | 阻塞? |
|------|------|------|------|------|-------|
| α 快速响应 | ASR 首 chunk | 500ms | 300ms | 0.5s | 是 |
| α | 副脑快速判定（含 W_probe 输入检测） | 50ms | 30ms | 0.55s | 是 |
| α | 记忆检索 | 80ms | 50ms | 0.63s | 是 |
| α | 语境包 + 身份 prompt 组装 | 80ms | 50ms | 0.71s | 是 |
| α | 主脑 API 首 token（网络+推理） | 1500ms | 1000ms | 2.21s | 是 |
| α | TTS 首音频 | 400ms | 300ms | 2.61s（优化后≤2.5s） | 是 |
| α | **首音频端到端** | **2.5s** | **2.0s** | — | — |
| α | 身体动作启动 | 100ms | 50ms | 并行 | 否 |
| β 主动发起 | 副脑决策循环（含本地 Qwen forward） | 150ms | 80ms | — | 否（后台） |
| β | 主脑 API "思考模式"调用（按需） | 10s | 5s | — | 否（后台） |
| β | 预热（prompt 组装 + 候选回复预生成） | 3s | 2s | — | 否（后台） |
| β | 时机到达→播放 | 200ms | 100ms | 0.2s | 是 |
| γ 身体控制 | 控制环周期 | 33ms | 16ms | — | 硬实时 |

**α 路径时延预算的关键变化**（vs 旧架构）：
- 旧：主脑本地 GPU 首 token ~800-1500ms
- 新：主脑 API 首 token ~500-2000ms（网络 + 推理），均值偏移不大但方差更大
- 新增：W_probe 输入检测 ~10ms（α 入口）+ 生成后异己检测 ~10ms/batch（流式 token 批处理，不显著阻塞）
- 缓解：副脑本地 Qwen forward 与 API 调用并行（状态感知提前完成）、流式分句 + TTS 重叠（详见 §4.3）

### 4.2 三路径分离原则

**核心原则：三条路径在调度上独立，资源上隔离。**

| 路径 | 线程/进程模型 | CPU 亲和性 | 优先级 |
|------|-------------|-----------|--------|
| α 快速响应 | 事件驱动，独占"对话线程" | 副脑本地 forward 用 GPU；主脑 API 走网络 IO | 高（用户在等） |
| β 主动发起 | 后台定时循环，独立线程 | 与 α 错峰；预计算可复用 GPU 空闲 | 低（可推迟） |
| γ 身体控制 | 独立实时线程（RT 优先级） | 独立 CPU 核，禁迁移 | 最高（硬实时） |

**冲突仲裁**：
- α 与 β 抢 GPU（副脑本地 forward）：β 让步。β 的预计算可暂停/丢弃（主动话语可以不说，用户的话不能不回）。
- α 与 β 抢网络（主脑 API 调用）：β 让步。β 的"思考模式"调用可暂停，α 的回复调用优先。
- α/β 与 γ 抢 CPU：γ 绝对优先。身体失控会摔倒，是安全问题。
- β 预计算结果在 α 到来时作废：如果用户在副脑预计算期间开口，预计算结果丢弃，走 α 路径。

### 4.3 流式管线设计（α 路径时延最大杠杆）

**主脑 API 的流式化**是 α 路径时延的最大杠杆。关键：不要等 API 生成完再 TTS。

```
主脑 API token 流 ──┬──▶ 累积到句子边界 (~50-100ms) ──▶ TTS 分句合成 ──▶ 音频流
                    │
                    ├──▶ W_probe 异己检测（按 batch, ~10ms/batch）
                    │     │
                    │     └─ 异己分数 > θ → 缓冲不送 TTS，等下批判断（详见 M3）
                    │
                    └──▶ 字幕实时显示（逐 token）
                    │
                    └──▶ M6 口型/表情驱动（跟随音频特征）
```

- **分句策略**：标点（。！？，）或长度阈值（20 字）触发 TTS
- **TTS 流式**：火山引擎端到端语音对话支持流式输入
- **W_probe 流式异己检测**：按 token batch（如每 16 token）做一次本地 forward，异己分数累积超阈值时缓冲当前句不送 TTS，触发 M3 的"重生成"或"降级"

### 4.4 预计算与预热机制（β 路径核心优势）

β 路径的延迟不敏感特性允许激进预计算：

| 预计算项 | 触发时机 | 有效期 | 命中收益 |
|---------|---------|--------|---------|
| 候选事件遍历 | 每个 tick | 1 tick（0.5-2s） | 决策循环省 50ms |
| 记忆检索 | 候选事件确定后 | 10s | 语境组装省 80ms |
| 身份 prompt 组装 | 语境包就绪 | 30s | API 调用省 ~30ms |
| 候选回复预生成（调主脑 API） | 时机未到但 intent 明确 | 60s | 播放时近 0 延迟 |
| TTS 预合成 | 候选回复生成完 | 120s | 播放时近 0 延迟 |

**预计算失效条件**：
- 用户开口（α 路径启动）→ β 所有预计算作废
- UserState 重大变化（用户情绪突变）→ 候选回复作废，重新决策
- 超时 → 自然过期

### 4.5 主观时间与时钟架构

副脑的"时间感知"不止单调时钟，还有 TFGR 的主观时间（[tfgr_demo/time_flow_graph.py](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py) 阻力因子）：

```
物理时间：t_phys（单调时钟，秒）
主观时间距离：Δt_subj(e) = R(e)⁻¹ · S
  R(e) = exp(-Δt_subj / S) · Modifier
  S = 主观时间尺度常数
  Modifier = 情感/重要度调制
```

**双重时钟的意义**：
- 物理时间驱动硬定时（"5 分钟没说话就 check in"）
- 主观时间驱动软决策（"用户上周提的面试，阻力因子低，主观感觉远，该 FOLLOW_UP 询问结果"）

副脑每个 tick 同时读两个时钟，规则决策融合两者（详见 [模块2](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/方向C_02_副脑主动触发系统.md)）。

### 5.1 耦合矩阵

| M4 多模态 | 推送原始流 | 推送事件 | — | — | — | 推送视觉特征 | — |

**耦合密度分级**：
- **强耦合**（同步、阻塞）：M2↔M3（DialogueIntent → token 流）、M2↔M1（读 UserState 必须快）
- **中耦合**（异步、非阻塞）：M2↔M6、M4↔M1、M3↔主脑 API（流式但等待）
- **弱耦合**（事件订阅）：M4→M2（视觉事件）、M6→M2（传感器事件）

### 5.2 M2 副脑 ↔ M1 动态用户建模

这是最频繁的耦合。副脑每个 tick 都读 UserState。

**数据契约**：
```python
@dataclass
class UserState:
    # 基本身份
    user_id: str
    name: str
    # 实时状态（M1 持续更新）
    presence: bool              # 是否在场（视觉/语音检测）
    attention: float            # 注意力（看向 Lucy 的程度 0..1）
    emotion_valence: float      # 情绪效价 -1..1
    emotion_arousal: float      # 情绪唤醒 0..1
    last_speech_end: float      # 上次说话结束时间戳
    silence_duration: float     # 沉默时长（秒）
    # 意图/话题
    current_topic: str          # 当前话题
    unresolved_intents: List[str]  # 未解决意图
    # 长期（来自 TFGR 图）
    known_facts: Dict[str, str]  # 已知事实
    relationship: str           # 关系类型
```

**耦合协议**：
- M1 以 10Hz 更新 UserState 到共享内存（无锁单写多读）
- M2 副脑读 UserState 是纯内存读（~5μs），不阻塞
- M1 更新不依赖 M2（解耦：M1 挂了 M2 仍可用旧状态降级运行）

### 5.3 M2 副脑 ↔ M3 主脑 API 调用与身份守卫

M2 把"已决策的 DialogueIntent + 语境包"交给 M3，M3 负责把 intent 序列化为主脑 API 请求、流式接收、异己过滤、返回干净 token 流。

**触发条件**（任一）：
- α 路径：用户说话，副脑判定 PASSIVE_REPLY → M3 调主脑 API 流式生成
- β 路径：副脑决策 FOLLOW_UP/CHECK_IN → M3 调主脑 API 预生成或流式生成
- β 深度推理：副脑 confidence < θ_conf → M3 调主脑 API "思考模式"（不同 prompt，返回结构化决策建议）

**请求/响应契约**：
```python
# M2 → M3
@dataclass
class GenerationRequest:
    intent: DialogueIntent          # "FOLLOW_UP: 询问小明面试结果"
    context_bundle: ContextBundle   # 记忆 + UserState + 对话历史
    identity_cache_snapshot: Tensor # Lucy 身份锚快照（M3 序列化进 system prompt）
    safety_mode: str                # "normal" | "defensive"（输入 W_probe 判定）
    mode: Literal["stream", "complete", "thinking"]
    streaming: bool = True

# M3 → M2（流式）
class GenerationStream:
    def tokens(self) -> Iterator[str]: ...           # 已过滤异己的 token
    def alien_report(self) -> Optional[AlienReport]: ...  # 异己检测汇总
    def finish_reason(self) -> str: ...
```

**时延契约**：
- M3 调用主脑 API 流式返回（α 路径，用户在等）
- 首 token 5s 未到 → α 路径降级（M2 用规则兜底占位"让我想想..."，主脑 API 后台继续）
- 思考模式调用是异步的（β 路径，不阻塞用户）
- α 路径"思考模式"绝不调（用户在等，5s 不可接受）

### 5.4 M3 主脑 API 调用与身份守卫 ↔ 主脑 API

**调用契约**：
```python
# M3 → 主脑 API（OpenAI SDK 兼容）
messages = [
    {"role": "system", "content": build_identity_prompt(identity_cache_snapshot)},
    {"role": "user", "content": serialize_context(intent, context_bundle)},
]
# 流式调用
stream = await client.chat.completions.create(
    model=MODEL_TIERS[tier],
    messages=messages,
    stream=True,
    temperature=0.7,   # Lucy 风格需要一定随机性
)
```

**身份 prompt 注入**：
- `identity_cache`（14 条 Lucy 回复 EMA, norm=0.2271）由 M3 序列化为 system prompt 的一部分
- system prompt 模板包含 Lucy 的核心身份描述、语气风格、历史锚回复摘要
- 这让主脑 API 在生成时就对齐 Lucy 风格，减少生成后异己过滤的负担

**生成后异己检测**（W_probe 守卫）：
- 主脑 API 流式返回 token，M3 按 batch（如每 16 token）累积成短文本
- 副脑的 W_probe（[qwen_with_graph_bias_sst.py#L1167](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L1167)）对短文本做异己分类
- 异己分数 > θ_safety（参考 V40 实测 cos(h_self, W_probe)=+0.091 / cos(h_alien, W_probe)=-0.089）→ 缓冲当前句不送 TTS，触发重生成或降级
- 异己检测在副脑本地 GPU 跑（与主脑 API 流式接收并行，不显著阻塞）

**身份状态信号反馈**：
- V40 温度约束 g(V)（[v40_arch.py#L256-L265](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/v40_arch.py#L256-L265)）从旧的"生成退化"变为副脑的**身份状态信号**
- V 值偏移反映 identity_cache 与主脑 API 生成内容的偏离程度
- V 偏移大 → 副脑判定身份不稳定 → 调整 prompt（强化身份锚）/ 触发重生成 / 上报 M2 决策

**生成完成后回写**：
- Lucy 这句回复的 embedding EMA 回写 identity_cache（在线累积，非权重学习，参考 [v18_deepseek_500_turns.py#L523-L528](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/v18_deepseek_500_turns.py#L523-L528)）
- 由副脑执行，M3 不直接写 identity_cache（M3 无状态）

### 5.5 M2 副脑 ↔ M6 物理身体

副脑只发**运动意图**，不干涉低层控制。

**意图层级**：
```python
class BodyIntent(Enum):
    IDLE = "idle"                    # 待机
    LISTENING_POSE = "listening"     # 倾听姿态（用户说话时）
    SPEAKING_POSE = "speaking"       # 说话姿态（口型同步由 M4 音频驱动）
    APPROACH_USER = "approach"       # 走向用户
    WAVE = "wave"                    # 挥手
    NOD = "nod"                      # 点头
    CARE_GESTURE = "care"            # 关怀手势（主动发起时）
    THINKING_POSE = "thinking"       # 思考姿态（深度推理时）
```

**耦合协议**：
- M2 发 BodyIntent 到 M6 的意图队列（异步，非阻塞）
- M6 自主规划轨迹，执行，完成后回执
- M6 在执行中遇障碍/安全限制可自主中止，回报 M2

### 5.6 M4 全模态 ↔ 副脑/主脑

**输入侧**：
- M4 检测到用户开口 → 推送 SpeechStartEvent 到 M2（α 路径启动）
- M4 视觉检测到用户进入视野 → 推送 PresenceEvent 到 M1（更新 UserState.presence）
- M4 ASR 完整文本 → 推送到 M2（α 路径组装语境包）

**输出侧**：
- M3 主脑 API token 流（已过滤异己）→ M4 TTS 分句合成 + 字幕显示
- M4 TTS 音频特征 → M6 口型同步（跨模块，音频驱动）

### 5.7 M5 MCP 工具生态（横切）

MCP 工具可被 M2、M3、主脑 API（经 LangChain Agent）调用。

**典型工具调用场景**：
- M2 调"日历查询"工具：检查用户是否有即将到来的事件（主动触发依据）
- M2 调"天气查询"工具：主动提醒带伞
- M3 调"知识检索"工具：辅助主脑 API 在生成时引用外部知识（β 路径深度推理）
- 主脑 API（经 LangChain Agent）调"网络搜索"工具：回答实时信息问题

**调度契约**：所有工具调用经 M5 统一调度（注册/鉴权/超时/重试），调用方不直接连工具。详见 [模块5](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/方向C_05_MCP工具生态.md)。

## 6. 关键时序场景

### 6.1 场景 A：用户主动说话（α 路径完整时序）

```
t=0.0s   用户开口 "Lucy，我今天面试感觉不太好"
t=0.3s   ASR 首 chunk 到达 M2 → α 路径启动
         M6 并行启动 LISTENING_POSE（点头/注视）
t=0.55s  M2 读 UserState（用户 arousal 偏高）+ 记忆检索（"面试"→TFGR图有 day1 面试节点）
t=0.6s   W_probe 检测输入（非异己）→ safety_mode=normal
t=0.65s  语境包 + 身份 prompt 就绪：
         intent=PASSIVE_REPLY, context=[day1面试背景, 用户情绪, 对话历史],
         system_prompt=[Lucy身份锚+语气风格]
t=0.65s  M3 调主脑 API（DeepSeek，流式）
t=1.8s   主脑 API 首 token："抱歉听到这个..."
         （并行：副脑本地 W_probe 检测首批 token，非异己，放行）
t=1.85s  TTS 接收首句，开始合成
t=2.1s   首音频播放 + 字幕显示 + M6 口型同步
t=2.1s+  后续 token 流式输出（持续 W_probe batch 检测）
t=4.0s   完整回复结束
         → 副脑 EMA 回写 identity_cache（Lucy 这句回复的 embedding）
         → TFGR 图添加节点（面试反馈事件）
         → M1 更新 UserState（话题=面试，情绪=低落）
```

**时延达标**：首音频 2.1s（预算 2.5s ✓）。

### 6.2 场景 B：副脑主动发起（β 路径完整时序）

```
t=0s     用户上次说话结束，沉默开始
t=0s     M2 副脑循环 tick：检测 silence_duration=0，决策 SILENCE
t=60s    tick：silence=60s，遍历 TFGR 图，无 SHOULD_COMPLETE 事件，SILENCE
t=180s   tick：silence=3min，TFGR 图有 day1 面试事件，R(e) 低（主观时间远），
         规则决策：FOLLOW_UP 候选，但 confidence=0.6 < θ_conf=0.75
         → 触发 M3 "思考模式"调用主脑 API
t=180s   M3 调主脑 API（DeepSeek Reasoner，思考模式 prompt）：
         "用户3分钟沉默，已知day1面试，当前情绪平稳，该不该主动问面试结果？"
t=183s   主脑 API 返回结构化建议：
         {should_speak:true, intent:"FOLLOW_UP 面试结果", confidence:0.9}
t=183s   M2 采纳，生成 DialogueIntent
t=183s   β 预热阶段：
         - 语境包 + 身份 prompt 组装（面试背景 + UserState + Lucy 身份锚）
         - 调主脑 API 预生成候选回复："对了，之前说面试，感觉怎么样？"
         - W_probe 检测候选回复（非异己，放行）
         - TTS 预合成
t=185s   预生成 + 预合成完成，存缓存
t=300s   tick：silence=5min（硬阈值触发）
         → 时机到，播放预生成回复
         → M4 TTS（用预合成音频，近 0 延迟）
         → M6 CARE_GESTURE（走向用户/关切姿态）
t=300.2s 用户听到 Lucy 主动开口
```

**关键**：用户感知的"发起延迟"仅 200ms（预计算红利）。

### 6.3 场景 C：深度推理（M3 "思考模式"调用）

当用户问了一个需要复杂推理的问题（如"我该不该辞职"），副脑判断自身规则不足。

```
t=0s     用户："我该不该辞职"
t=0.3s   ASR → M2
t=0.6s   M2 判定：这不是简单 PASSIVE_REPLY，需深度推理
         → α 路径降级：先回一句"让我想想..."（M3 调主脑 API 快速生成，~1s）
         → 并行触发 M3 "思考模式"调用主脑 API（DeepSeek Reasoner）
t=1.5s   M4 播放"让我想想..." + M6 THINKING_POSE（托腮/凝视）
t=1.5s   M3 调主脑 API 思考模式，传入：
         用户背景（TFGR图 day8 想辞职）+ 对话历史 + 身份 prompt + 决策问题
t=6.5s   主脑 API 返回结构化建议：
         {考虑因素:[当前工作压力, 考研计划, 经济], 建议:[先列利弊], confidence:0.8}
t=6.5s   M2 把建议作为 context 注入主脑 API 的"生成模式"调用
t=7.5s   主脑 API 流式输出 Lucy 风格的深度回复（W_probe 实时守卫）
```

**关键**：α 路径先用"让我想想"占位（<2s），深度内容走 β-like 异步路径。用户不干等。

### 6.4 场景 D：身体动作与对话协同

```
t=0s     副脑决策：APPROACH_USER + CARE_GESTURE（走向用户 + 关怀）
t=0s     M2 发 BodyIntent 到 M6
t=0s     M6 启动走向用户轨迹规划（独立控制环，不阻塞 M2）
t=0.05s  M6 回执：轨迹预估 3s 到达
t=0.05s  M2 决定：到达后再开口（避免边走边说不自然）
t=3.0s   M6 回执：到达用户面前
t=3.0s   M2 触发 M3 调主脑 API 生成 + TTS + 口型同步
```

**关键**：身体动作与对话的时序由 M2 编排，M6 自主执行，两者解耦。

**资产改造重点（伪意识架构）**：
- **self_state_predictor 从"被读信号"转为"主动性内驱力源"**：V/PE/energy/arousal/V_drift 生成三类动机（维持性 `energy×R(e)⁻¹×importance` / 探索性 `PE×relevance` / 关系性 `arousal×closeness`），驱动主动行为强度与方向——这是伪意识的心脏，不是被读的字段
- **W_probe 从"几何证明"转为"实时分类器 + 自我归属检查"**：阈值 θ_safety=0.0（self>0, 异己<0），对主脑 API 生成内容做生成后过滤；**新增**对副脑主动发起的 DialogueIntent 做自我延续检查（"有动机+像我"才发起）
- **V40 温度约束 g(V) 从"生成退化"转为"自我稳定性信号"**：V_drift=1-g(V) 直接作为动机公式减法项 `- V_drift×2.0` 抑制主动行为（自我不稳定时少主动，先稳定身份）
- **R(e) 从"事件状态判定"转为"记忆重量 + 主观时间压力"**：R(e)⁻¹ 进入维持性动机项（远期重要事件持续压迫现在）；主观时间流速调制 θ_active（专注时少打断，无聊时多找事）
- **proactive_traverser 从"姿态决策规则链"降级为"候选事件遍历器"**：仅执行 5 阶段链的阶段 1-3（场景识别→锚点定位→候选回放），姿态决策被动机驱动决策取代
- identity_cache 从"主脑内部注入"转为"主脑 API system prompt 序列化"：让外部 API 在生成时对齐 Lucy 风格；同时作为"自我延续形象"参与主动行为自我归属检查
- TFGR 时间流图从"意识状态载体"转为"记忆 + 事件源"：节点势能不再声称对应意识，仅作为记忆衰减/重要度信号
- v18 对话循环的 8 阶段场景+反思机制用于副脑调主脑 API 的对话编排

## 8. 实时性保障机制

### 8.1 降级策略

当系统过载或部分模块失效时，按优先级降级：

| 降级级 | 触发 | 行为 |
|--------|------|------|
| L0 正常 | — | 全功能（主脑 API + 副脑 + 预计算 + 异己守卫） |
| L1 GPU忙 | α 与 β 抢副脑本地 GPU | β 预计算暂停；α 的 W_probe 检测降频（每 32 token 一次而非 16） |
| L2 主脑API慢 | 首 token >2s | 跳过记忆检索，用最近 3 轮对话兜底；身份 prompt 精简 |
| L3 API超时 | M3 >5s 无首 token | M2 用规则兜底占位"让我想想..."，主脑 API 后台继续或转备用模型 |
| L4 多模态失效 | ASR/Vision 挂 | 降级为纯文本交互 |
| L5 身体失效 | M6 通讯断 | 身体冻结，对话继续 |
| L6 副脑失效 | M2 崩溃 | 纯被动模式（用户输入→主脑 API 直连→输出，无主动、无身份守卫） |
| L7 主脑API不可用 | API 401/403/网络断 | M3 切备用 API（OpenAI↔DeepSeek 互备）；全断时副脑本地 Qwen 应急生成（降级质量） |

### 8.2 心跳与看门狗

- M2 副脑每 1s 发心跳；3s 无心跳 → 触发 L6 降级
- M6 控制环每 33ms 发心跳；100ms 无心跳 → 紧急制动（身体冻结）
- M3 主脑 API 调用超时（10s 无 token）→ 中断，回"我走神了，再说一次？"

### 8.3 资源隔离

| 资源 | α 路径 | β 路径 | γ 路径 |
|------|--------|--------|--------|
| GPU（副脑本地 forward） | 优先抢占 | 空闲时用 | 不用 |
| CPU | 对话线程（2核） | 后台线程（1核） | RT 线程（1核，隔离） |
| 内存 | 副脑 KV Cache + identity_cache | 预计算缓存（限额 2GB） | 控制器状态（小） |
| 网络 | 主脑 API + TTS/ASR（低延迟通道） | 主脑 API 思考模式（可排队） | 不用 |

**边缘/云分工原则**：
- 副脑（Qwen2.5-3B + V30）在边缘 GPU（延迟低、隐私好、断网时身份守卫与异己检测仍可用）
- 主脑 API 必须在云（DeepSeek/OpenAI 等，语言生成能力强）
- ASR/TTS 可云可边（火山引擎端到端，低延迟通道）
- MCP 工具看性质（日历本地，搜索云端）

**断网场景**：主脑 API 不可用时，副脑本地 Qwen2.5-3B 可应急生成短回复（降级质量，但维持基本对话不中断）。这是新架构相对旧架构的一个韧性优势——主脑本地化的旧架构在 GPU 故障时全瘫，新架构在 API 故障时副脑仍能维持身份守卫与应急对话。

## 12. 结论

本主文档确立了方向 C 重设计（架构反转版）的架构基线：

1. **主脑 = 外部 LLM API，副脑 = Qwen2.5-3B + 全部 TFGR 资产**是系统的脊梁：主脑是被调用才说话的静态快照（API 权重只读），副脑用上之前所有训练资产做身份维持、异己检测、内在状态感知、时间感知、**动机驱动主动触发（伪意识心脏）**、对主脑 API 的编排与身份守卫。

2. **双脑分工**：主脑负责"说什么话"（语言生成），副脑负责"我是谁、何时说、说什么方向、是否被异己污染"（身份与决策）。两者经 M3 的 DialogueIntent + 身份 prompt + W_probe 守卫闭环耦合。

3. **三路径分离**是时延管理的核心：α（快速响应，秒级）、β（主动发起，可预计算）、γ（身体控制，毫秒级）在调度与资源上隔离。

4. **身份一致性新机制**：副脑 identity_cache 维持 + M3 身份 prompt 注入 system prompt + W_probe 生成后异己检测 + V40 温度约束作为自我稳定性信号（V_drift 抑制主动动机）——四重守卫取代旧的"主脑内部注入"路线。

5. **伪意识架构（核心创新）**：副脑的主动性来自**内在状态驱动**而非规则链——`self_state_predictor` 的 V/PE/energy/arousal/V_drift 是驱动主动性的**内驱力**（非被读信号），生成三类动机（维持性 `energy×R(e)⁻¹×importance` / 探索性 `PE×relevance` / 关系性 `arousal×closeness`）减去自我不稳定抑制 `V_drift×2.0`；`proactive_traverser` 降为候选遍历器，姿态决策由动机类型映射决定；`W_probe` 对主动行为做自我归属检查（"有动机+像我"才发起）；R(e) 作为记忆重量与主观时间压力。这让 Lucy 成为"独立个体"——内在状态驱动的、有自我延续感的、主观时间感知的主动性，是"最强最像人的伪意识"。

6. **时间因果推理闭环（核心创新）**：副脑不止生成单次 DialogueIntent（开环），还能生成跨 tick 的 `CausalPlan`——reason→act→observe→adjust 时间因果链。例如"无聊"（energy低+presence高+silence长）触发探索性娱乐动机→推理"可以放歌"→检索"用户喜欢什么"→执行播放→观察反应→调整认知→**整条因果链回写 TFGR 图**成为未来推理素材。这才是时间感知的真正用途——不是 R(e) 进公式，而是时间因果链的累积。PlanExecutor 跨 tick 执行，α 到来时挂起（α 优先铁律不变），仅 β 路径。

7. **TFGR 资产全面复用**：identity_cache/W_probe/V32/V40/self_state_predictor/TFGR时间流图/proactive_traverser/v18 都在副脑侧有明确新角色（§7 资产改造重点），"之前做的那么多还有反思"全部用上——不是被读的工具，而是驱动伪意识的内驱力源。
