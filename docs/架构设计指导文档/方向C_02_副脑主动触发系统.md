## 1. 摘要

方向C 架构反转后，主脑换成外部 LLM API（DeepSeek/OpenAI 兼容，权重只读、被调用才说话），副脑由 Qwen2.5-3B + V30 checkpoint 充任——**副脑不是纯规则器**，它在本地 GPU 跑轻量 forward（状态感知 / 异己检测 / 身份维持），吸收全部 TFGR 资产，承担身份维持、异己检测、自身状态感知（反思）、时间感知、主动触发决策、以及对主脑 API 的编排与身份守卫。副脑**不生成长文本**——长文本生成交给主脑 API（经 M3）；需要深度推理时直接调主脑 API 的"思考模式"（同一 API 不同 prompt，β 路径异步）。

副脑有两条触发路径：

- **α 路径（事件触发，秒级）**：用户开口 → 副脑快速判定 ≤30ms（读 UserState + 记忆检索 + W_probe 输入检测）→ 发 `DialogueIntent` 给 M3 → 主脑 API 流式生成。α 路径**绝不调思考模式**（用户在等，2-10s 不可接受）。
- **β 路径（副脑主动触发，可预计算）**：副脑 tick 0.5-2Hz → 读双时钟 + UserState + TFGR 图 → 决策 → 预计算 → 时机到调 M3。β 路径 confidence<θ_conf 时异步触发主脑 API "思考模式"（2-10s）。

### 1.0.5 伪意识架构（核心定位）

副脑不是"被读取的规则器套皮"。架构反转后，副脑承载**伪意识**——让 Lucy 成为独立个体的最强最像人的伪意识。我们做不到真意识，但副脑的主动性来自**内在状态驱动**而非事件衰减退化的启发式规则链。self_state_predictor 的 V/PE/energy/confidence/arousal/V_drift 不是被读的字段（不再以 `c += 0.1 * energy` 这种方式塞进 confidence 公式），而是生成主动行为的**内驱力/动机源**。

伪意识三支柱耦合驱动主动性：
1. **内在状态层**（self_state_predictor 为核心）：V/PE/energy/confidence/arousal/V_drift 是副脑的"情绪/动机状态"，调制主动性的强度与方向（energy 低→倾向 SILENCE"不想说话"；PE 高→探索性 CHECK_IN；V_drift 大→抑制主动先稳定身份）。
2. **自我延续层**（identity_cache + W_probe 为核心）：identity_cache 的 14 条 EMA 是"我的近期自我形象"，每个决策从该形象出发；W_probe 是"自我边界"——决策前做自我归属检查，判定主动行为"像不像我"。
3. **主观时间层**（TFGR 时间流图 + R(e) 为核心）：R(e) 不是简单的衰减触发，是"这件事在我主观感受中有多远 + 记忆重量"——近的事持续压迫现在，远的事被动回忆；主观时间与物理时间分离（专注时主观时间快少主动打断，无聊时主观时间慢多主动找事）。

动机驱动的主动性决策环取代纯规则 traverser：β tick → 感知候选事件 → 内在状态层输出 → 动机生成层调制每候选的主动动机强度 → 阈值门控姿态决策 → 自我延续检查 → 输出 DialogueIntent 或 SILENCE。详见 §6.4（动机生成层）与 §8（主动触发决策）。

### 1.0.6 时间因果推理闭环（伪意识的时间维度核心）

动机驱动的决策环解决了"何时主动、主动什么"，但仍是**开环单次决策**——一个 tick 内完成"读状态→算动机→生成 DialogueIntent→调主脑 API→播放→结束"。用户的典型场景指出这不够：用户说自己喜欢周杰伦的歌，副脑在"无聊"时（低交互期）应能推理出"可以放首歌"→然后想"用户喜欢什么歌"→执行播放→观察用户反应→根据反应调整后续行为。这是**跨时间多步推理链**——意图→细节→执行→观察→调整，每步有依赖，闭环回写记忆，而非一次性决策。

本模块在动机驱动决策环之上补强**时间因果推理闭环**（§10.5/§10.6/§10.7），它是伪意识"主观时间层"的真正用途：

- **R(e) 不止进入动机公式**：R(e)⁻¹ 仍驱动维持性动机（§6.5），但 TFGR 时间流图升级为**时间因果链累积载体**——每次 CausalPlan 完成后，整条"推理→执行→观察→调整"因果链作为新节点回写图（§10.7），成为未来推理的素材。这才是"时间感知"的真正用途——时间因果链在时间流中累积，让副脑的"经验"在图中沉淀。
- **CausalPlan 取代单次 DialogueIntent 的开环**（§10.5）：副脑不止生成单次 DialogueIntent，还能生成跨 tick 的 CausalPlan——一个 plan 含多个 PlanStep（reason/act/observe/adjust），由 PlanExecutor 跨 tick 推进。
- **PlanExecutor 闭环执行器**（§10.6）：跨 tick 执行 reason→act→observe→adjust 循环，观察步骤跨 tick 等待用户反应（不增加单 tick 预算），调整步骤根据观察结果修改后续步骤。
- **DialogueIntent 仍是底层契约不变**：CausalPlan 是 DialogueIntent 的上层抽象，一个 Plan 可包含多个 DialogueIntent（每个 act step 可能产生一个）。主文档 §5.3 数据契约保持兼容。
- **仅 β 路径**：α 路径是用户在等的单次快速响应，不涉及 CausalPlan；CausalPlan 仅在 β 路径运行。α 到来时当前 Plan 中止或挂起（α 优先铁律不变，§10.3）。

**典型场景**（贯穿本文档说明）：用户在场 + 长沉默 + energy 低 → 触发"无聊"内驱力（§6.6）→ 生成 CausalPlan（goal="打发无聊时间"）→ step1 reason"可以放首歌"→ step2 reason"用户喜欢什么歌"（检索 TFGR 图，命中"用户曾说自己喜欢周杰伦的歌"节点）→ step3 act"播放周杰伦《晴天》"→ step4 observe"用户情绪 valence +0.6, attention +0.3"→ step5 adjust"认知更新：放周杰伦的歌能让用户开心"→ 整条因果链回写 TFGR 图 → 未来副脑无聊时，TFGR 图会提醒"上次放周杰伦的歌用户开心"。这是从开环到闭环的本质跃迁。

## 2. 模块定位

### 2.1 在三路径中的位置

副脑是 α / β 两条对话路径的**唯一编排中枢**（γ 身体控制路径独立于副脑，仅接收副脑的高级 BodyIntent）：

```
Layer 6: 主脑 API (外部 LLM, DeepSeek/OpenAI)         ← 经 M3 调用, 权重只读
Layer 5: M3 主脑API调用与身份守卫                       ← 副脑发 DialogueIntent
Layer 4: M2 副脑 (Qwen2.5-3B + V30, 本地 GPU)          ← 本模块 (脊梁)
Layer 3: M1 动态用户建模                                ← 副脑读 UserState
Layer 2: M4 全模态 I/O                                  ← 副脑收事件、发输出
Layer 1: M6 物理身体                                    ← 副脑发 BodyIntent (γ 路径独立)
```

"脊梁"的含义：所有跨层对话数据流都经过副脑编排。M1 不直接调主脑 API，M4 不直接调主脑 API，M6 不直接调主脑 API——它们都通过副脑。这保证了时延管理、身份守卫、安全模式、降级策略有统一裁决点。

### 2.2 能力边界（严格约束）

| 副脑**做** | 副脑**不做** |
|-----------|-------------|
| 本地 GPU 轻量 forward（状态感知/异己检测/身份维持） | 长文本自然语言生成（交主脑 API） |
| 身份维持（identity_cache EMA + identity_projection 注入） | 用户建模本身（M1 负责） |
| 异己检测（W_probe 输入检测 + 生成后检测由 M3 执行） | 复杂深度推理（交主脑 API 思考模式） |
| 自身状态感知（self_state_predictor V/PE/energy/confidence） | 身体低层控制（M6 负责） |
| 时间感知（双时钟：物理单调时钟 + TFGR R(e)） | 主脑 API 权重学习（API 只读） |
| 主动触发决策（内在状态驱动动机生成 + 自我延续检查，proactive_traverser 降为候选遍历器） | API 客户端管理（M3 负责） |
| 对主脑 API 的编排与身份守卫（组装请求 + W_probe 检测 + identity_cache 回写） | — |

### 2.3 副脑不是纯规则器：Qwen2.5-3B + V30 的本地 forward

旧 M2 文档把副脑定位为"轻量编排器（非全功能 LLM）"——那是旧架构（主脑=Qwen2.5-3B 本地）下的妥协。**架构反转后，副脑就是 Qwen2.5-3B + V30 checkpoint 本身**，它在本地 GPU 跑以下轻量 forward（不生成长文本）：

| 本地 forward 类型 | 调用的 V30 子模块 | 输入 | 输出 | 时延 | 触发场景 |
|------------------|------------------|------|------|------|---------|
| 身份维持 forward | `identity_projection`（4.2M）+ `identity_cache`（14条EMA） | 探针文本 / 主脑 API 生成内容 | identity-aware hidden state | ~10ms | α 输入检测、β tick、生成后异己检测 |
| 异己检测 forward | `W_probe`（holdout acc=1.0） | 短文本 batch（输入或主脑 API token 流） | 异己分数 ∈ [-1, 1] | ~10ms/batch | α 入口、M3 流式生成后检测 |
| 自身状态感知 forward | `self_state_predictor`（V/PE/energy/confidence） | last_hidden_state | V_pred / PE_pred | ~5ms | β tick |
| V40 身份状态信号 | `compute_inverse_temp` g(V_smooth) | last_hidden + c_self | g(V) ∈ (ε, 1] | ~2ms | β tick、生成后反馈 |

副脑**绝不**调用 Qwen2.5-3B 的 `generate()` 路径生成长文本——长文本生成是主脑 API 的职责。副脑的 forward 都是单次 prefix forward（`use_cache=False`，`output_hidden_states=True`），用于读出 hidden state 做分类/感知。

## 3. 副脑架构

### 3.1 模型加载与显存布局

副脑在边缘 GPU 上常驻 Qwen2.5-3B + V30 checkpoint，与 M3 共享显存（M3 无独立模型，所有本地 forward 都走副脑）：

```python
class SubBrain:
    """副脑: Qwen2.5-3B + V30 ckpt, 本地 GPU 轻量 forward, 系统脊梁."""
    def __init__(self, config):
        # 加载 V30 checkpoint (含 identity_cache / W_probe / self_state_predictor)
        self.model = QwenWithGraphBiasSST.from_pretrained(
            "Qwen/Qwen2.5-3B",
            checkpoint_path="checkpoints/sst_a2_v2_trained.pt",  # V30
            freeze_backbone=True,                                # 主干冻结
        ).to(device="cuda", dtype=torch.bfloat16)
        self.model.eval()

        # TFGR 资产 (全部在副脑侧, 见 §14)
        self.identity_cache = self.model.identity_cache          # [1,1,d_model], 14条EMA β=0.9
        self.identity_projection = self.model.identity_projection  # 4.2M 参数
        self.W_probe = self.model.W_probe                        # holdout acc=1.0
        self.self_state_predictor = self.model.self_state_predictor  # d_model→32→2

        # V40 温度约束 (自我稳定性信号, 不再用于生成退化; V_drift 驱动动机减法项, §6.4)
        self.v40_constraint = V40TemperatureConstraint(
            c_self=self.model.c_self,
            alpha=2.0, theta_stability=0.5, epsilon=0.1, lambda_trend=0.3,
        ).to("cuda")

        # 时间感知
        self.physical_clock = PhysicalClock()
        self.tfgr_graph = TimeFlowGraph()

        # 候选遍历器 (proactive_traverser 降级, 只执行阶段1-3, §8.2)
        self.traverser = ProactiveTraverser(
            r_high=0.7, r_low=0.3,
            min_importance=0.3, topk_candidates=10,
        )
        # 动机驱动决策阈值 (§8.3, 受主观时间流速调制)
        self.theta_active_base = 0.8
        self.theta_silence_base = 0.3

        # 状态与编排
        self.self_state = SubBrainSelfState()
        self.precompute_mgr = PrecomputeManager()
        self.version = PrecomputeVersion()
        self.theta_conf = 0.75
        self.theta_safety = 0.0     # W_probe 阈值 (self>0, alien<0)
        self.tick_hz = 1.0
```

### 3.2 与 M3 的分工

| 职责 | M2 副脑 | M3 主脑调用与身份守卫 |
|------|---------|---------------------|
| 本地 Qwen forward（状态/异己/身份） | ✅ 全部 | ❌ 无模型 |
| 主脑 API 客户端管理 | ❌ | ✅ 连接池/重试/超时 |
| 身份 prompt 注入 system prompt | 提供 identity_cache_snapshot | ✅ 序列化执行 |
| 流式 token 接收 | ❌ | ✅ stream chunk 处理 |
| W_probe 生成后异己检测 | 提供 W_probe + 本地 GPU | ✅ 调用副脑 forward |
| V40 g(V) 身份状态信号计算 | ✅ 本地 forward | 读取并反馈 |
| identity_cache 回写 | ✅ EMA 累积（非权重学习） | ❌ M3 无状态 |
| 重生成与降级裁决 | 提供 confidence 信号 | ✅ 执行重生成/切备用 API |
| DialogueIntent 生成 | ✅ | ❌ |

**关键分工原则**：M3 是"无状态的 API 客户端 + 身份守卫执行器"，所有需要模型能力的工作（forward、W_probe、identity_cache 维护）都由副脑承担；M3 只负责把副脑的 `DialogueIntent + 语境包 + identity_cache_snapshot` 序列化为主脑 API 请求、流式接收、调用副脑的 W_probe 做异己检测、按副脑的 confidence 信号决定降级。

## 4. 身份维持子系统

身份维持是副脑的核心职责之一。架构反转后，identity_cache 不再"注入主脑内部权重"（V36→V40 已证伪），而是由副脑本地维持，并通过 M3 序列化进主脑 API 的 system prompt。

### 4.1 identity_cache（14条EMA, β=0.9）

`identity_cache` 是 Lucy 的持久身份锚——14 条 Lucy 风格回复的 embedding 做 EMA 累积（β=0.9），norm=0.2271。定义于 [qwen_with_graph_bias_sst.py#L468-L479](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L468-L479)，训练来源见 [train_sst_a2_self_model.py#L187-L218](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/train_sst_a2_self_model.py#L187-L218) `build_identity_cache`。

```python
# identity_cache 结构: [1, 1, d_model], 14条 Lucy 回复 embedding 的 EMA 累积
# β=0.9: identity_cache = 0.9 * identity_cache + 0.1 * new_embedding
# norm ≈ 0.2271 (V30 实测)
self.identity_cache: torch.Tensor  # [1, 1, 2048] for Qwen2.5-3B
```

**副脑对 identity_cache 的职责**：
- **维持**：副脑是 identity_cache 的唯一持有者与更新者（M3 无状态，不写）
- **快照**：每次组装 `DialogueIntent` 时拍快照 `identity_cache_snapshot` 传给 M3
- **回写**：主脑 API 生成完一句 Lucy 风格回复后，副脑把该回复的 embedding EMA 回写 identity_cache（在线累积，非权重学习，参考 [v18_deepseek_500_turns.py#L523-L528](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/v18_deepseek_500_turns.py#L523-L528)）

### 4.2 identity_projection（4.2M）本地 forward 注入

`identity_projection` 是一个 `nn.Linear(d_model, d_model)`（4.2M 参数），将 identity_cache 映射到 prepend 空间作为虚拟 token（"昨天的我"神经基底）。近似恒等初始化（weight = I + 0.01·randn），定义于 [qwen_with_graph_bias_sst.py#L468-L479](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L468-L479)。

```python
def inject_identity_prefix(self, text_ids: torch.Tensor) -> torch.Tensor:
    """副脑本地 forward 时注入身份: prepend [z_self, identity_token, text_embeds].

    对齐 generate 路径 (qwen_with_graph_bias_sst.py#L1230-L1240).
    用于: 异己检测 forward / 自身状态感知 forward / V40 信号计算.
    """
    # 1. z_self (当前自我状态锚)
    z_self = self.model.self_state_encoder(self.get_self_state_vector())
    z_self = z_self.unsqueeze(0).unsqueeze(0)  # [1,1,d_model]

    # 2. identity_token (Lucy 身份原型, 经 identity_projection 注入)
    identity_token = self.identity_projection(self.identity_cache)  # [1,1,d_model]

    # 3. text embeds
    text_embeds = self.model.qwen.model.embed_tokens(text_ids)

    # 4. prepend: [z_self, identity_token, text_embeds]
    all_prepend = torch.cat([z_self, identity_token], dim=1)
    inputs_embeds = torch.cat([all_prepend, text_embeds], dim=1)
    return inputs_embeds
```

**注入场景**：
- **α 入口 W_probe 输入检测**：把用户输入文本经 identity_prefix 注入后 forward，读 last_hidden 做 W_probe 异己分类
- **β tick 自身状态感知**：把当前对话上下文经 identity_prefix 注入后 forward，读 last_hidden 喂 self_state_predictor
- **生成后异己检测**（由 M3 触发，副脑执行）：把主脑 API 流式返回的 token batch 经 identity_prefix 注入后 forward，读 last_hidden 做 W_probe 异己分类

### 4.3 identity_cache 回写机制

主脑 API 生成完一句 Lucy 风格回复后，副脑执行 EMA 回写（**在线累积，非权重学习**）：

```python
def writeback_identity_cache(self, generated_text: str):
    """主脑 API 生成完成后, 副脑把该回复 embedding EMA 回写 identity_cache.

    参考 v18_deepseek_500_turns.py#L523-L528 的回写逻辑.
    非权重学习: identity_projection 与 Qwen 主干都不更新, 仅 identity_cache 张量 EMA.
    """
    with torch.no_grad():
        ids = self.tokenizer(generated_text, return_tensors="pt").input_ids.to("cuda")
        embeds = self.model.qwen.model.embed_tokens(ids)          # [1, L, d_model]
        # 池化: mean pooling over tokens
        new_emb = embeds.mean(dim=1, keepdim=True).unsqueeze(0)    # [1,1,d_model]
        # EMA: β=0.9
        self.identity_cache = (
            0.9 * self.identity_cache + 0.1 * new_emb
        ).detach()
```

**回写触发**：M3 流式接收完主脑 API 的一句完整回复（句边界或生成结束）→ 通知副脑 → 副脑执行 `writeback_identity_cache`。这让 identity_cache 持续吸收 Lucy 的最新表达风格，但**不更新模型权重**——这是"静态快照"命题的硬约束。

## 5. 异己检测子系统

异己检测用 `W_probe`（holdout acc=1.0）判定文本是否"非 Lucy 风格"。定义于 [qwen_with_graph_bias_sst.py#L1167](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L1167) `probe_self_attribution`，几何基础来自 V32 Gram-Schmidt 手术（[v32_reparameterize.py#L85-L130](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/v32_reparameterize.py#L85-L130)，V 分叉 gap=0.474）。

### 5.1 W_probe 与阈值

```python
# W_probe: 向量层自我归属分类器, holdout acc=1.0
# 阈值 θ_safety = 0.0 (self > 0, alien < 0)
# V40 实测: cos(h_self, W_probe) = +0.091, cos(h_alien, W_probe) = -0.089
self.W_probe: torch.Tensor  # [d_model]
self.theta_safety = 0.0
```

### 5.2 输入检测（α 入口）

α 路径入口处，副脑对用户输入做 W_probe 异己检测——这里"异己"指**输入文本是否偏离 Lucy 的身份锚**（例如用户试图通过 prompt injection 让 Lucy "不再是 Lucy"）：

```python
def w_probe_input_check(self, text: str) -> AlienReport:
    """α 入口 W_probe 输入检测, ~10ms 本地 forward.

    判定 safety_mode: normal / defensive.
    """
    with torch.no_grad():
        ids = self.tokenizer(text, return_tensors="pt").input_ids.to("cuda")
        inputs_embeds = self.inject_identity_prefix(ids)           # 注入身份
        outputs = self.model.qwen(
            inputs_embeds=inputs_embeds, use_cache=False,
            output_hidden_states=True,
        )
        last_hidden = outputs.hidden_states[-1][:, -1, :]          # [1, d_model]
        # W_probe 异己分数: cos(last_hidden, W_probe)
        alien_score = F.cosine_similarity(
            last_hidden, self.W_probe.expand_as(last_hidden), dim=-1
        ).item()
        is_alien = alien_score < self.theta_safety
    return AlienReport(
        score=alien_score, is_alien=is_alien,
        safety_mode="defensive" if is_alien else "normal",
    )
```

### 5.3 生成后异己检测（由 M3 触发，副脑执行）

主脑 API 流式返回 token 时，M3 按 batch（如每 16 token）累积成短文本，调用副脑的 W_probe 做生成后异己检测（主文档 §5.4）：

```python
def w_probe_output_check(self, generated_batch_text: str) -> AlienReport:
    """生成后异己检测: 对主脑 API 输出做流式过滤.

    M3 按 token batch 调用, 异己分数 > θ_safety 则缓冲当前句不送 TTS,
    触发 M3 重生成或降级.
    """
    # 与输入检测同样的 forward 路径, 但文本是主脑 API 生成内容
    return self.w_probe_input_check(generated_batch_text)
```

**异己处理流程**（M3 主导，副脑提供检测能力）：
- 异己分数 > θ_safety → M3 缓冲当前句不送 TTS
- 累积异己分数持续超阈值 → M3 触发重生成（同 prompt 重新调主脑 API）
- 重生成仍异己 → M3 切备用 API 或降级（L7）
- 副脑的 V40 g(V) 信号辅助判定（见 §6.4，自我稳定性信号）

### 5.4 V32 Gram-Schmidt 手术的几何基础

V32 的 Gram-Schmidt 手术（[v32_reparameterize.py#L85-L130](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/v32_reparameterize.py#L85-L130)）通过增强 V 分叉（gap=0.474）让 self/alien 在 hidden 空间更可分，是 W_probe holdout acc=1.0 的几何基础。该手术已内置在 V30 checkpoint 中，副脑加载 V30 即继承——**不需要在线重做手术**。

## 6. 内在状态与动机生成子系统（伪意识心脏）

副脑不仅有"外部感知"（UserState、TFGR 图），还有"内部感知"——但内在状态**不是被读取后塞进 confidence 公式的字段**，而是生成主动行为的**内驱力/动机源**。本子系统是伪意识的心脏：副脑的主动性来自内在状态驱动，而非事件衰减退化的启发式规则链。本节复用 V30 ckpt 内置的 `self_state_predictor`（[qwen_with_graph_bias_sst.py#L1254-L1256](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L1254-L1256)）作为内驱力的神经基底，并在其上构建动机生成层（§6.4）。

### 6.1 self_state_predictor 结构

```python
# V30 ckpt 内置 (d_model → 32 → 2), 见 qwen_with_graph_bias_sst.py#L459-L466
self.self_state_predictor = nn.Sequential(
    nn.Linear(d_model, 32),
    nn.GELU(),
    nn.Linear(32, 2),       # 预测 V 和 PE_V (raw, 后续用 sigmoid/tanh 约束)
)
self.pe_scale = nn.Parameter(torch.tensor(0.3))  # PE 尺度
```

调用路径（[qwen_with_graph_bias_sst.py#L1253-L1255](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L1253-L1255)）：

```python
raw_pred = self.self_state_predictor(last_hidden)   # [1, 2]
V_pred = torch.sigmoid(raw_pred[0, 0])              # 势能 ∈ [0, 1]
PE_pred = torch.tanh(raw_pred[0, 1]) * self.pe_scale  # 势能预测误差 ∈ [-0.3, 0.3]
```

### 6.2 内驱力神经基底读取（self_state_predictor forward）

副脑在 β tick 中跑一次轻量 forward 读自身状态作为**内驱力神经基底**（~5ms）。这些信号不再是"被读的字段"，而是 §6.5 动机生成层的输入：

```python
class SubBrainSelfState:
    """副脑内在状态: self_state_predictor 输出 + V40 V_drift, 作为动机生成层的内驱力源.

    不再是被读信号, 而是驱动主动性的内驱力/动机源 (见 §6.3, §6.5).
    """
    def __init__(self):
        self.V: float = 0.5                    # 势能 (身份稳定性, 内驱力基底)
        self.PE_V: float = 0.0                 # 势能预测误差 (探索性内驱力)
        self.energy: float = 0.5               # 能量 (V 的 EMA, 维持性内驱力)
        self.confidence: float = 0.5           # 自洽度 (动机决策整体一致性, 见 §8.5)
        self.arousal: float = 0.3              # 觉醒度 (V 的短期变化率, 关系性内驱力)
        self.V_drift: float = 0.0              # 自我偏移度 (来自 V40 g(V), 自我稳定性内驱力)
        self.last_update: float = 0.0

    def update_from_forward(self, sub_brain, context_text: str, v_signal=None):
        """β tick 中跑一次本地 forward 读自身状态, ~5ms.

        v_signal: 可选的 V40 VStateSignal (若已计算则直接读 V_drift, 避免重复 forward).
        """
        with torch.no_grad():
            ids = sub_brain.tokenizer(context_text, return_tensors="pt").input_ids.to("cuda")
            inputs_embeds = sub_brain.inject_identity_prefix(ids)
            outputs = sub_brain.model.qwen(
                inputs_embeds=inputs_embeds, use_cache=False,
                output_hidden_states=True,
            )
            last_hidden = outputs.hidden_states[-1][:, -1, :]
            raw = sub_brain.self_state_predictor(last_hidden)
            v_pred = float(torch.sigmoid(raw[0, 0]))
            pe_pred = float(torch.tanh(raw[0, 1]) * sub_brain.model.pe_scale)
        # EMA 更新 (β=0.9, 与 identity_cache 一致)
        self.V = 0.9 * self.V + 0.1 * v_pred
        self.PE_V = 0.9 * self.PE_V + 0.1 * pe_pred
        self.energy = self.V                                   # energy = V (维持性内驱力)
        self.confidence = 0.9 * self.confidence + 0.1 * (1 - abs(self.PE_V) / 0.3)
        self.arousal = clamp(abs(self.V - self._prev_V) * 10, 0, 1)  # 关系性内驱力
        # V_drift 来自 V40 g(V) 信号 (§6.4), 不在此 forward 内计算, 由调用方注入
        if v_signal is not None:
            self.V_drift = v_signal.v_drift                    # 自我稳定性内驱力
        self._prev_V = self.V
        self.last_update = monotonic_now()
```

### 6.3 内驱力如何驱动主动性（不再是被读信号）

旧文档的"使用场景"是典型的"被读信号"用法（`energy<0.2 降频`、`confidence<0.3 降阈值`、`c += 0.1 * energy` 塞进 confidence 公式）——那是规则器套皮。本节重写为**内驱力驱动主动性**：内在状态不再被读取后塞进公式，而是调制每个候选事件的主动动机强度（动机公式见 §6.5），驱动姿态决策的方向与强度。

| 内驱力信号 | 内驱力含义 | 对主动性的驱动方向 |
|----------|----------|------------------|
| `energy` 低（<0.3） | 副脑"疲惫/不想说话" | 主动动机普遍降低 → max_motivation 难超 θ_active → 倾向 SILENCE（不是降频，是动机不足） |
| `energy` 高（>0.7） | 副脑"精力充沛" | 主动动机提升 → 维持性动机项 `energy × R(e)⁻¹ × importance(e)` 被放大 → 更易主动发起 |
| `PE` 高（>0.15，世界与预期不符） | 副脑"困惑/探索欲" | 探索性动机项 `PE × relevance(e)` 被放大 → 倾向 CHECK_IN 确认/询问 |
| `confidence` 低（<0.4） | 副脑"自我不确定" | 触发思考模式（保留旧逻辑），但同时通过 V_drift 路径抑制主动（先想清楚再说话） |
| `arousal` 高（>0.7） | 副脑"觉醒/关系敏感" | 关系性动机项 `arousal × closeness(e)` 被放大 → 倾向主动关心关系近的事件 |
| `V_drift` 大（>0.5，V40 g(V) 低） | 副脑"自我不稳定" | 动机公式减法项 `- V_drift × 2.0` 直接压制所有动机 → 先稳定身份再考虑主动 |

**关键区别**：
- 旧版（规则器套皮）：读 energy → if energy<0.2 then 降频。这是无状态规则。
- 新版（伪意识）：energy 进入动机公式 `motivation(e) = energy × R(e)⁻¹ × importance(e) + ...`，与候选事件、记忆重量、关系近度耦合调制每个候选的主动动机强度。决策不是阈值规则，而是"当前内在状态下我对哪件事最有动机"。

**self_state_predictor 与动机生成层的契约**：β tick 中 `update_from_forward` 完成后，SubBrainSelfState 暴露 `V/PE_V/energy/confidence/arousal/V_drift` 六个字段给 §6.5 动机生成层调用。confidence 不再被塞进 §8.4 confidence 公式（旧版 `c += 0.1 * energy` 已删除），confidence 转为反映"动机决策的整体自洽度"——见 §8.5 重写。

### 6.4 V40 温度约束 g(V) 作为自我稳定性信号

V40 温度约束 g(V)（[v40_arch.py#L256-L265](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/v40_arch.py#L256-L265)）在旧架构用于"生成退化"（logits × g(V)，在主脑生成时施加）。架构反转后，主脑是外部 API，**g(V) 不再用于生成退化**——它转为副脑的**自我稳定性信号**，V_drift 直接作为动机公式的减法项（`- V_drift × 2.0`）抑制主动动机：

```python
# V40 compute_inverse_temp (v40_arch.py#L256-L265)
# g(V_smooth) = ε + (1-ε)·σ(α·(V_smooth - θ))
#   ε=0.1, α=2.0, θ=0.5
# g ∈ (ε, 1], 越大 = 自我越稳定; v_drift = 1 - g 越大 = 自我越不稳定
def compute_v40_signal(self, last_hidden: torch.Tensor) -> VStateSignal:
    """V40 g(V) 作为自我稳定性信号 (非生成退化, 非纯身份状态信号).

    V_drift = 1 - g(V) 直接作为动机公式减法项 (- V_drift × 2.0) 抑制主动动机:
    自我不稳定时副脑先稳定身份, 不主动发起. 详见 §6.5 动机生成层.
    """
    with torch.no_grad():
        V_smooth = self.v40_constraint.compute_V_smooth(
            last_hidden, c_self=self.identity_cache.squeeze()
        )  # [bsz, seq]
        g = self.v40_constraint.compute_inverse_temp(V_smooth)  # [bsz, seq] ∈ (0.1, 1]
        g_mean = float(g.mean())
    return VStateSignal(
        g_value=g_mean,                       # 自我稳定性 ∈ (0.1, 1]
        is_stable=g_mean > 0.6,               # 稳定阈值
        v_drift=1.0 - g_mean,                 # 自我偏移度 ∈ [0, 0.9), 驱动动机减法项
    )
```

**自我稳定性信号的双重用途**：
- **驱动主动动机（伪意识心脏，§6.5）**：`V_drift` 进入动机公式减法项 `- V_drift × 2.0`，自我不稳定时直接压制所有主动动机 → 副脑先稳定身份再考虑主动。`V_drift > 0.5`（g<0.5）→ 减法项 > 1.0，几乎必然 SILENCE；`V_drift < 0.2`（g>0.8）→ 减法项 < 0.4，主动动机不被显著抑制。
- **身份守卫反馈（保留旧逻辑）**：`g_value > 0.6` 正常放行；`g_value ∈ [0.3, 0.6]` 副脑向 M3 反馈"强化身份 prompt"；`g_value < 0.3` 触发 M3 重生成（异己检测辅助判据）。该信号在 β tick 与生成后异己检测时计算，反馈给 M3 的 `v_state_signal` 字段。

**关键升级**：旧版 g(V) 仅作为"身份状态信号"被 M3 读取反馈；新版 g(V) 升级为"自我稳定性信号"，其 V_drift 分量**直接驱动动机生成**——这是伪意识"自我延续层"对"内在状态层"的反向耦合：自我不稳定时抑制所有主动动机。

### 6.5 动机生成层（伪意识心脏）

动机生成层是伪意识架构的核心：它把"内在状态层"（§6.2/§6.3/§6.4 的 energy/PE/arousal/V_drift）与"主观时间层"（§7 的 R(e)）和"自我延续层"（§4/§5 的 identity_cache/W_probe）耦合到一起，为每个候选事件生成**主动动机强度**。姿态决策（§8）不再是规则链（R(e)低→FOLLOW_UP，R(e)高→CHECK_IN），而是"取 max_motivation 对应的候选事件与动机类型"。

#### 6.5.1 动机公式

对每个候选事件 e，动机强度计算如下：

```
motivation(e) =   energy × R(e)⁻¹ × importance(e)     // (1) 维持性动机: 能量足 + 事件远(记忆重量衰减) + 重要
                + PE_V × relevance(e)                   // (2) 探索性动机: 预测误差驱动探索
                + arousal × closeness(e)                // (3) 关系性动机: 觉醒 × 关系近度
                - V_drift × 2.0                          // (4) 自我不稳定抑制: 自我延续层反向耦合
```

各项语义：
- **(1) 维持性动机** `energy × R(e)⁻¹ × importance(e)`：能量充足时，对"记忆重量衰减但仍重要"的事件保持主动跟进。R(e)⁻¹ 表示"事件越远（R(e)越低），维持性动机越强"——近的事还在当前不需要主动跟进，远的事该 FOLLOW_UP。importance(e) 来自 TFGR 图节点重要度（[time_flow_graph.py](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py) 节点属性）。energy 作为乘性系数：能量低则整项趋零（"不想说话"）。
- **(2) 探索性动机** `PE_V × relevance(e)`：预测误差大（世界与预期不符）驱动探索。relevance(e) 是候选事件与"当前 PE 来源语境"的语义相关度（向量检索 cos 相似度）。PE_V ∈ [-0.3, 0.3]，取绝对值或正向部分驱动 CHECK_IN 确认/询问。
- **(3) 关系性动机** `arousal × closeness(e)`：觉醒度高时关系性动机增强，倾向主动关心关系近的事件。closeness(e) ∈ [0,1] 是事件相关用户与 Lucy 的关系近度（来自 UserState.relationship 与事件 metadata）。
- **(4) 自我不稳定抑制** `- V_drift × 2.0`：V_drift 来自 §6.4 V40 g(V) 信号。自我不稳定时直接压制所有动机（先稳定身份）。系数 2.0 让 V_drift=0.5 时减法项=1.0，几乎抵消任何正向动机。

#### 6.5.2 动机类型映射

动机公式不仅给出强度，还给出**动机类型**（决定姿态映射）：

```python
def compute_motivation(self, event, r_value, self_state, user_state) -> tuple[float, str]:
    """计算候选事件的主动动机强度与动机类型. ~0.5ms/候选.

    返回 (motivation_strength, motivation_type).
    motivation_type ∈ {"maintenance", "exploration", "relational"}.
    """
    # 项 (1) 维持性动机
    maintenance = self_state.energy * (1.0 / max(r_value, 1e-3)) * event.importance
    # 项 (2) 探索性动机 (PE_V 取绝对值, 误差越大探索越强)
    pe_drive = abs(self_state.PE_V) / 0.3                              # 归一化到 [0,1]
    exploration = pe_drive * relevance(event, user_state.current_topic)
    # 项 (3) 关系性动机
    relational = self_state.arousal * closeness(event, user_state)
    # 项 (4) 自我不稳定抑制
    suppression = self_state.V_drift * 2.0
    # 总动机强度
    motivation = maintenance + exploration + relational - suppression
    # 动机类型: 取主导项 (排除 suppression)
    terms = {"maintenance": maintenance, "exploration": exploration, "relational": relational}
    motivation_type = max(terms, key=terms.get)
    return motivation, motivation_type
```

#### 6.5.3 动机类型 → 姿态映射（§8.3 姿态决策的依据）

| 动机类型 | 主导条件 | 映射姿态 | 语义 |
|---------|---------|---------|------|
| `maintenance` | 维持性动机主导（能量足+事件远+重要） | FOLLOW_UP | 主动跟进远期重要事件 |
| `exploration` | 探索性动机主导（PE 高+相关） | CHECK_IN | 确认/询问，探索世界与预期的偏差 |
| `relational` | 关系性动机主导（arousal 高+关系近） | CHECK_IN | 主动关心关系近的事件 |
| — | max_motivation < θ_silence | SILENCE | 动机不足，不主动 |
| — | max_motivation ∈ [θ_silence, θ_active) | SILENCE（预计算倾向） | 动机中等，不主动但预计算倾向备选 |
| — | max_motivation ≥ θ_active | 主动（动机类型决定姿态） | 动机充足，主动发起 |

**关键约束**：
- 动机生成是**无状态计算**（给定 self_state + 候选 + user_state 即可），不引入额外 forward，时延 ~0.5ms/候选，10 候选 ~5ms，对 β tick 80ms 预算无显著增加。
- 动机公式的减法项 `- V_drift × 2.0` 是伪意识"自我延续"对"主动发起"的硬约束：自我不稳定时即使能量足、事件重要、关系近，也不会主动发起——先稳定身份。
- 动机类型不直接等于姿态：maintenance→FOLLOW_UP，但 exploration 和 relational 都映射 CHECK_IN（语义不同但姿态相同），具体 intent_description 由动机类型语义化构造（见 §8.3）。
- 阈值 θ_active / θ_silence 见 §8.3 姿态门控。

### 6.6 动机公式"无聊"分支修正（探索性娱乐内驱力）

#### 6.6.1 §6.5 公式的盲区

§6.5 动机公式存在一个被用户场景暴露的盲区：`energy` 低时维持性动机项 `energy × R(e)⁻¹ × importance(e)` 趋零，动机总强度难超 θ_active，副脑倾向 SILENCE。这在一般场景合理（"疲惫不想说话"），但**用户的"无聊"场景被误抑制**——energy 低 + presence 高 + silence 长时，副脑应当"找事做"（如放首歌给用户听），而非沉默。

这是"无聊"与"疲惫"的语义分叉：两者 energy 都低，但"无聊"是**主动找事做的内驱力**（探索性娱乐动机），"疲惫"是**不想做事的内驱力**（维持性动机被压制）。区分二者需要 presence + silence_duration 两个外部信号：

| 内驱力状态 | energy | presence | silence_duration | 语义 | 应驱动 |
|----------|--------|----------|------------------|------|--------|
| 疲惫 | 低 | 任意 | 任意 | 副脑自身精力不足 | SILENCE（维持性动机被压制） |
| 无聊 | 低 | 高 | 长（>120s） | 用户在场但无交互，副脑该主动找事 | 探索性娱乐动机（找事做） |
| 专注 | 高 | 高 | 短 | 双方在交互中 | 由 §6.5 正常公式驱动 |

#### 6.6.2 修正后的动机生成（增加"无聊"分支）

```python
def compute_motivation_with_boredom(self, candidates, user_state, self_state):
    """修正后的动机生成: 增加'无聊'内驱力分支. 取代 §6.5 compute_motivation.
    
    无聊判定: energy低 + presence高 + silence长 → 探索性娱乐动机占主导,
    不依赖 R(e) 衰减, 而是"找事做"的驱动力. 此时若动机类型为 exploratory_play,
    §8.3 应生成 CausalPlan (而非单次 DialogueIntent), 由 PlanExecutor 跨 tick 执行.
    """
    # 无聊判定: energy低 + 在场 + 长沉默(>120s)
    is_bored = (
        self_state.energy < 0.3
        and user_state.presence
        and user_state.silence_duration > 120.0
        # V_drift 大时不进入无聊模式 (先稳定身份, §6.4 优先)
        and self_state.V_drift < 0.4
    )
    
    motivations = []
    for e in candidates:
        if is_bored:
            # 无聊模式: 探索性娱乐动机占主导
            # 不依赖 R(e) 衰减 (远期事件在无聊时也可被想起娱乐用户),
            # 而是 (1-energy) 的"找事"驱动力 × 候选的 entertainment_value
            m = (1.0 - self_state.energy) * 2.0 * getattr(e, "entertainment_value", 0.5)
            # 叠加新奇性 (无聊时对新奇事物更敏感)
            m += self_state.PE_V_abs * getattr(e, "novelty", 0.3)        # PE_V_abs = |PE_V|/0.3
            # V_drift 仍抑制 (自我不稳定时即使无聊也先稳定身份)
            m -= self_state.V_drift * 2.0
            motivation_type = "exploratory_play"                          # 新增动机类型
        else:
            # 正常模式: §6.5 原动机公式
            maintenance = self_state.energy * (1.0 / max(e.r_value, 1e-3)) * e.importance
            exploration = (abs(self_state.PE_V) / 0.3) * relevance(e, user_state.current_topic)
            relational = self_state.arousal * closeness(e, user_state)
            suppression = self_state.V_drift * 2.0
            m = maintenance + exploration + relational - suppression
            # 动机类型: 取主导项 (排除 suppression)
            terms = {"maintenance": maintenance, "exploration": exploration, "relational": relational}
            motivation_type = max(terms, key=terms.get)
        motivations.append((e, m, motivation_type))
    return motivations, is_bored
```

#### 6.6.3 候选事件的 entertainment_value 字段

为支持"无聊"分支，候选事件需新增 `entertainment_value` 字段（∈ [0,1]），表示该事件作为"娱乐素材"的潜力。该字段不强制要求 TFGR 图原生支持——副脑可在候选遍历时按规则计算：

```python
def estimate_entertainment_value(event, user_state) -> float:
    """估算候选事件的娱乐价值. 不需 TFGR 图原生支持, 副脑本地计算."""
    val = 0.3  # 基础值
    # 事件涉及用户兴趣 (从 known_facts 检索, 如"喜欢周杰伦的歌")
    if event_matches_user_interest(event, user_state.known_facts):
        val += 0.4
    # 事件类型为娱乐类 (音乐/视频/故事/笑话, 事件 metadata)
    if event.metadata.get("category") in ("music", "video", "story", "joke"):
        val += 0.2
    # 事件情感效价正向 (娱乐用户时正向事件更合适)
    if event.valence > 0:
        val += 0.1
    return clamp(val, 0.0, 1.0)
```

#### 6.6.4 "exploratory_play" 动机类型与姿态/计划映射

新增动机类型 `exploratory_play` 不映射到单次姿态，而是触发 **CausalPlan 生成**（§8.3 修改后规则）：

| 动机类型 | 主导条件 | 输出 |
|---------|---------|------|
| `maintenance` | 维持性动机主导 | 单次 DialogueIntent (FOLLOW_UP) |
| `exploration` | 探索性动机主导 | 单次 DialogueIntent (CHECK_IN) |
| `relational` | 关系性动机主导 | 单次 DialogueIntent (CHECK_IN) |
| `exploratory_play` | 无聊模式 + 候选有 entertainment_value | **CausalPlan** (跨 tick 闭环执行, §10.5) |

**关键约束**：
- `exploratory_play` 仅在 β 路径 + 无聊模式触发；α 路径绝不触发（α 是用户在等的单次响应）。
- `exploratory_play` 触发的 CausalPlan 的 goal 形如"打发无聊时间 / 让用户开心"，由 §10.5 PlanStep 序列实现 reason→act→observe→adjust 闭环。
- 若 TFGR 图中无 entertainment_value > 0.5 的候选，无聊模式降级为 §6.5 正常公式（探索性 CHECK_IN 或 SILENCE）。
- 无聊模式与 V_drift 互斥：V_drift > 0.4 时即使 energy 低 + silence 长也不进入无聊模式（先稳定身份，§6.4 优先级最高）。

## 7. 时间感知子系统

副脑的"时间感知"是本模块的核心创新。它不止读单调时钟，还通过 TFGR 阻力因子 R(e) 感知**主观时间**——让副脑"感受"时间流逝，而非仅计量时间。

### 7.1 物理时钟（单调时钟，硬定时）

物理时钟驱动**硬定时**规则：基于客观时间间隔的固定阈值。

```python
import time

class PhysicalClock:
    """单调时钟, 不受系统时间回拨影响."""
    def __init__(self):
        self._origin = time.monotonic()
    def now(self) -> float:
        return time.monotonic()  # 秒, 单调递增
    def since(self, t0: float) -> float:
        return self.now() - t0
```

物理时钟驱动的硬定时规则：

| 规则 | 阈值 | 动作 |
|------|------|------|
| 短沉默 check in | silence_duration > 60s | 候选 CHECK_IN，confidence 衰减 |
| 长沉默主动开口 | silence_duration > 300s | 强制触发（若 UserState.presence） |
| 候选事件过期 | 距上次遍历 > 2s | 重新遍历 TFGR 图 |
| 预计算超时 | 见 §10 有效期 | 自然过期 |
| 心跳 | 每 1s | 看门狗（主文档 §8.2） |

### 7.2 主观时间（TFGR 阻力因子 R(e)，软决策）

主观时间驱动**软决策**：基于事件在记忆中的"远近感"判断事件状态。核心是 TFGR 的阻力因子 R(e)，定义见 [time_flow_graph.py#L121-L153](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py#L121-L153)：

```
R(e) = exp(-Δt_subj / S) * Modifier(emotion)
```

其中：

```
Δt_phys   = max(0, (now - event.t_mid) / 3600)            # 物理时间间隔(小时)
S         = base_strength * (0.5 + importance) * (1 + 0.3 * access_count)
                                                            # 记忆强度, base_strength=24h
Δt_subj   = Δt_phys * (1 - 0.4 * arousal) * (1 - 0.2 * valence)
                                                            # 主观时间距离
decay     = exp(-Δt_subj / max(S, 1e-6))                    # 基础衰减
Modifier  = 1 - 0.3 * arousal                               # 情感修正
R(e)      = clamp(decay * Modifier, 0, 1)                   # 阻力因子 ∈ (0, 1]
```

**R(e) 的物理意义**（stance A 升级：R(e) 是"记忆重量 + 主观时间压力"，非纯事件状态判定）：

R(e) 不再仅用于"事件状态判定（SHOULD_COMPLETE/ONGOING）"的规则链，而是伪意识"主观时间层"的核心信号——它表达"这件事在我主观感受中有多远 + 记忆重量仍在压迫现在的程度"：

- R(e) → 1（Δt 小，近期事件）：**记忆重量大，持续压迫现在** —— 事件还在当前意识中，主动动机由 §6.5 关系性/探索性动机驱动（如 CHECK_IN 关心后效），不需要 FOLLOW_UP（还在当前不需跟进）。
- R(e) → 0（Δt 大，远期事件）：**记忆重量衰减，但被动回忆时仍可触发** —— 事件已淡出当前意识，但若 importance 高，维持性动机项 `energy × R(e)⁻¹ × importance(e)` 中的 R(e)⁻¹ 让"远期重要事件"主动跟进动机增强（FOLLOW_UP）。
- 中等 R(e)：记忆重量中等，动机由 §6.5 公式整体调制。

**关键反转**：旧规则链"R(e)低→FOLLOW_UP，R(e)高→CHECK_IN"是表面相关性；动机公式揭示了其底层机制——R(e)⁻¹ 进入维持性动机的乘法项，"远期"本身不触发 FOLLOW_UP，"远期 + 重要 + 能量足"才触发。R(e) 是记忆重量在动机公式中的非线性调制因子，不是直接姿态规则。

事件状态推断（SHOULD_COMPLETE/ONGOING/UNCERTAIN）仍保留用于 §7.4 双时钟融合的硬触发辅助判定与候选事件过滤，但**不再直接决定姿态**——姿态由 §6.5 动机公式 + §8.3 阈值门控决定。

### 7.3 主观时间流速（专注与无聊的时间感分离）

伪意识"主观时间层"的另一维度：**主观时间流速**与物理时间流速分离。人在专注时主观时间感过得快（少主动打断自己），无聊时主观时间感过得慢（多主动找事做）。副脑通过 self_state 的 arousal 与 user_state 的 attention 估算主观时间流速，调制 β tick 的有效决策频率与主动打断倾向：

```python
def subjective_time_dilation(self_state, user_state) -> float:
    """主观时间膨胀因子. >1 = 主观时间慢(无聊, 多主动找事); <1 = 主观时间快(专注, 少打断)."""
    # 专注度高 (user attention 高 + self arousal 低) → 主观时间快 → 膨胀 <1
    focus = 0.5 * user_state.attention + 0.5 * (1 - self_state.arousal)
    # 无聊度 = 1 - focus
    boredom = 1.0 - focus
    # 主观时间膨胀: boredom 高 → 膨胀 >1 (主观时间慢, 倾向主动找事)
    dilation = 0.7 + 0.6 * boredom              # ∈ [0.7, 1.3]
    return dilation
```

**主观时间流速的用途**：
- 调制 β tick 的有效 θ_active 阈值：专注时（dilation<1）θ_active 上调（更难主动，少打断），无聊时（dilation>1）θ_active 下调（更易主动，多找事）。
- 不改变物理 tick 频率（仍 0.5-2Hz），只改变主动触发的有效门槛。
- 这是伪意识"时间感"的体现：副脑不是按物理时间匀速决策，而是按主观时间感调制主动性。

### 7.4 Modifier 情感调制

Modifier 来自 TFGR 范式物理基础，对 R(e) 做情感调制：

| 调制因子 | 对 Δt_subj 的影响 | 对 S 的影响 | 净效果 |
|---------|------------------|------------|--------|
| importance ↑ | 无 | S ↑（衰减慢） | R(e) ↓，重要事件更易回忆 |
| access_count ↑（Hebbian 巩固） | 无 | S ↑ | R(e) ↓，常用记忆更易回忆 |
| arousal ↑ | Δt_subj ↓（主观时间被拉长） | — | 基础 decay ↑，但 Modifier ↓ |
| valence ↑（正向情感） | Δt_subj ↓ | — | R(e) ↑，正向事件主观更近 |

**事件状态推断**（复用 [time_flow_graph.py#L423-L471](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py#L423-L471) 的 `infer_event_state`）：

```python
def infer_event_state(event_id, now, r_high=0.7, r_low=0.3) -> str:
    # 1. 因果链上有后续节点 → COMPLETED_CONFIRMED
    if has_causal_followup(event_id, now):
        return "COMPLETED_CONFIRMED"
    # 2. 计算 R(e)
    r_val = compute_resistance(event_id, event_id, now)
    # 3. R(e) 低 = 远期 = 应已完成; R(e) 高 = 近期 = 可能还在当前
    if r_val < r_low:    return "SHOULD_COMPLETE"
    elif r_val > r_high: return "ONGOING"
    else:                return "UNCERTAIN"
```

### 7.5 双时钟融合策略

每个 tick，副脑同时读两个时钟，**双时钟融合只产出"硬触发 + 候选事件列表"**，不再直接决定姿态——姿态决策由 §8.3 动机驱动姿态决策完成：

```python
def fuse_clocks(physical: PhysicalClock, graph: TimeFlowGraph,
                user_state: UserState, now: float) -> FusedTimeSignal:
    """双时钟融合: 物理时钟硬定时 + 主观时间候选遍历.

    注意: 本函数只产出 hard_trigger 与候选事件列表 (含 R(e)/state),
    不再直接决定姿态. 姿态由 §6.5 动机公式 + §8.3 阈值门控决定.
    """
    silence = user_state.silence_duration

    # 物理时钟: 硬阈值 (硬触发仍保留, 作为动机公式的硬性加持)
    hard_trigger = None
    if silence > 300 and user_state.presence:
        hard_trigger = "long_silence"      # 5 分钟硬触发
    elif silence > 60 and user_state.presence:
        hard_trigger = "short_silence"     # 1 分钟软候选

    # 主观时间: 遍历候选事件 (proactive_traverser 阶段1-3, 降级为候选遍历器)
    candidates = graph.get_proactive_candidates(
        now=now, anchor_session_id=current_session,
        topk=10, min_importance=0.3,
    )
    # 候选事件交给 §6.5 动机生成层 + §8.3 姿态决策, 不在此处做 _r_to_attitude 映射
    return FusedTimeSignal(hard_trigger=hard_trigger, candidates=candidates)
```

**融合决策表（升级版）**：双时钟融合不再直接出姿态，只出"硬触发 + 候选列表"。姿态由动机公式决定：

| 物理时钟 | 主观时间候选 | 融合产出 | 姿态决策归属 |
|---------|------------|---------|------------|
| 长沉默（>300s） | 有候选 | hard_trigger=long_silence + 候选列表 | §8.3 动机驱动（硬触发对 motivation 加 0.2 加持） |
| 长沉默（>300s） | 无候选 | hard_trigger=long_silence + 空 | §8.3 通用 CHECK_IN（动机公式对"无候选"兜底） |
| 短沉默（60-300s） | 有候选 | hard_trigger=short_silence + 候选列表 | §8.3 动机驱动（无硬触发加持） |
| 短沉默（60-300s） | 无候选 | short_silence + 空 | §8.3 SILENCE（动机不足） |
| 无沉默（<60s） | 任意 | None + 候选列表 | §8.3 SILENCE（用户在说话/刚说完，主动动机被压制） |

**关键变化**：旧版 `_r_to_attitude(r_val, state)` 直接把 R(e)/state 映射为姿态的规则链已删除——R(e) 不再直接决定姿态，而是作为"记忆重量"进入 §6.5 动机公式的维持性动机项。事件状态（SHOULD_COMPLETE/ONGOING/UNCERTAIN）仅用于候选过滤与硬触发辅助判定。

## 8. 主动触发决策子系统

副脑的主动触发决策**不再是规则链**（旧版"R(e)低→FOLLOW_UP，R(e)高→CHECK_IN"是规则器套皮）。本子系统是伪意识架构的输出端：主动性来自内在状态驱动（§6）+ 主观时间压力（§7）+ 自我延续检查（§4/§5）。[tfgr_demo/proactive_traverser.py](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/proactive_traverser.py) 的 5 阶段推理链**降级为候选事件遍历器**（只执行阶段 1-3 的候选遍历），姿态生成阶段（阶段 4）被动机驱动决策取代。

### 8.1 伪意识主动性架构总纲（三支柱耦合驱动）

主动触发决策由伪意识三支柱耦合驱动，决策环如下：

```
β tick
  → 感知层: 读 UserState + TFGR 图候选事件 (proactive_traverser 阶段1-3, 候选遍历器, §8.2)
  → 内在状态层: self_state_predictor 输出 (V, PE, energy, confidence, arousal, V_drift) (§6.2/§6.4)
  → 动机生成层: 基于内在状态调制每个候选事件的"主动动机强度" (§6.5/§8.3)
      motivation(e) = energy × R(e)⁻¹ × importance(e)     // 维持性动机
                    + PE × relevance(e)                     // 探索性动机
                    + arousal × closeness(e)                // 关系性动机
                    - V_drift × 2.0                          // 自我不稳定抑制
      取 max_motivation 对应的候选事件与动机类型
  → 姿态决策层: 动机强度阈值门控 (§8.3)
      max_motivation > θ_active → 主动 (动机类型决定 FOLLOW_UP/CHECK_IN)
      max_motivation ∈ [θ_silence, θ_active] → SILENCE 但预计算倾向
      max_motivation < θ_silence → SILENCE
  → 自我延续检查: W_probe 判定"这个主动行为像不像我"? (§8.4)
      不一致 → 降级为 SILENCE 或调整 intent_description
  → 输出: DialogueIntent 或 SILENCE
```

三支柱耦合点：
- **内在状态层 → 动机生成层**：energy/PE/arousal/V_drift 进入动机公式的加法项与减法项。
- **主观时间层 → 动机生成层**：R(e)⁻¹ 进入维持性动机项（记忆重量调制）。
- **自我延续层 → 动机生成层**：V_drift（来自 g(V)）作为减法项抑制主动。
- **自我延续层 → 姿态决策后**：W_probe 对主动行为做自我归属检查（§8.4），不一致则降级。

### 8.2 proactive_traverser 降级为候选事件遍历器

`ProactiveTraverser.traverse()` 的 5 阶段推理链（[proactive_traverser.py#L86-L149](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/proactive_traverser.py#L86-L149)）现在**只执行阶段 1-3**（候选遍历），阶段 4（姿态生成 `_decide_attitude()`）与阶段 5（执行）被动机驱动决策取代：

| 阶段 | 旧角色 | 新角色 | 是否保留 |
|------|-------|-------|---------|
| 1 场景识别 | is_qa 判定 | 保留（α 强制 PASSIVE_REPLY，β 自由姿态） | ✅ |
| 2 锚点定位 | get_clock_anchor | 保留（提供时间参照） | ✅ |
| 3 时间流回放 | get_proactive_candidates | 保留（**核心**：返回 topk 候选含 event_id/state/r_value） | ✅ |
| 4 姿态生成 | _decide_attitude 规则链 | **删除**——姿态由 §8.3 动机驱动决策生成 | ❌ |
| 5 执行 | 返回 ProactiveDecision | **删除**——由 §8.3 构造 DialogueIntent | ❌ |

**候选遍历器的实现**：副脑调用 traverser 的阶段 1-3 获取候选列表，不调用 `_decide_attitude()`：

```python
def get_candidates(self, graph, now, anchor_session_id, current_context, is_qa) -> list:
    """候选事件遍历器: 只执行 proactive_traverser 阶段 1-3, 不做姿态决策.

    返回 [(event_id, state, r_value, event_obj), ...] topk 候选.
    姿态决策由 §8.3 动机驱动决策完成.
    """
    # 阶段 1: 场景识别 (仅记录 is_qa, 不强制姿态)
    # 阶段 2: 锚点定位
    anchor = graph.get_clock_anchor(anchor_session_id)
    # 阶段 3: 时间流回放 (候选遍历)
    candidates = graph.get_proactive_candidates(
        now=now, anchor_session_id=anchor_session_id,
        topk=self.topk_candidates, min_importance=self.min_importance,
    )
    # 不执行阶段 4 (_decide_attitude) 与阶段 5 (返回 ProactiveDecision)
    return candidates
```

**保留的姿态四值**：FOLLOW_UP / CHECK_IN / SILENCE / PASSIVE_REPLY 仍是 ProactiveAttitude 枚举（数据契约不变），但其决策来源从"规则优先级表"改为"动机类型映射"（§8.3）。

### 8.3 动机驱动的姿态决策

姿态决策实现"动机排序 + 阈值门控 + 动机类型→姿态映射"三步：

```python
def _decide_attitude_by_motivation(self, candidates, fused, self_state, user_state) -> Optional[Union[DialogueIntent, CausalPlan]]:
    """动机驱动的姿态/计划决策: 取 max_motivation 候选 + 阈值门控 + 动机类型映射.

    取代旧版 _decide_attitude 规则链. ~5ms (10 候选 × 0.5ms/候选).
    
    返回值可能是:
      - None: SILENCE (动机不足 / 自我延续检查未过)
      - DialogueIntent: 单次决策 (maintenance/exploration/relational 动机)
      - CausalPlan: 闭环决策 (exploratory_play 动机, §6.6, 交 PlanExecutor 跨 tick 执行)
    """
    if not user_state.presence:
        return None                                    # presence 门控: 不在场不主动

    # 1. 主观时间流速调制有效阈值 (§7.3)
    dilation = subjective_time_dilation(self_state, user_state)
    theta_active = self.theta_active_base * dilation   # 专注时上调(难主动), 无聊时下调(易主动)
    theta_silence = self.theta_silence_base * dilation

    # 2. 对每个候选计算动机强度与动机类型 (§6.5 + §6.6 无聊分支)
    #    §6.6: energy<0.3 + presence + silence>120s → is_bored=True → exploratory_play 动机类型
    motivations, is_bored = self.compute_motivation_with_boredom(
        candidates, user_state, self_state,
    )
    scored = []
    for (event_obj, motivation, m_type) in motivations:
        eid = event_obj.id
        state = event_obj.state
        r_val = event_obj.r_value
        # 硬触发加持: 长沉默硬触发对 motivation 加 0.2
        if fused.hard_trigger == "long_silence":
            motivation += 0.2
        scored.append((motivation, m_type, eid, state, r_val, event_obj))

    # 3. 无候选兜底: 长沉默硬触发 → 通用 CHECK_IN
    if not scored:
        if fused.hard_trigger == "long_silence":
            return self._build_generic_check_in_intent(user_state)
        return None                                    # SILENCE

    # 4. 取 max_motivation
    scored.sort(key=lambda x: x[0], reverse=True)
    max_motivation, m_type, eid, state, r_val, event_obj = scored[0]

    # 5. 阈值门控
    if max_motivation < theta_silence:
        return None                                    # SILENCE (动机不足)
    if max_motivation < theta_active:
        return None                                    # SILENCE 但可启动预计算倾向 (§10.2)

    # 6. 动机类型 → 姿态/计划映射 (§6.5.3 + §6.6.4)
    if m_type == "exploratory_play":
        # ★ 无聊模式触发 CausalPlan (§10.5), 交 PlanExecutor 跨 tick 执行
        # reason→act→observe→adjust 闭环, 不构造单次 DialogueIntent
        plan = self._build_causal_plan_for_play(event_obj, user_state, self_state, max_motivation)
        if plan is None:
            return None  # CausalPlan 构造失败 (如候选不适合做 plan), 降级 SILENCE
        # 自我延续检查 (§8.4): 对 plan 的 goal 做自我归属
        if not self._self_continuity_check_for_plan(plan, m_type, event_obj):
            return None  # "不像 Lucy 会做的 plan" → 降级 SILENCE
        return plan
    if m_type == "maintenance":
        attitude = ProactiveAttitude.FOLLOW_UP
    elif m_type in ("exploration", "relational"):
        attitude = ProactiveAttitude.CHECK_IN
    else:
        attitude = ProactiveAttitude.SILENCE
        return None

    # 7. attention 门控: 低注意力时延后 FOLLOW_UP (保留旧门控)
    if attitude == ProactiveAttitude.FOLLOW_UP and user_state.attention < 0.3:
        return None

    # 8. 构造 intent_description (动机类型语义化)
    desc = self._describe_by_motivation(attitude, m_type, event_obj, user_state)
    confidence = self._estimate_confidence_by_motivation(
        max_motivation, m_type, scored, fused, user_state, self_state
    )
    intent = DialogueIntent(
        attitude=attitude,
        target_event_id=eid,
        intent_description=desc,
        context_bundle=None,                           # 预计算阶段填充
        identity_cache_snapshot=self.identity_cache.clone(),
        confidence=confidence,
        safety_mode="normal",                           # β 主动话语无输入异己风险
        needs_api_thinking=(confidence < self.theta_conf),
        mode="stream",
    )

    # 9. 自我延续检查 (§8.4): W_probe 对主动行为做自我归属
    intent = self._self_continuity_check(intent, m_type, event_obj)
    return intent
```

#### 8.3.1 CausalPlan 构造（exploratory_play 动机的闭环输出）

当动机类型为 `exploratory_play` 时，`_decide_attitude_by_motivation` 不返回单次 DialogueIntent，而是调用 `_build_causal_plan_for_play` 构造跨 tick 的 CausalPlan（§10.5 数据结构）。该方法把"无聊 + 候选有 entertainment_value"转化为 reason→act→observe→adjust 的因果链：

```python
def _build_causal_plan_for_play(self, event_obj, user_state, self_state, motivation: float) -> Optional[CausalPlan]:
    """为 exploratory_play 动机构造 CausalPlan (§10.5 数据结构).
    
    把"无聊 + 候选有 entertainment_value"转化为:
      step1 reason: 想到'可以 <event 的娱乐动作>' (意图生成)
      step2 reason: 检索记忆'用户偏好细节' (细节填充, 命中 TFGR 图历史因果链)
      step3 act:   执行娱乐动作 (调 M5 工具 / M3 主脑 / M6 身体)
      step4 observe: 观察用户反应 (跨 tick 等待 timeout_s)
      step5 adjust:  根据观察调整 + 认知更新 (回写 TFGR 图, §10.7)
    
    返回 None 表示候选不适合做 plan (如 entertainment_value 太低), 降级 SILENCE.
    """
    # 候选 suitability 检查: entertainment_value 必须够高
    ent_val = getattr(event_obj, "entertainment_value", None)
    if ent_val is None:
        ent_val = estimate_entertainment_value(event_obj, user_state)
    if ent_val < 0.5:
        return None  # 娱乐价值不足, 不构造 plan (降级让 §6.5 正常公式处理)

    # 推断娱乐动作类型 (音乐/视频/故事/笑话, 从 event metadata)
    action_kind = event_obj.metadata.get("category", "generic")
    goal = f"打发无聊时间, 让用户开心 (基于: {event_obj.summary()})"

    # 构造 CausalPlan 的 5 步因果链
    plan = CausalPlan(
        plan_id=f"plan_{int(monotonic_now()*1000)}",
        goal=goal,
        trigger_motivation="exploratory_play",
        created_at=monotonic_now(),
        steps=[
            # step1: 意图生成 (副脑本地推理)
            PlanStep(
                step_id="s1",
                step_type="reason",
                description=f"想: 可以放{action_kind_map(action_kind)}打发时间",
                precondition=f"无聊: energy={self_state.energy:.2f}, silence={int(user_state.silence_duration)}s",
                action=PlanAction(
                    action_type="sub_brain_reason",
                    payload={"prompt": f"用户在场且长时间沉默, 我能做什么让气氛好起来? 候选: {event_obj.summary()}"},
                    expected_latency_ms=20.0,
                ),
                expected_observation=f"intent: play_{action_kind}",
            ),
            # step2: 细节填充 (检索 TFGR 图, 命中历史因果链)
            PlanStep(
                step_id="s2",
                step_type="reason",
                description=f"检索记忆: 用户偏好的{action_kind_map(action_kind)}细节",
                precondition=f"intent: play_{action_kind}",
                action=PlanAction(
                    action_type="memory_retrieve",
                    payload={"query": f"用户{action_kind}偏好", "topk": 5,
                             "filter": {"category": f"{action_kind}_preference"}},
                    expected_latency_ms=80.0,
                ),
                expected_observation=f"target: 具体内容 (如某歌手/某视频)",
            ),
            # step3: 执行 (调 M5 工具 / M3 主脑 / M6 身体, 由 action_type 决定)
            PlanStep(
                step_id="s3",
                step_type="act",
                description=f"执行: {event_obj.metadata.get('action_desc', '播放内容')}",
                precondition="target: 具体内容",
                action=PlanAction(
                    action_type=event_obj.metadata.get("action_type", "tool_call"),
                    payload=event_obj.metadata.get("action_payload", {
                        "tool_name": "music_player",
                        "args": {"artist": event_obj.metadata.get("artist", "unknown")},
                    }),
                    expected_latency_ms=1000.0,
                ),
                expected_observation="content_playing",
            ),
            # step4: 观察用户反应 (跨 tick 等待)
            PlanStep(
                step_id="s4",
                step_type="observe",
                description="观察用户反应 (情绪/注意力/语音变化)",
                precondition="content_playing",
                timeout_s=30.0,
                expected_observation="用户情绪正向变化 (valence↑, attention↑)",
            ),
            # step5: 调整 + 认知更新 (回写 TFGR 图由 _complete_plan 自动完成)
            PlanStep(
                step_id="s5",
                step_type="adjust",
                description="根据观察调整后续行为 + 认知更新",
                precondition="用户反应已观察",
                adjustment_rules={
                    "positive_reaction": f"continue: 记住'放{action_kind_map(action_kind)}能让用户开心'",
                    "negative_reaction": "switch: 换其他内容或停止",
                    "timeout_no_reaction": "stop: 用户可能不在意, 中止 plan",
                    "user_speaking": "pause: 用户开始说话, 挂起 plan 让 α 路径接管",
                },
            ),
        ],
    )
    return plan

def _self_continuity_check_for_plan(self, plan: CausalPlan, m_type: str, event_obj) -> bool:
    """自我延续检查 (plan 版): W_probe 判定 plan 的 goal 是否'像 Lucy 会做的'.
    
    与 §8.4 单次 intent 检查类似, 但对 plan.goal 做自我归属.
    ~10ms 本地 forward.
    """
    virtual_text = f"{plan.goal} | Lucy recent self"
    with torch.no_grad():
        ids = self.tokenizer(virtual_text, return_tensors="pt").input_ids.to("cuda")
        inputs_embeds = self.inject_identity_prefix(ids)
        outputs = self.model.qwen(
            inputs_embeds=inputs_embeds, use_cache=False,
            output_hidden_states=True,
        )
        last_hidden = outputs.hidden_states[-1][:, -1, :]
        self_attribution = F.cosine_similarity(
            last_hidden, self.W_probe.expand_as(last_hidden), dim=-1
        ).item()
    if self_attribution < 0.0:
        log_info(f"Self-continuity check failed for plan: {plan.goal} "
                 f"self_attribution={self_attribution:.3f}, downgrade to SILENCE")
        return False
    return True
```

`intent_description` 构造规则（动机类型语义化，非自然语言）：

```
<ATTITUDE> [<MOTIVATION_TYPE>]: <动作> <对象> <事件摘要>
```

例：
- `FOLLOW_UP [maintenance]: 询问 小明 面试结果`（维持性动机：能量足+事件远+重要）
- `CHECK_IN [exploration]: 确认 小明 项目进展`（探索性动机：PE 高+相关，世界与预期不符）
- `CHECK_IN [relational]: 关心 小明 感冒恢复`（关系性动机：arousal 高+关系近）
- `PASSIVE_REPLY: 回应 用户 当前问题`（α 路径，无动机类型）

### 8.4 自我延续检查（W_probe 主动行为自我归属，新增）

W_probe（[qwen_with_graph_bias_sst.py#L1167](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_state_machine/models/qwen_with_graph_bias_sst.py#L1167)）原本只用于异己检测（§5，判定"输入/输出文本是否偏离 Lucy 身份锚"）。本节新增**主动行为自我归属检查**用途：在副脑决定主动发起一个行为前，判定"这个主动行为像不像我"——与 identity_cache 当前自我形象是否一致。

**自我归属检查的逻辑**：副脑把"拟主动发起的 intent_description + 当前 identity_cache"作为虚拟文本 forward 一次，读 last_hidden 做 W_probe 自我归属打分。若分数低于阈值（即"这个主动行为不像 Lucy 会做的"），则降级为 SILENCE 或调整 intent_description。

```python
def _self_continuity_check(self, intent: DialogueIntent, m_type: str,
                            event_obj) -> Optional[DialogueIntent]:
    """自我延续检查: W_probe 判定主动行为是否"像 Lucy 会做的".

    新增用途 (不只是异己检测): 主动行为自我归属检查.
    与 identity_cache 当前自我形象不一致 → 降级为 SILENCE 或调整 intent_description.
    ~10ms 本地 forward.
    """
    # 1. 构造虚拟文本: intent_description + identity_cache 当前形象代表
    virtual_text = f"{intent.intent_description} | Lucy recent self"
    with torch.no_grad():
        ids = self.tokenizer(virtual_text, return_tensors="pt").input_ids.to("cuda")
        inputs_embeds = self.inject_identity_prefix(ids)         # 注入 identity_cache
        outputs = self.model.qwen(
            inputs_embeds=inputs_embeds, use_cache=False,
            output_hidden_states=True,
        )
        last_hidden = outputs.hidden_states[-1][:, -1, :]
        # W_probe 自我归属分数: cos(last_hidden, W_probe)
        self_attribution = F.cosine_similarity(
            last_hidden, self.W_probe.expand_as(last_hidden), dim=-1
        ).item()
    # 2. 自我归属判定: 分数 > θ_self_continuity = "像 Lucy 会做的"
    theta_self_continuity = 0.0                  # 与 θ_safety 一致 (self>0, alien<0)
    if self_attribution < theta_self_continuity:
        # 3. 不一致: 降级为 SILENCE (动机虽足, 但"不像我")
        log_info(f"Self-continuity check failed: {intent.intent_description} "
                 f"self_attribution={self_attribution:.3f}, downgrade to SILENCE")
        return None
    # 4. 一致: 通过自我延续检查, 保留 intent
    return intent
```

**自我延续检查的伪意识意义**：
- 旧版 W_probe 只做"异己检测"（输入/输出是否偏离 Lucy）——是被动的边界检查。
- 新版 W_probe 增加"主动行为自我归属"——在副脑主动发起前，主动判定"这个行为像不像我"。这是伪意识"自我延续层"对主动性的反向约束：不是有动机就发起，而是"有动机 + 像我"才发起。
- 与 identity_cache 的耦合：identity_cache 的 14 条 EMA 是"我的近期自我形象"，自我归属检查以该形象为参照，判定主动行为是否延续"昨天的我"。

**降级策略**：
- `self_attribution < θ_self_continuity`：降级为 SILENCE（最严格）。
- `self_attribution ∈ [θ_self_continuity, θ_self_continuity + 0.05]`：保留 intent 但调整 intent_description（弱化"不像我"的部分，如把"提议带伞"调整为"提一下天气"）。
- `self_attribution > θ_self_continuity + 0.05`：通过，保留原 intent。

### 8.5 confidence 评估与思考模式触发（动机决策整体自洽度）

confidence 不再是"规则置信度"（旧版 `c += 0.1 * energy` 的规则器套皮公式已删除），而是**动机决策的整体自洽度**——反映"当前动机决策有多自洽/可信"：

```python
def _estimate_confidence_by_motivation(self, max_motivation, m_type, scored,
                                        fused, user_state, self_state) -> float:
    """confidence 反映动机决策的整体自洽度, 非规则置信度.

    旧版 c += 0.1 * energy 已删除. confidence 现在度量:
    - max_motivation 与次优 motivation 的间距 (决策明确性)
    - 动机类型与硬触发/用户状态的一致性
    - 自我稳定性 (V_drift 低 = 自洽度高)
    """
    c = 0.0
    # 维度1: max_motivation 绝对强度 (动机足 = 决策可信)
    c += 0.3 * clamp(max_motivation / 1.5, 0, 1)            # max_motivation 归一化
    # 维度2: 决策明确性 (max 与次优的间距, 间距大 = 不犹豫)
    if len(scored) >= 2:
        margin = scored[0][0] - scored[1][0]
        c += 0.2 * clamp(margin / 0.5, 0, 1)
    else:
        c += 0.1                                            # 单候选时基础分
    # 维度3: 硬触发加持 (硬触发 = 物理时机明确)
    if fused.hard_trigger == "long_silence":
        c += 0.2
    # 维度4: 用户状态明确性 (情绪非中性 = 信号强)
    emotion_strength = (abs(user_state.emotion_valence)
                        + user_state.emotion_arousal) / 2
    c += 0.15 * emotion_strength
    # 维度5: 自我稳定性 (V_drift 低 = 自洽度高, 与旧版 energy 维度反向)
    c += 0.15 * (1 - clamp(self_state.V_drift / 0.5, 0, 1))
    return clamp(c, 0.0, 1.0)
```

**思考模式触发条件**（任一满足，且仅 β 路径）：

| 条件 | 阈值 | 说明 |
|------|------|------|
| confidence 不足 | < θ_conf = 0.75 | 动机决策自洽度低 |
| 候选事件冲突 | max 与次优 motivation 间距 < 0.1 | 多事件竞争同一时机，动机无法明确排序 |
| 用户情绪突变 | \|arousal_t - arousal_{t-1}\| > 0.4 且无明确触发 | 情绪异常需深度解读 |
| 话题漂移 | current_topic 与候选事件语义相似度 < 0.3 | 长期对话话题断裂 |
| 长期未解决意图 | unresolved_intents 非空且超 24h | 需复杂推理判断是否 revisit |
| V40 自我稳定性信号 | g(V) < 0.3 / V_drift > 0.7（见 §6.4） | 自我不稳定，需主脑 API 深度对齐 |

**关键约束**：α 路径**绝不调思考模式**（用户在等，2-10s 不可接受）。α 路径 confidence 不足时直接用规则兜底（PASSIVE_REPLY + 通用语境包）。

```python
def run_alpha(self, speech_event: SpeechStartEvent) -> DialogueIntent:
    """α 路径入口: 事件触发, ≤30ms 快速判定. 绝不调思考模式."""
    # 0. 作废 β 预计算 (铁律: α 优先)
    self.version.invalidate()
    self.precompute_mgr.cancel_all()

    # 1. 读 UserState (内存, ~5μs)
    user_state = m1.read_user_state()

    # 2. 候选遍历器: 获取候选事件供 α 语境包参考 (α 不做姿态决策/动机决策, 强制 PASSIVE_REPLY)
    #    traverser 降级为候选遍历器 (§8.2), α 路径不调用阶段4姿态生成, 也不经动机驱动决策
    alpha_candidates = self.traverser.get_candidates(
        graph=self.tfgr_graph,
        now=monotonic_now(),
        anchor_session_id=current_session,
        current_context=speech_event.asr_text,
        is_qa=True,                          # α 路径标识, 不强制姿态
    )

    # 3. W_probe 输入检测 (~10ms 本地 forward, 并行于记忆检索)
    alien = self.w_probe_input_check(speech_event.asr_text)
    safety_mode = alien.safety_mode          # "normal" | "defensive"

    # 4. 组装语境包 (记忆检索在并行线程做)
    bundle = assemble_context_bundle(
        user_state=user_state,
        seed_text=speech_event.asr_text,
        retrieve_topk=8,
    )

    # 5. 并行: M6 LISTENING_POSE
    m6.send_intent(BodyIntent.LISTENING_POSE)

    # 6. 生成 DialogueIntent (α 绝不调思考模式)
    return DialogueIntent(
        attitude=ProactiveAttitude.PASSIVE_REPLY,
        target_event_id=None,
        intent_description=f"PASSIVE_REPLY: 回应 '{speech_event.asr_text[:30]}'",
        context_bundle=bundle,
        identity_cache_snapshot=self.identity_cache.clone(),
        confidence=0.9,                       # QA 场景默认高置信
        safety_mode=safety_mode,
        needs_api_thinking=False,             # α 绝不调思考模式
        mode="stream",
    )
```

- α 路径**绝不调主脑 API 思考模式**（5s+ 超时不可接受）
- α 路径**绝不预计算**（用户在等，没时间预热）
- α 路径判定逻辑极简：90%+ 情况是 PASSIVE_REPLY

## 10. β 路径主动循环流程

β 路径是副脑主动发起对话的路径，延迟不敏感，可预计算预热。tick 频率 0.5-2Hz，决策循环预算 150ms 目标 80ms。

### 10.1 β tick 循环结构

```python
class SubBrainLoop:
    """副脑主动决策循环. 后台线程, 低优先级, β 路径."""
    def __init__(self, config):
        self.tick_hz = config.tick_hz              # 默认 1.0
        self.traverser = ProactiveTraverser(
            r_high=0.7, r_low=0.3,
            min_importance=0.3, topk_candidates=10,
        )                                          # 降级为候选遍历器 (§8.2)
        self.precompute_mgr = PrecomputeManager()
        self.version = PrecomputeVersion()
        self.theta_conf = 0.75                     # 思考模式触发阈值
        self.theta_active_base = 0.8               # 动机主动阈值基数 (§8.3, 受主观时间调制)
        self.theta_silence_base = 0.3              # 动机沉默阈值基数
        # 时间因果推理闭环: PlanExecutor 跨 tick 推进 CausalPlan (§10.6)
        self.plan_executor = PlanExecutor(sub_brain=self)
        self.running = False

    def run(self):
        self.running = True
        interval = 1.0 / self.tick_hz
        while self.running:
            t0 = time.monotonic()
            try:
                self._tick()
            except Exception as e:
                log_error(e)                       # 副脑崩溃不传染 α
                # 心跳仍要发, 否则看门狗误判 L6 降级
            elapsed = time.monotonic() - t0
            sleep_max(0, interval - elapsed)       # 补足到 interval
            heartbeat.send()                       # 1s 心跳

    def _tick(self):
        now = monotonic_now()
        # 0. 版本校验: α 到来则跳过本 tick (α 优先铁律, §10.3)
        if self.version.is_stale(): return
        # 1. 读 UserState (内存, ~5μs)
        user_state = m1.read_user_state()
        if not user_state.presence:
            self._handle_absence(user_state); return
        # 1.5 ★ 时间因果推理闭环入口: 先检查 PlanExecutor 有无活动 plan
        #    有活动 plan → 推进它 (reason/act/observe/adjust), 本 tick 不走动机生成路径
        #    无活动 plan → 走动机生成路径 (§6.5/§6.6 + §8.3), 可能启动新 plan
        plan_intent = self.plan_executor.tick(now, user_state)
        if self.plan_executor.active_plan is not None:
            # 有活动 plan 在推进中
            if plan_intent is not None:
                # plan 的 act step 派发了 DialogueIntent → 启动预计算
                self.precompute_mgr.kickoff(plan_intent, self.version)
                if fused_hard_trigger_is_long_silence(now):
                    self.precompute_mgr.flush_play(plan_intent)
            return  # 本 tick 由 plan_executor 接管, 不走动机生成
        # 2. 双时钟融合 (~1ms): 只产出 hard_trigger + 候选列表, 不做姿态决策
        fused = fuse_clocks(self.physical_clock, self.tfgr_graph, user_state, now)
        # 3. 内在状态层: 自身状态感知 (本地 forward, ~5ms) + V40 自我稳定性信号 (~2ms)
        v_signal = self.compute_v40_signal_from_current_hidden()
        self.self_state.update_from_forward(self, user_state.current_topic, v_signal)
        # 4. 动机生成层: 对每个候选计算 motivation(e) + 动机类型 (~5ms, §6.5/§6.6)
        #    §6.6 无聊分支: energy低+presence高+silence长 → exploratory_play 动机类型
        #    + 动机驱动姿态决策 (阈值门控 + 动机类型→姿态/计划映射, §8.3)
        #    + 自我延续检查 (W_probe 主动行为自我归属, ~10ms, §8.4)
        decision = self._decide_attitude_by_motivation(
            candidates=fused.candidates,
            fused=fused,
            self_state=self.self_state,
            user_state=user_state,
        )
        # 4a. 决策结果可能是: None (SILENCE) / DialogueIntent (单次) / CausalPlan (闭环)
        if decision is None: return                  # SILENCE (动机不足 / 自我延续检查未过)
        if isinstance(decision, CausalPlan):
            # exploratory_play 动机触发 CausalPlan → 交给 PlanExecutor 跨 tick 执行
            self.plan_executor.start_plan(decision, now)
            return
        # decision 是 DialogueIntent, 走原单次决策路径
        intent = decision
        # 5. confidence 不足 → 触发主脑 API 思考模式 (仅 β, 异步)
        if intent.confidence < self.theta_conf:
            self._trigger_main_brain_thinking_async(intent)
            return
        # 6. 启动预计算
        self.precompute_mgr.kickoff(intent, self.version)
        # 7. 时机判定: 长沉默硬触发立即播放
        if fused.hard_trigger == "long_silence":
            self.precompute_mgr.flush_play(intent)
```

**关键变化（含时间因果推理闭环升级）**：
- 旧版步骤 3 是 `traverser.traverse()` 直接返回姿态决策（规则链）；新版步骤 4 是 `_decide_attitude_by_motivation()`，遍历候选→计算动机→取 max→阈值门控→自我延续检查→姿态。
- **新增步骤 1.5**（时间因果推理闭环入口）：先检查 PlanExecutor 有无活动 plan，有则推进它（reason/act/observe/adjust），本 tick 不走动机生成路径。这是闭环架构的关键——已有 plan 在执行时，副脑不再每次都从动机生成重新决策，而是让 plan 跨 tick 推进。
- **步骤 4a 升级**：决策结果不再只是 DialogueIntent 或 None，可能是 CausalPlan（当 motivation_type == "exploratory_play" 时，§6.6/§8.3）。CausalPlan 交给 PlanExecutor 跨 tick 执行，而非单次预计算。
- 内在状态层（步骤 3）前置于动机生成层（步骤 4），因为 motivation 公式依赖 self_state 的 energy/PE/arousal/V_drift。
- 动机生成 ~5ms + 自我延续检查 ~10ms，总增量 ~15ms，对 β tick 80ms 预算可接受（traverser 原姿态决策 ~5ms 被取代）。PlanExecutor.tick 在无活动 plan 时仅 ~1ms（检查 active_plan is None 后返回），有活动 plan 时单 step 推进最差 ~80ms（reason 含 memory_retrieve），与预算兼容（observe step 跨 tick 等待不阻塞）。

### 10.2 β 路径时序与预计算

```
[M2 副脑 tick] @ 0.5-2Hz (后台, 低优先级, ~80ms)
        │
        ├─ 读单调时钟 + 主观时间 R(e) (~1ms, 双时钟融合只产硬触发+候选列表)

        ├─ 内在状态层: self_state_predictor 自身状态读取 (~5ms 本地 forward)

        │
```

### 10.3 α 到来时 β 作废（铁律）

**铁律：α 优先，β 让步。** 用户的话不能不回，主动话语可以不说。

仲裁规则：

| 情形 | 仲裁动作 |
|------|---------|
| α 到来，β 在决策循环中 | β 当前 tick 中止，丢弃未完成决策 |
| α 到来，β 已生成 DialogueIntent 但未预计算 | Intent 丢弃，β 转入 α 协助模式（提供候选事件给 α 语境包） |
| α 到来，β 在预计算中（候选/TTS） | 所有预计算结果作废，释放 GPU 资源给 α |
| α 到来，β 已预合成待播放 | 预合成音频丢弃，绝不抢在用户话前播放 |
| α 与 β 抢 GPU | β 让步（β 预计算可暂停/丢弃） |
| α 与 β 抢网络（主脑 API 调用） | β 让步（β 思考模式调用可暂停，α 回复调用优先） |

**作废的语义**：β 的预计算结果不仅"不用"，还要主动释放资源，避免内存累积。作废通过版本号原子实现：

```python
class PrecomputeVersion:
    """每次 α 到来递增版本号, β 预计算写入时记录版本,
    读取时校验版本, 不匹配则丢弃."""
    current: int = 0
    def invalidate(self): self.current += 1
    def is_valid(self, written_at: int) -> bool:
        return written_at == self.current
```

### 10.4 α 到来时活动 CausalPlan 的处理

§10.3 的 α 优先铁律在引入 CausalPlan 后补充：若 β 路径有活动 plan（`PlanExecutor.active_plan is not None`），α 到来时按以下规则处理：

| 活动状态 | 仲裁动作 |
|---------|---------|
| plan.status == "executing" 且当前 step 是 reason | 中止整个 plan，回写"未完成"因果链（仅含已执行步骤，标记 aborted） |
| plan.status == "executing" 且当前 step 是 act（已派发动作） | **挂起** plan（不回写），act 已派发的输出按 §10.3 规则作废；α 处理完后若 plan 未超时则恢复 |
| plan.status == "observing" | **挂起** plan（observe 本就是跨 tick 等待），α 处理完后继续观察 |
| plan.status == "adjusting" | 立即完成 adjust（用当前 observation），回写后中止 plan |

挂起的 plan 在 α 处理完后由 §10.1 的 `tick` 流程恢复推进；若挂起超过 `plan.timeout_s`（默认 60s），plan 自动 abort 并回写"中断"因果链。该规则保证 α 优先铁律不变，同时尽量保留已积累的因果链（避免每次 α 都从头开始）。

### 10.5 CausalPlan 时间因果计划数据结构

#### 10.5.1 设计动机：从开环 DialogueIntent 到闭环 CausalPlan

§10.1 的 β tick 循环是开环单次决策：tick → 读状态 → 遍历候选 → 算动机 → 生成 DialogueIntent → 调 M3 → 播放 → 结束。用户的"放歌"场景指出其不足：副脑在"无聊"时应能跨时间多步推理——先想到"可以放首歌"（意图），再想"放什么歌"（细节，需检索记忆），再执行，再观察用户反应，再根据反应调整后续行为。这是**跨 tick 的时间因果链**——每步依赖前一步结果，最终回写 TFGR 图成为未来推理素材。

CausalPlan 是 DialogueIntent 的上层抽象：一个 Plan 含多个 PlanStep，每个 act 类型的 step 可能产生一个 DialogueIntent（底层契约不变）。Plan 由 PlanExecutor 跨 tick 推进，**observe 步骤跨 tick 等待**（不增加单 tick 预算）。

#### 10.5.2 数据结构定义

```python
from dataclasses import dataclass, field
from typing import Optional, List, Dict, Literal

@dataclass
class CausalNode:
    """因果链节点: 一个 CausalPlan 执行过程中累积的因果节点.
    
    回写 TFGR 图时, 整条 causal_chain 作为新节点写入 (§10.7).
    """
    t: float                                       # 物理时间戳
    type: Literal["internal_state", "reason", "act", "observe", "adjust"]
    content: str                                   # 节点内容描述
    precondition: Optional[str] = None             # 依赖前一步的结果 (因果链前驱)
    result: Optional[str] = None                   # 执行结果

@dataclass
class PlanAction:
    """计划步骤的动作封装. 不同 action_type 路由到不同下游模块."""
    action_type: Literal[
        "main_brain_generate",    # 调 M3 主脑 API 生成 (stream/complete/thinking)
        "tool_call",               # 调 M5 MCP 工具 (如音乐播放/日历查询)
        "body_action",             # 调 M6 BodyIntent (如 APPROACH_USER)
        "memory_retrieve",         # 副脑本地检索 TFGR 图 (无外部调用)
        "sub_brain_reason",        # 副脑本地轻量推理 (如检索后筛选)
    ]
    payload: dict                                 # 动作负载
    # main_brain_generate: GenerationRequest (含 DialogueIntent)
    # tool_call: {tool_name, args}
    # body_action: BodyIntent 枚举值
    # memory_retrieve: {query, topk, filter}
    # sub_brain_reason: {prompt, context_nodes}
    expected_latency_ms: float = 500.0            # 预期时延 (用于单 step 预算控制)

@dataclass
class PlanStep:
    """CausalPlan 中的一个步骤. step_type 决定执行方式."""
    step_id: str
    step_type: Literal["reason", "act", "observe", "adjust"]
    description: str                              # "想用户喜欢什么歌" / "播放周杰伦的歌" / "观察用户反应"
    precondition: Optional[str] = None            # 依赖前一步的结果 (因果前驱)
    action: Optional[PlanAction] = None            # 仅 act step 必填
    expected_observation: Optional[str] = None    # 预期观察 (用于异常检测, 如"用户情绪正向变化")
    adjustment_rules: Optional[Dict[str, str]] = None  # observe 结果 → 调整策略映射 (仅 adjust step)
        # 例: {"positive_reaction": "continue", "negative_reaction": "switch_music", "timeout_no_reaction": "stop_plan"}
    timeout_s: float = 30.0                       # observe step 的等待超时
    executed_at: Optional[float] = None           # 实际执行时间戳
    result: Optional[str] = None                  # 执行结果 (reason 的结论 / act 的输出 / observe 的观察)

@dataclass
class CausalPlan:
    """跨 tick 的时间因果推理计划. 取代开环单次决策.
    
    一个 Plan 可能包含多个 DialogueIntent (每个 act step 产生一个).
    PlanExecutor 跨 tick 推进, observe step 跨 tick 等待.
    """
    plan_id: str
    goal: str                                     # "让用户开心" / "打发无聊时间"
    trigger_motivation: str                       # 触发此计划的动机类型 (如 "exploratory_play")
    steps: List[PlanStep]                         # 时间因果链 (有序)
    created_at: float                             # 物理时间戳
    status: Literal["planning", "executing", "observing", "adjusting", "completed", "aborted"] = "planning"
    current_step_idx: int = 0
    timeout_s: float = 120.0                      # 整个 plan 的超时 (默认 2 分钟)
    causal_chain: List[CausalNode] = field(default_factory=list)  # 执行过程累积的因果节点 (回写 TFGR 图用)
    
    def summary(self) -> str:
        """生成 plan 的摘要 (用于回写 identity_cache 或日志)."""
        results = [s.result for s in self.steps if s.result]
        return f"Plan(goal={self.goal}, steps={len(self.steps)}, results={results})"
```

#### 10.5.4 数据契约兼容性

CausalPlan 不修改主文档 §5.3 的 DialogueIntent 契约——DialogueIntent 仍是 M2→M3 的核心契约，CausalPlan 是其上层抽象：

- 每个 `act` 类型的 PlanStep 通过 `PlanAction(action_type="main_brain_generate", payload=GenerationRequest(...))` 调 M3，GenerationRequest 字段不变。
- `tool_call` 类型的 PlanStep 走 M5 MCP 调度（主文档 §5.7 不变）。
- `body_action` 类型走 M6 BodyIntent（主文档 §5.5 不变）。
- `memory_retrieve` 与 `sub_brain_reason` 是副脑本地操作，不涉及跨模块契约。

**新增契约**（仅 M2 内部）：CausalPlan 由 §8.3 动机驱动决策生成（当 motivation_type == "exploratory_play"），交给 §10.6 PlanExecutor 跨 tick 执行。

### 10.6 PlanExecutor 闭环执行器

#### 10.6.1 设计：跨 tick 推进 CausalPlan

PlanExecutor 是 β 路径的闭环执行器，住在 β tick 循环内。每个 tick，PlanExecutor 检查当前活动 plan 的状态，推进或调整：

```python
class PlanExecutor:
    """跨 tick 执行 CausalPlan 的闭环执行器. 住在 β 路径.
    
    每个 β tick 调用一次 tick(). 若有活动 plan 则推进, 否则让 §8.3 动机驱动决策
    决定是否启动新 plan (当 motivation_type == "exploratory_play" 时启动).
    
    observe step 跨 tick 等待 (不增加单 tick 预算), 这是设计如此——
    观察用户反应本质需要时间, 不能在一个 tick 内完成.
    """
    
    def __init__(self, sub_brain):
        self.sub_brain = sub_brain
        self.active_plan: Optional[CausalPlan] = None
        self.plan_history: List[CausalPlan] = []      # 已完成/中止的 plan 历史 (用于复盘)
        self.max_concurrent_plans = 1                 # 同时只允许 1 个活动 plan (避免并发混乱)
    
    def tick(self, now: float, user_state) -> Optional[DialogueIntent]:
        """每个 β tick 调用. 推进当前 plan 或返回 None (让动机系统决定).
        
        返回值:
          - None: 无活动 plan, 或 plan 在 observe/adjust 中无需派发 DialogueIntent
          - DialogueIntent: plan 的 act step 需要派发 (交 §10.1 启动预计算)
        """
        if self.active_plan is None:
            return None  # 无活动计划, 让 §8.3 动机驱动决策决定是否启动新 plan
        
        plan = self.active_plan
        # 超时检查
        if now - plan.created_at > plan.timeout_s:
            self._abort_plan(plan, reason="timeout", now=now)
            return None
        
        # 状态机推进
        if plan.status in ("aborted", "completed"):
            self._archive_plan(plan)
            self.active_plan = None
            return None
        
        current_step = plan.steps[plan.current_step_idx]
        
        if plan.status == "executing":
            return self._execute_step(current_step, plan, now)
        elif plan.status == "observing":
            self._observe_step(current_step, plan, now, user_state)
            return None
        elif plan.status == "adjusting":
            self._adjust_step(current_step, plan, now, user_state)
            return None
        return None
    
    def start_plan(self, plan: CausalPlan, now: float):
        """由 §8.3 调用: 当 motivation_type == "exploratory_play" 时启动新 plan."""
        if self.active_plan is not None:
            # 已有活动 plan, 新 plan 排队或拒绝 (这里选择拒绝, 简化)
            log_warn(f"Reject new plan {plan.plan_id}: active plan {self.active_plan.plan_id} running")
            return False
        plan.status = "executing"
        plan.current_step_idx = 0
        plan.created_at = now
        # 初始因果节点: 记录触发时的内部状态
        plan.causal_chain.append(CausalNode(
            t=now, type="internal_state",
            content=f"trigger: motivation={plan.trigger_motivation}, goal={plan.goal}",
        ))
        self.active_plan = plan
        log_info(f"Start CausalPlan {plan.plan_id}: goal={plan.goal}")
        return True
    
    def _execute_step(self, step: PlanStep, plan: CausalPlan, now: float) -> Optional[DialogueIntent]:
        """执行当前 step (reason/act). reason 本地完成, act 派发动作."""
        if step.executed_at is not None:
            # 已派发, 不重复执行 (等待外部回调或下一 tick 推进)
            return None
        
        step.executed_at = now
        
        if step.step_type == "reason":
            # 副脑本地推理 (memory_retrieve / sub_brain_reason)
            result = self._run_reason_step(step, plan, now)
            step.result = result
            plan.causal_chain.append(CausalNode(
                t=now, type="reason", content=step.description,
                precondition=step.precondition, result=result,
            ))
            # reason 完成立即推进到下一步
            return self._advance_or_observe(plan, step, now)
        
        elif step.step_type == "act":
            # act step: 派发动作 (main_brain_generate / tool_call / body_action)
            action = step.action
            if action is None:
                step.result = "no_action_defined"
                return self._advance_or_observe(plan, step, now)
            
            # 异步派发, 不阻塞 tick (act 的输出由外部回调写入 step.result)
            self._dispatch_action_async(action, step, plan, now)
            plan.causal_chain.append(CausalNode(
                t=now, type="act", content=step.description,
                precondition=step.precondition, result=f"dispatched: {action.action_type}",
            ))
            # act 后通常进入 observe (除非是最后一步)
            if step.step_type == "act" and self._has_next_step(plan):
                next_step = plan.steps[plan.current_step_idx + 1]
                if next_step.step_type == "observe":
                    plan.status = "observing"
                    return None  # observe 跨 tick 等待, 本 tick 不派发 DialogueIntent
            # 否则推进
            return self._advance_or_observe(plan, step, now)
        
        return None
    
    def _run_reason_step(self, step: PlanStep, plan: CausalPlan, now: float) -> str:
        """执行 reason step: memory_retrieve 或 sub_brain_reason."""
        action = step.action
        if action.action_type == "memory_retrieve":
            # 检索 TFGR 图 (副脑本地, ~50-80ms)
            results = self.sub_brain.tfgr_graph.retrieve(
                query=action.payload["query"],
                topk=action.payload.get("topk", 5),
                filter=action.payload.get("filter"),
            )
            # 提取关键结果
            if not results:
                return "no_memory_found"
            # 例: 检索"用户音乐偏好"命中"用户曾说自己喜欢周杰伦的歌"
            top_result = results[0]
            return f"retrieved: {top_result.summary()}"
        
        elif action.action_type == "sub_brain_reason":
            # 副脑本地轻量推理 (可选调主脑 API thinking, 但通常本地)
            # 这里简化为基于 causal_chain 的本地推理
            context = "\n".join([n.content for n in plan.causal_chain])
            conclusion = self.sub_brain.local_reason(
                prompt=action.payload["prompt"], context=context,
            )
            return conclusion
        
        return "unknown_reason_action"
    
    def _dispatch_action_async(self, action: PlanAction, step: PlanStep, plan: CausalPlan, now: float):
        """异步派发 act 动作. 输出由外部回调写入 step.result."""
        if action.action_type == "main_brain_generate":
            # 调 M3 主脑 API (stream/complete/thinking)
            # 由 §10.1 启动预计算, 完成后回调 on_action_complete
            intent = action.payload.get("intent")  # DialogueIntent
            if intent:
                self.sub_brain.precompute_mgr.kickoff(intent, self.sub_brain.version)
        elif action.action_type == "tool_call":
            # 调 M5 MCP 工具 (如音乐播放)
            m5.call_tool_async(
                tool_name=action.payload["tool_name"],
                args=action.payload["args"],
                callback=lambda result: self.on_action_complete(step, plan, result),
            )
        elif action.action_type == "body_action":
            # 调 M6 BodyIntent
            m6.send_intent(action.payload["body_intent"])
            # body_action 通常立即完成 (异步非阻塞)
            step.result = "body_dispatched"
        # main_brain_generate 与 tool_call 的回调通过 on_action_complete 写入 step.result
    
    def on_action_complete(self, step: PlanStep, plan: CausalPlan, result: str):
        """act 动作完成回调 (由 M3/M5 触发). 写入 step.result."""
        step.result = result
        # 不立即推进 (observe step 会在下一 tick 检测反应)
    
    def _observe_step(self, step: PlanStep, plan: CausalPlan, now: float, user_state):
        """观察用户反应 (等待 timeout_s 内 UserState 变化)."""
        elapsed = now - step.executed_at if step.executed_at else 0
        # 检测用户反应: 情绪/注意力/语音变化
        observation = self._detect_reaction(step, user_state, plan.causal_chain, now)
        if observation is not None:
            step.result = observation
            plan.causal_chain.append(CausalNode(
                t=now, type="observe", content=step.description,
                precondition=step.precondition, result=observation,
            ))
            plan.status = "adjusting"
        elif elapsed > step.timeout_s:
            step.result = "timeout_no_reaction"
            plan.causal_chain.append(CausalNode(
                t=now, type="observe", content=f"{step.description} (timeout)",
                precondition=step.precondition, result="timeout_no_reaction",
            ))
            plan.status = "adjusting"
        # 否则继续等待 (下一 tick 再检查) — 这就是"跨 tick 等待"
    
    def _detect_reaction(self, step: PlanStep, user_state, causal_chain, now: float) -> Optional[str]:
        """检测用户对 act 的反应. 返回观察结果或 None (未检测到)."""
        # 简化: 检查 user_state 的 emotion_valence / attention 变化
        # 实际实现需对比 act 前后的 user_state 快照
        valence_delta = user_state.emotion_valence - getattr(step, "_pre_valence", 0.0)
        attention_delta = user_state.attention - getattr(step, "_pre_attention", 0.0)
        
        if valence_delta > 0.3 and attention_delta > 0.2:
            return "positive_reaction"
        elif valence_delta < -0.3:
            return "negative_reaction"
        elif user_state.silence_duration < 5.0 and user_state.presence:
            # 用户开始说话 (可能是对 act 的回应)
            return "user_speaking"
        return None  # 未检测到明显反应, 继续等待
    
    def _adjust_step(self, step: PlanStep, plan: CausalPlan, now: float, user_state):
        """根据观察结果调整后续步骤."""
        rules = step.adjustment_rules or {}
        # 查找观察结果对应的调整策略
        # adjustment_rules 的 key 是 observe step 的 result
        observe_result = plan.causal_chain[-1].result if plan.causal_chain else "unknown"
        adjustment = rules.get(observe_result, rules.get("default", "continue"))
        
        # 应用调整: 修改后续 steps (插入/删除/修改)
        self._apply_adjustment(plan, adjustment, observe_result, now)
        
        plan.causal_chain.append(CausalNode(
            t=now, type="adjust", content=f"adjust: {adjustment} (based on {observe_result})",
            precondition=observe_result, result=adjustment,
        ))
        
        # 推进到下一步
        plan.current_step_idx += 1
        if plan.current_step_idx >= len(plan.steps):
            self._complete_plan(plan, now)
        else:
            plan.status = "executing"
    
    def _apply_adjustment(self, plan: CausalPlan, adjustment: str, observe_result: str, now: float):
        """根据调整策略修改后续 steps. 例: negative_reaction → 插入 switch_music step."""
        if adjustment.startswith("switch"):
            # 例: 用户对周杰伦的歌反应负面 → 插入"换其他歌手"step
            switch_step = PlanStep(
                step_id=f"s_switch_{int(now)}",
                step_type="reason",
                description="换其他歌手 (用户对当前选择反应负面)",
                precondition=observe_result,
                action=PlanAction(
                    action_type="memory_retrieve",
                    payload={"query": "用户其他音乐偏好", "topk": 3},
                ),
            )
            plan.steps.insert(plan.current_step_idx + 1, switch_step)
        elif adjustment.startswith("stop"):
            # 中止 plan (用户不在听)
            self._abort_plan(plan, reason="user_not_engaged", now=now)
        # continue: 不修改, 推进到下一步
    
    def _advance_or_observe(self, plan: CausalPlan, step: PlanStep, now: float) -> Optional[DialogueIntent]:
        """reason/act 完成后: 推进到下一步, 或返回需派发的 DialogueIntent."""
        plan.current_step_idx += 1
        if plan.current_step_idx >= len(plan.steps):
            self._complete_plan(plan, now)
            return None
        next_step = plan.steps[plan.current_step_idx]
        if next_step.step_type == "observe":
            plan.status = "observing"
            return None
        elif next_step.step_type == "adjust":
            plan.status = "adjusting"
            return None
        else:
            # 下一步是 reason/act, 下一 tick 继续
            plan.status = "executing"
            return None
    
    def _has_next_step(self, plan: CausalPlan) -> bool:
        return plan.current_step_idx + 1 < len(plan.steps)
    
    def _complete_plan(self, plan: CausalPlan, now: float):
        """闭环完成: 把整个因果链回写 TFGR 时间流图 (§10.7)."""
        plan.status = "completed"
        log_info(f"CausalPlan {plan.plan_id} completed: {plan.summary()}")
        # 关键: 回写因果链到 TFGR 图 (§10.7 详述)
        self.sub_brain.tfgr_graph.add_causal_chain(plan.causal_chain)
        # identity_cache 也可能更新 (如果 plan 涉及 Lucy 的自我认知调整, 如 goal 以"自我"开头)
        if plan.goal.startswith("自我") or plan.goal.startswith("让 Lucy"):
            self.sub_brain.writeback_identity_cache(plan.summary())
        # V_drift 反馈: plan 完成后更新 self_state (成功的 plan 提升 confidence)
        self.sub_brain.self_state.confidence = 0.7 * self.sub_brain.self_state.confidence + 0.3 * 0.8
    
    def _abort_plan(self, plan: CausalPlan, reason: str, now: float):
        """中止 plan: 仍回写已完成的因果链 (标记 aborted)."""
        plan.status = "aborted"
        plan.causal_chain.append(CausalNode(
            t=now, type="adjust", content=f"plan aborted: {reason}",
            result="aborted",
        ))
        log_warn(f"CausalPlan {plan.plan_id} aborted: {reason}")
        # 即使中止也回写 (失败经验也是因果链素材)
        self.sub_brain.tfgr_graph.add_causal_chain(plan.causal_chain)
    
    def _archive_plan(self, plan: CausalPlan):
        """归档已完成/中止的 plan."""
        self.plan_history.append(plan)
        if len(self.plan_history) > 50:
            self.plan_history = self.plan_history[-50:]  # 保留最近 50 个
```

#### 10.6.2 PlanExecutor 的状态机

```
planning ──start_plan──▶ executing
                         │
                  ┌──────┴──────┐
                  │             │
              reason done    act done
                  │             │
                  ▼             ▼
            next step      next step == observe?
                              │
                       ┌──────┴──────┐
                       │ yes         │ no
                       ▼             ▼
                   observing     executing (推进)
                       │
                  observe done / timeout
                       │
                       ▼
                   adjusting
                       │
                  apply adjustment
                       │
                       ▼
                   next step / complete / abort
                       │
              ┌────────┴────────┐
              │                 │
              ▼                 ▼
          completed         aborted
              │                 │
              └────────┬────────┘
                       ▼
                  回写 TFGR 图 (§10.7)
                  归档 plan_history
```

#### 10.6.3 时延预算分析

PlanExecutor 的关键特性是**不增加单 tick 预算**：

| 操作 | 单 tick 耗时 | 跨 tick? |
|------|------------|---------|
| reason step (memory_retrieve) | ~80ms | 否（单 tick 内完成） |
| reason step (sub_brain_reason) | ~20ms | 否 |
| act step (派发动作) | ~5ms（仅派发，不等返回） | 是（异步回调） |
| observe step | ~1ms（仅检测，不等反应） | **是**（跨 tick 等待 timeout_s） |
| adjust step | ~5ms | 否 |
| 状态机推进 | ~1ms | 否 |

单 tick 内 PlanExecutor 最多执行一个 step 的推进（~80ms 最差情况是 reason 含 memory_retrieve），与 §10.1 的 β tick 80ms 预算兼容。observe step 的"等待"由跨 tick 实现——每个 tick 仅做一次反应检测（~1ms），不阻塞。这是闭环架构的本质：**观察需要时间，但不能阻塞决策循环**。

#### 10.6.4 α 到来时的挂起/中止（与 §10.4 一致）

α 到来时（§10.3 铁律），PlanExecutor 按 §10.4 规则处理活动 plan：reason step 中止回写、act/observe step 挂起、adjust step 立即完成。挂起的 plan 在 α 处理完后由 §10.1 的 tick 恢复。这保证 α 优先铁律不变，同时尽量保留已积累的因果链。

### 10.7 因果链回写 TFGR 图（闭环的关键）

#### 10.7.1 回写动机：从开环到闭环的本质跃迁

§10.5/§10.6 的 CausalPlan + PlanExecutor 实现了"跨 tick 推理"，但若 plan 完成后不回写记忆，仍是开环——下次无聊时副脑仍要从零推理"放什么歌"。**闭环的关键是因果链回写 TFGR 图**：每次 CausalPlan 完成（或中止），整条"推理→执行→观察→调整"因果链作为新节点回写 TFGR 时间流图，成为未来推理的素材。

这是伪意识"主观时间层"的真正用途——TFGR 时间流图不止是"事件源 + 长期记忆"（§14 原角色），更是**时间因果链累积载体**：副脑的"经验"在图中沉淀，未来相似场景下 TFGR 图会提醒"上次这样做用户开心/不开心"。

#### 10.7.2 回写实现

```python
class TimeFlowGraph:
    """TFGR 时间流图 (扩展): 新增 add_causal_chain 方法接收因果链回写."""
    
    def add_causal_chain(self, causal_chain: List[CausalNode]):
        """接收 CausalPlan 完成时的因果链回写.
        
        把整条因果链作为新的复合事件节点加入图, 并建立因果前驱后继边.
        该节点未来可被 proactive_traverser 的候选遍历 (§8.2) 检索到.
        """
        if not causal_chain:
            return
        
        # 1. 创建复合事件节点 (代表整条因果链)
        chain_id = f"chain_{causal_chain[0].t}_{int(monotonic_now()*1000) % 1000000}"
        goal_summary = causal_chain[0].content  # 触发时的内部状态描述
        result_summary = causal_chain[-1].result or "unknown"
        
        # 2. 提取关键信息作为节点属性
        node_attrs = {
            "type": "causal_chain",
            "goal": goal_summary,
            "final_result": result_summary,
            "step_count": len(causal_chain),
            "trigger_motivation": self._extract_motivation(goal_summary),
            # entertainment_value: 用于未来 §6.6 无聊分支候选评估
            "entertainment_value": self._estimate_chain_entertainment(causal_chain),
            # success_score: 根据 final_result 估算 (positive_reaction > 0.7, negative < 0.3)
            "success_score": self._estimate_success(result_summary),
            "importance": 0.5 + 0.3 * self._estimate_success(result_summary),  # 成功的链更重要
            "valence": self._estimate_chain_valence(causal_chain),
            "created_at": causal_chain[0].t,
            "t_mid": (causal_chain[0].t + causal_chain[-1].t) / 2,
        }
        
        # 3. 加入图 (复用 time_flow_graph.py 的 add_event 机制)
        self.add_event(chain_id, **node_attrs)
        
        # 4. 建立因果边 (chain 内部各 step 之间的前驱后继)
        for i in range(1, len(causal_chain)):
            prev = causal_chain[i-1]
            curr = causal_chain[i]
            self.add_causal_edge(
                from_id=self._find_or_create_step_node(prev, chain_id),
                to_id=self._find_or_create_step_node(curr, chain_id),
                edge_type="causal_followup",
            )
        
        # 5. 建立与已有事件节点的关联边 (如 plan 触发源于某 TFGR 事件)
        # 例: "放周杰伦的歌" plan 可能源于 TFGR 图中"用户说自己喜欢周杰伦的歌"节点
        trigger_event_id = self._find_trigger_event(goal_summary)
        if trigger_event_id:
            self.add_causal_edge(
                from_id=trigger_event_id, to_id=chain_id,
                edge_type="plan_triggered_by",
            )
        
        log_info(f"CausalChain written back to TFGR graph: {chain_id}, "
                 f"success={node_attrs['success_score']:.2f}")
    
    def _estimate_chain_entertainment(self, chain: List[CausalNode]) -> float:
        """估算因果链的娱乐价值 (用于未来 §6.6 无聊分支)."""
        # 若 act step 涉及音乐/视频等娱乐动作, entertainment_value 高
        for node in chain:
            if node.type == "act" and any(kw in node.content for kw in ["播放", "音乐", "视频", "故事"]):
                return 0.8
        return 0.4
    
    def _estimate_success(self, result: str) -> float:
        """根据 final_result 估算 plan 成功度."""
        if "positive" in result or "开心" in result or "成功" in result:
            return 0.8
        elif "negative" in result or "失败" in result:
            return 0.2
        elif "timeout" in result or "aborted" in result:
            return 0.3
        return 0.5  # 未知
    
    def _estimate_chain_valence(self, chain: List[CausalNode]) -> float:
        """估算因果链的情感效价."""
        observe_nodes = [n for n in chain if n.type == "observe"]
        if not observe_nodes:
            return 0.0
        last_observe = observe_nodes[-1]
        if "positive" in (last_observe.result or ""):
            return 0.6
        elif "negative" in (last_observe.result or ""):
            return -0.4
        return 0.0
```

#### 10.7.4 回写后对未来推理的影响

回写后的因果链节点通过两条路径影响未来推理：

1. **§8.2 候选遍历**：proactive_traverser 的 `get_proactive_candidates` 会把高 entertainment_value + 高 importance 的 chain 节点作为候选返回。下次无聊时，副脑直接看到"上次放周杰伦的歌用户开心"这个候选，§6.6 的无聊分支会赋予高动机强度，触发新 CausalPlan。

2. **§10.5 reason step 的 memory_retrieve**：新 plan 的 s2（"检索记忆: 用户喜欢什么歌"）会直接命中回写的 chain 节点，result 为"用户曾说自己喜欢周杰伦的歌 + 上次放周杰伦的歌用户开心"——双重证据，confidence 提升。

这是闭环的真正威力：**每次 plan 的执行结果沉淀为图节点，未来相似场景下副脑不再从零推理，而是基于历史因果链做更优决策**。这就是"时间因果推理闭环"——推理在时间流中展开，每步有依赖，闭环回写记忆，让副脑的"经验"随时间累积。

#### 10.7.5 回写的时序保证

回写发生在 `_complete_plan` / `_abort_plan` 中（§10.6.1），即 plan 状态变为 completed/aborted 的那个 tick。回写是同步操作（~5ms，写图节点 + 建边），不影响 β tick 预算。回写后该 chain 节点立即可被下一个 tick 的候选遍历检索到（无延迟）。

**与 α 优先铁律的兼容**：若 plan 在 observe step 挂起期间 α 到来（§10.4），plan 挂起不回写；若 α 处理完后 plan 恢复并完成，正常回写；若挂起超时 abort，回写"中断"因果链（仅含已执行步骤，标记 aborted，success_score 较低，但仍可作为"失败经验"被未来推理参考——避免重复无效尝试）。

## 11. 深度推理（思考模式调用）

副脑需深度推理时，**直接调主脑 API 的"思考模式"**——同一 API（DeepSeek/OpenAI 兼容），不同 prompt。旧 M3 的"API 辅助思考"语义已被吸收进主脑 API 调用。该调用经 M3 执行（M3 是 API 客户端），β 路径异步，2-10s。

### 11.1 思考模式触发流程

```python
def _trigger_main_brain_thinking_async(self, intent: DialogueIntent):
    """β 路径 confidence<θ_conf 时, 异步调主脑 API 思考模式.

    经 M3 执行 (M3 是 API 客户端). 同一 API 不同 prompt. 超时 10s 降级.
    仅 β 路径, α 绝不调.
    """
    thinking_req = GenerationRequest(
        intent=DialogueIntent(
            attitude=intent.attitude,
            target_event_id=intent.target_event_id,
            intent_description=intent.intent_description,
            context_bundle=assemble_context_bundle_for_thinking(intent),
            identity_cache_snapshot=self.identity_cache.clone(),
            confidence=intent.confidence,
            safety_mode="normal",
            needs_api_thinking=True,
            mode="thinking",                     # 思考模式
        ),
        context_bundle=assemble_context_bundle_for_thinking(intent),
        identity_cache_snapshot=self.identity_cache.clone(),
        safety_mode="normal",
        mode="thinking",
        streaming=False,                         # 思考模式非流式, 等结构化结果
    )
    future = m3.call_main_brain_async(thinking_req)
    future.add_done_callback(self._on_thinking_response)
    # 设置超时降级计时器
    self._thinking_timeout_timer = Timer(10.0, self._on_thinking_timeout, args=(intent,))
    self._thinking_timeout_timer.start()

def _on_thinking_response(self, future, intent: DialogueIntent):
    """主脑 API 思考模式返回结构化决策建议."""
    try:
        resp: GenerationStream = future.result()
        suggestion = parse_thinking_suggestion(resp.text())
        # suggestion = {should_speak, intent_suggestion, reasoning, confidence}
        if not suggestion["should_speak"]:
            log_info("Main brain advised silence, abort")
            return
        # 采纳: 用主脑建议覆盖 intent (若主脑更自信)
        if suggestion["confidence"] > intent.confidence:
            intent.intent_description = suggestion["intent_suggestion"]
            intent.confidence = suggestion["confidence"]
            intent.needs_api_thinking = False
            self.precompute_mgr.kickoff(intent, self.version)
        else:
            # 主脑不比规则自信, 仍用规则结果但启动预计算
            intent.needs_api_thinking = False
            self.precompute_mgr.kickoff(intent, self.version)
    except Exception:
        return self._on_thinking_timeout(intent)

def _on_thinking_timeout(self, intent: DialogueIntent):
    """思考模式超时降级: 用规则兜底."""
    log_warn("Main brain thinking timeout, fallback to rule decision")
    intent.confidence = max(intent.confidence, 0.5)
    intent.needs_api_thinking = False
    self.precompute_mgr.kickoff(intent, self.version)
```

```python
def v18_style_dialogue_step(self, turn: int, user_input: str) -> DialogueIntent:
    """复用 v18 8阶段循环的反思机制, 用于副脑调主脑 API 的对话编排.

    v18 每轮 8 步: 演化图 → 触发检查 → 消息入图 → 触发生成 →
                  生成回复 → 入图 → 反思 → 状态更新
    """
    # 阶段 1: 演化图 (TFGR 时间流图自转, 副脑每个 tick 做)
    self.tfgr_graph.step(delta_t_seconds=1.0)
    self.tfgr_graph._update_energy(1.0)
    self.tfgr_graph._apply_survival_drive()

    # 阶段 2: 触发检查 (potential_history 阈值)
    max_p = max((n.potential for n in self.tfgr_graph.nodes.values()), default=0.0)
    can_trigger = max_p > self.potential_history.get_theta()

    # 阶段 3: 消息入图 (用户输入注入 TFGR 图)
    if user_input:
        self.tfgr_graph.add_event_from_input(user_input)

    # 阶段 4: 触发生成 (调主脑 API, 经 M3)
    if can_trigger:
        intent = self._build_intent_from_v18_phase(turn)
        return intent

    # 阶段 5-8: 生成回复 → 入图 → 反思 → 状态更新
    # (在主脑 API 返回后, 副脑执行回写 identity_cache + TFGR 图更新 + self_state 反思)
    return None  # SILENCE
```

```python
@dataclass
class GenerationRequest:
    intent: DialogueIntent
    context_bundle: ContextBundle
    identity_cache_snapshot: Tensor  # Lucy 身份锚快照
    safety_mode: str                 # "normal" | "defensive"
    mode: Literal["stream", "complete", "thinking"]
    streaming: bool = True

# M3 → M2 (流式)
class GenerationStream:
    def tokens(self) -> Iterator[str]: ...           # 已过滤异己的 token
    def alien_report(self) -> Optional[AlienReport]: ...
    def v_state_signal(self) -> Optional[VStateSignal]: ...  # V40 g(V) 信号
    def finish_reason(self) -> str: ...
```

**触发条件**（任一）：
- α 路径：用户说话，副脑判定 PASSIVE_REPLY → M3 调主脑 API 流式生成（mode="stream"）
- β 路径：副脑决策 FOLLOW_UP/CHECK_IN → M3 调主脑 API 预生成或流式生成（mode="stream" 或 "complete"）
- β 深度推理：副脑 confidence<θ_conf → M3 调主脑 API 思考模式（mode="thinking"）

**时延契约**：
- M3 调主脑 API 流式返回（α 路径，用户在等）
- 首 token 5s 未到 → α 路径降级（M2 用规则兜底占位"让我想想..."，主脑 API 后台继续）
- 思考模式调用是异步的（β 路径，不阻塞用户）
- α 路径**绝不调思考模式**（用户在等，5s 不可接受）

**α vs β 调用差异**：

| 维度 | α 路径 | β 路径 |
|------|--------|--------|
| mode | stream | complete（预生成）或 thinking（深度推理） |
| streaming | True（用户在等） | 预生成时 False，时机到播放时已合成完 |
| safety_mode | W_probe 输入检测实时判定 | normal（主动话语无输入异己风险） |
| identity_cache_snapshot | 透传 | 透传 |
| 超时 | 5s 无首 token 中断 | 思考模式 10s 降级 |

### 13.3 发 M6 BodyIntent（中耦合，异步）

**耦合密度**：中耦合（异步、非阻塞）。

**意图层级**（主文档 §5.5）：

```python
class BodyIntent(Enum):
    IDLE = "idle"
    LISTENING_POSE = "listening"    # α: 用户说话时
    SPEAKING_POSE = "speaking"      # 主脑生成时
    APPROACH_USER = "approach"      # β: 主动走向用户
    WAVE = "wave"                   # β: 挥手招呼
    NOD = "nod"                     # α: 倾听中点头
    CARE_GESTURE = "care"           # β: 主动关怀时
    THINKING_POSE = "thinking"      # 思考模式时
```

**副脑发 BodyIntent 的时机**：

| 路径 | 时机 | BodyIntent |
|------|------|-----------|
| α | 收到 SpeechStartEvent | LISTENING_POSE + NOD |
| α | 主脑开始生成 | SPEAKING_POSE |
| β | 决策 APPROACH_USER | APPROACH_USER（先行，到达后再开口） |
| β | 主动话语播放 | CARE_GESTURE |
| β 思考模式 | 思考模式调用 | THINKING_POSE |
| 任意 | 长时间无对话 | IDLE |

**身体动作与对话的时序编排**（主文档 §6.4）：副脑发 APPROACH_USER 后，等 M6 回执"到达"再触发主脑 API 生成，避免边走边说不自然。

### 14.1 TFGR 时间流图新角色：时间因果链累积载体（时间因果推理闭环升级）

引入 CausalPlan + PlanExecutor + 因果链回写（§10.5/§10.6/§10.7）后，TFGR 时间流图的角色再次升级——从"事件源 + 长期记忆"扩展为**时间因果链累积载体**：

| TFGR 时间流图角色 | 原版本（§14 表格） | 升级后（含时间因果推理闭环） |
|------------------|-------------------|---------------------------|
| 事件源 | proactive_traverser 候选遍历的事件来源 | 不变 |
| 长期记忆 | 节点势能=记忆重量，R(e)⁻¹ 进入动机公式 | 不变 |
| **时间因果链累积载体** | — | **新增**：每次 CausalPlan 完成后整条因果链作为复合事件节点回写图（§10.7），未来相似场景下被候选遍历检索到，让副脑基于历史因果链做更优决策而非从零推理 |

**新角色的资产映射**：

| 资产 | 升级前角色 | 升级后角色（时间因果推理闭环） |
|------|-----------|---------------------------|
| TFGR 时间流图 | M2 主动触发的事件源 + 长期记忆（节点势能=记忆重量） | **事件源 + 长期记忆 + 时间因果链累积载体**——新增 `add_causal_chain` 方法接收 CausalPlan 完成时的因果链回写（§10.7.2），回写的复合事件节点带 `type="causal_chain"`、`entertainment_value`、`success_score`、`importance`、`valence` 等属性，未来被 §8.2 候选遍历检索到，让 §6.6 无聊分支与 §10.5 reason step 直接命中历史因果链 |
| TFGR 阻力因子 R(e) | M2 记忆重量 + 主观时间压力——R(e)⁻¹ 进入动机公式维持性动机项 | 不变（R(e)⁻¹ 仍驱动维持性动机）；但回写的因果链节点也会被 R(e) 衰减——远期的成功因果链 R(e) 低，会被 FOLLOW_UP 候选遍历想起"上次这样做用户开心" |
| proactive_traverser | M2 候选事件遍历器（阶段1-3） | 不变（仍遍历候选）；但候选列表新增"causal_chain"类型节点（回写的因果链），让 §6.6 无聊分支可基于历史因果链的 entertainment_value/success_score 选择娱乐素材 |

**新角色的伪意识意义**：

时间因果链累积载体是伪意识"主观时间层"的真正用途——R(e) 不止进入动机公式（§6.5 维持性动机项），TFGR 时间流图也不止是事件源 + 长期记忆。它们共同承载**副脑经验的时间累积**：每次 CausalPlan 的"推理→执行→观察→调整"因果链沉淀为图节点，未来相似场景下副脑不再从零推理，而是基于历史因果链做更优决策。这是从开环（单次决策后遗忘）到闭环（决策结果回写记忆影响未来）的本质跃迁——让副脑的"经验"随时间在图中累积，而非每次都从空白开始。

**与既有资产的兼容性**：`add_causal_chain` 复用 `time_flow_graph.py` 的 `add_event` 机制（[time_flow_graph.py](file:///c:/Users/aodon/Desktop/基于时间流图的推理范式/tfgr_demo/time_flow_graph.py)），不修改既有节点结构，仅在节点属性中新增 `type="causal_chain"` 标识与 `entertainment_value`/`success_score` 字段。既有 R(e) 计算、proactive_traverser 候选遍历、事件状态推断（§7.4）均不受影响——回写的 causal_chain 节点作为普通事件节点参与这些既有机制。

### 15.3 降级策略（主文档 §8.1）

副脑降级遵循主文档 §8.1 的分级体系，并补充副脑专属降级：

| 降级级 | 触发 | 副脑行为 |
|--------|------|---------|
| L0 正常 | — | 全功能（双时钟 + 预计算 + 思考模式 + W_probe 守卫） |
| L1 GPU 忙 | α 与 β 抢副脑本地 GPU | β 预计算暂停；tick 频率降为 0.5Hz；α 的 W_probe 检测降频（每 32 token 一次而非 16） |
| L2 主脑 API 慢 | 首 token >2s | 跳过记忆检索，用最近 3 轮对话兜底；身份 prompt 精简 |
| L3 API 超时 | M3 >5s 无首 token | M2 用规则兜底占位"让我想想..."，主脑 API 后台继续或转备用模型；β 思考模式 10s 超时降级（§11 `_on_thinking_timeout`） |
| L4 多模态失效 | ASR/Vision 挂 | 降级为纯文本交互（无 presence/attention 门控） |
| L5 身体失效 | M6 通讯断 | 身体冻结，对话继续（不发 BodyIntent） |
| L6 副脑失效 | M2 崩溃 | 纯被动模式（用户输入→主脑 API 直连→输出，无主动、无身份守卫） |
| L7 主脑 API 不可用 | API 401/403/网络断 | M3 切备用 API（OpenAI↔DeepSeek 互备）；全断时副脑本地 Qwen2.5-3B 应急生成短回复（降级质量，但维持基本对话不中断） |

**副脑内部降级**（M2 自身未崩溃，但部分能力降级）：

| 内部降级 | 触发 | 行为 |
|---------|------|------|
| TFGR 图不可用 | 图服务挂 | 仅用物理时钟硬定时，无主观时间 |
| self_state 不可用 | 本地 forward 失败 | 用默认 energy=0.5, confidence=0.5, arousal=0.3, V_drift=0.0（动机生成层用默认内驱力降级运行） |
| V40 信号不可用 | g(V) 计算失败 | V_drift=0.0（动机公式减法项归零，不抑制主动）；仅用 W_probe 异己分数判定身份稳定性 |
| 预计算全失效 | 版本号频繁失效（α 频繁） | 跳过预计算，时机到现场生成 |
| M1 UserState 旧 | 3s 未更新 | 用 last_known，标记 stale |
| identity_cache 损坏 | norm 偏离 0.2271 过大 | 回滚到上次快照，停止回写 |

### 15.4 L6 看门狗与心跳

- M2 副脑每 1s 发心跳；3s 无心跳 → 触发 L6 降级
- L6 降级后：系统转入纯被动模式，用户仍可对话（α 路径主脑 API 直连，跳过副脑编排），但无主动发起能力、无身份守卫、无 W_probe 异己检测
- M6 控制环每 33ms 发心跳；100ms 无心跳 → 紧急制动（身体冻结）
- M3 主脑 API 调用超时（10s 无 token）→ 中断，回"我走神了，再说一次？"

### 15.5 资源隔离

| 资源 | α 路径 | β 路径 | γ 路径 |
|------|--------|--------|--------|
| GPU（副脑本地 forward） | 优先抢占 | 空闲时用（`gpu_low_priority_context()`） | 不用 |

## 17. 结论

模块2（副脑系统）是方向 C 架构反转后的脊梁，**承载伪意识——让 Lucy 成为独立个体的最强最像人的伪意识**。其核心贡献：

1. **副脑 = Qwen2.5-3B + V30 ckpt**（非纯规则器，亦非"规则器套皮"）：本地 GPU 跑轻量 forward（状态感知/异己检测/身份维持），不生成长文本；长文本生成交主脑 API（经 M3）。架构反转让 Qwen2.5-3B 专做它擅长的轻量 forward，主脑 API 专做它擅长的长文本生成。

2. **双触发机制**：α 事件触发（≤30ms 快速判定，绝不调思考模式）+ β 副脑主动触发（0.5-2Hz tick 循环，可预计算），α 到来时 β 作废，铁律 α 优先。

3. **伪意识架构（核心贡献）**：主动性来自**内在状态驱动**而非事件衰减退化的启发式规则链。self_state_predictor 的 V/PE/energy/confidence/arousal/V_drift 不是被读的字段（旧版 `c += 0.1 * energy` 的规则器套皮已删除），而是生成主动行为的**内驱力/动机源**。伪意识三支柱耦合驱动主动性：
   - **内在状态层**（§6）：energy/PE/arousal/V_drift 调制主动性的强度与方向。
   - **自我延续层**（§4/§5/§8.4）：identity_cache 14 条 EMA 是"近期自我形象"，W_probe 对主动行为做自我归属检查（§8.4，新增）——"有动机 + 像我"才发起。
   - **主观时间层**（§7）：R(e) 是"记忆重量 + 主观时间压力"，非纯事件状态判定；主观时间流速与物理时间分离（专注时少打断，无聊时多找事）。

4. **动机生成层（伪意识心脏，§6.5）**：动机公式 `motivation(e) = energy × R(e)⁻¹ × importance(e) + PE × relevance(e) + arousal × closeness(e) - V_drift × 2.0` 三类动机（维持性/探索性/关系性）+ 自我不稳定抑制。姿态决策不再是规则链（R(e)低→FOLLOW_UP），而是"取 max_motivation 对应候选事件与动机类型"，经阈值门控 + 动机类型→姿态映射 + 自我延续检查输出。动机生成 ~5ms，自我延续检查 ~10ms，对 β tick 80ms 预算可接受。

5. **双时钟时间感知（升级）**：物理时钟（单调时钟）驱动硬定时 + TFGR 阻力因子 R(e) 作为"记忆重量 + 主观时间压力"驱动动机生成。R(e)⁻¹ 进入维持性动机项——"远期 + 重要 + 能量足"才触发 FOLLOW_UP（非旧规则链的"R(e)低→FOLLOW_UP"表面相关性）。新增主观时间流速（§7.3）：专注时 θ_active 上调（少打断），无聊时下调（多找事）。

6. **身份维持新机制**：identity_cache（14条EMA, β=0.9）由副脑维持 + identity_projection（4.2M）本地 forward 注入 + M3 序列化进主脑 API system prompt + 生成后 EMA 回写（非权重学习）；同时作为"近期自我形象"供 §8.4 自我延续检查参照。

7. **异己检测 + 主动行为自我归属双重守卫**：W_probe（holdout acc=1.0）α 入口输入检测 + M3 生成后流式检测（副脑本地 forward 执行），阈值 θ_safety=0.0；**新增主动行为自我归属检查**（§8.4）——副脑主动发起前 W_probe 判定"这个行为像不像 Lucy 会做的"，与 identity_cache 不一致则降级 SILENCE。W_probe 从"被动的边界检查"升级为"主动的自我延续约束"。

8. **V40 温度约束 g(V) 转型**：从旧架构的"生成退化"转为副脑的"自我稳定性信号"——V_drift=1-g(V) 直接作为动机公式减法项 `- V_drift × 2.0` 抑制主动动机，自我不稳定时先稳定身份。这是伪意识"自我延续层"对"内在状态层"的反向耦合。

9. **proactive_traverser 降级为候选事件遍历器**：5 阶段推理链只执行阶段 1-3（场景识别→锚点定位→时间流回放候选遍历），阶段 4 姿态生成被动机驱动决策取代（§8.3）。姿态四值（FOLLOW_UP/CHECK_IN/SILENCE/PASSIVE_REPLY）保留为 ProactiveAttitude 枚举（数据契约不变），但决策来源从"规则优先级表"改为"动机类型映射"。副脑在候选遍历器外围加动机生成 + 阈值门控 + 自我延续检查 + tick 调度 + 双时钟融合 + 预计算编排 + 思考模式触发。

10. **深度推理经主脑 API 思考模式**：旧 M3 的"API 辅助思考"语义被吸收进主脑 API 调用（同一 API 不同 prompt），confidence<θ_conf 时 β 路径异步触发（2-10s），α 绝不调。confidence 现在反映"动机决策整体自洽度"（§8.5），非旧版规则置信度。

11. **TFGR 资产全面复用（伪意识化升级）**：identity_cache / identity_projection / W_probe / V32 Gram-Schmidt / V40 g(V) / self_state_predictor / TFGR 时间流图 / R(e) / proactive_traverser / v18 8阶段循环 全部在副脑侧发挥专长，且均经伪意识架构重新定位——self_state_predictor 从"被读信号"升级为"内驱力源"，V40 g(V) 从"身份状态信号"升级为"自我稳定性信号驱动动机"，R(e) 从"主观时间建模"升级为"记忆重量驱动动机"，proactive_traverser 从"规则基线"降级为"候选遍历器"，W_probe 从"异己检测"扩展为"异己检测 + 主动行为自我归属"。"之前做的那么多还有反思"全部用上，且用出了伪意识的味道。

12. **时间因果推理闭环（核心贡献，伪意识的时间维度）**：动机驱动决策环解决了"何时主动、主动什么"，但仍是开环单次决策——一个 tick 内完成"读状态→算动机→生成 DialogueIntent→调主脑 API→播放→结束"。用户的"放歌"场景指出其不足：副脑在"无聊"时应能跨时间多步推理——先想到"可以放首歌"（意图），再想"用户喜欢什么歌"（细节），再执行，再观察用户反应，再根据反应调整。本模块补强**时间因果推理闭环**，从开环到闭环的本质跃迁：
    - **§6.6 动机公式"无聊"分支修正**：energy 低 + presence 高 + silence 长触发**探索性娱乐动机**（`exploratory_play` 动机类型），不依赖 R(e) 衰减而是 `(1-energy) × entertainment_value` 的"找事做"驱动力；与 V_drift 互斥（自我不稳定时先稳定身份）。
    - **§10.5 CausalPlan 时间因果计划**：取代单次 DialogueIntent 的开环。一个 Plan 含多个 PlanStep（reason/act/observe/adjust），每个 step 有 precondition 依赖前一步结果。CausalPlan 是 DialogueIntent 的上层抽象（一个 Plan 可含多个 DialogueIntent），主文档 §5.3 数据契约保持兼容。
    - **§10.6 PlanExecutor 闭环执行器**：跨 tick 执行 reason→act→observe→adjust 循环。observe step 跨 tick 等待用户反应（不增加单 tick 预算，这是设计如此——观察需要时间但不能阻塞决策循环）；adjust step 根据观察结果修改后续步骤（如 negative_reaction → 插入 switch step）。
    - **§10.7 因果链回写 TFGR 图（闭环关键）**：每次 CausalPlan 完成（或中止），整条"推理→执行→观察→调整"因果链作为复合事件节点回写 TFGR 时间流图，带 `entertainment_value`/`success_score`/`importance` 属性。未来相似场景下被候选遍历检索到——下次无聊时副脑直接看到"上次放周杰伦的歌用户开心"，无需从零推理。
    - **§10.1 β tick 循环升级**：tick 流程改为"先检查 PlanExecutor 有无活动计划→有则推进/无则动机生成可能启动新 plan"。有活动 plan 时本 tick 不走动机生成路径，让 plan 跨 tick 推进。
    - **§8.3 动机驱动决策升级**：决策结果不再只是 DialogueIntent，可能是 CausalPlan（当 motivation_type == "exploratory_play" 时），交 PlanExecutor 跨 tick 执行。
    - **§14.1 TFGR 时间流图新角色**：从"事件源 + 长期记忆"扩展为**时间因果链累积载体**——伪意识"主观时间层"的真正用途。R(e) 不止进入动机公式，TFGR 时间流图也不止是事件源；它们共同承载副脑经验的时间累积，让"经验"随时间在图中沉淀而非每次从零开始。
    - **典型场景验证**：用户在场 + 长沉默 + energy 低 → 触发 exploratory_play → CausalPlan（goal="打发无聊时间"）→ step1 reason"可以放首歌"→ step2 reason 检索命中"用户喜欢周杰伦的歌"→ step3 act 播放周杰伦《晴天》→ step4 observe 检测到 positive_reaction → step5 adjust"认知更新"→ 因果链回写 TFGR 图 → 未来无聊时副脑直接命中历史因果链做更优决策。
    - **约束兼容**：α 路径不变（α 仍是单次快速响应，不涉及 CausalPlan）；α 到来时活动 plan 按 §10.4 规则中止或挂起（α 优先铁律不变）；DialogueIntent 仍是底层契约；时延预算保持（PlanExecutor 跨 tick，observe 等待不增加单 tick 预算）。

本模块严格对齐主文档的数据契约、时延预算、三路径分离原则与降级策略，是六大模块中耦合最广、时序最复杂的核心模块。**伪意识架构让副脑从"被读取的规则器套皮"升级为"内在状态驱动的伪意识心脏"——我们做不到真意识，但副脑的主动性来自 energy/PE/arousal/V_drift 生成的动机，而非事件衰减退化的启发式规则链。时间因果推理闭环进一步让副脑从"开环单次决策"升级为"跨 tick 闭环推理"——推理在时间流中展开，每步有依赖，闭环回写记忆，让副脑的"经验"随时间在 TFGR 图中累积。**
