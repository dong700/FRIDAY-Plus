### preload 的安全模型（这段是全项目最规范的一处）

```javascript
contextBridge.exposeInMainWorld('petAPI', {
  setHit: hit => ipcRenderer.send('pet:hit', hit),
  setBar: open => ipcRenderer.send('pet:bar', open),
  setHidden: hidden => ipcRenderer.send('pet:hide', hidden),
  dragStart: () => ipcRenderer.send('pet:drag-start'),
  dragMove: () => ipcRenderer.send('pet:drag-move'),
  dragEnd: () => ipcRenderer.send('pet:drag-end'),
  toggleSize: () => ipcRenderer.send('pet:toggle-size'),
  scale: v => ipcRenderer.send('pet:scale', v),
  moveTo: (x, y, seconds) => ipcRenderer.send('pet:move-to', x, y, seconds),
  stopService: () => ipcRenderer.invoke('pet:service-stop'),
  startService: () => ipcRenderer.invoke('pet:service-start'),
  quit: () => ipcRenderer.send('pet:quit'),
});
```

**白名单式 IPC**：渲染层拿不到 `require`，只能发这 12 个消息。`hit` 通道决定了"点击是否穿透到桌面"——这是透明桌宠的关键机制。

### 审查视角

1. **`startService` / `stopService` 直接换进程**。若 IPC 通道没有校验来源，页面里任何 XSS 都能停掉后端。而页面加载的是 `127.0.0.1:18080` 的 SPA + 外链 CDN（Live2D 两个 js），**CDN 被投毒 = 本地服务可控**。
2. **`moveTo(x, y, seconds)` 归一化坐标**，但没有范围校验（注释说 0–1）。传 `-5` 或 `99` 的行为取决于主进程实现。
3. `scale` 注释写 0.35–1.6，同样依赖主进程 clamp。
4. **两份前端**：改 UI 时不知道改哪份。`ui/` 是线上实际用的，`frontend/src` 是还原出来的、缺 `types.ts`/`index.css`/构建配置，**不可构建**。

```python
@app.api_route("/api/{path:path}", methods=["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"])
async def proxy_api(path: str, request: Request):
    headers = {k: v for k, v in request.headers.items()
               if k.lower() not in ("host", "content-length", "connection")}
    try:
        r = await _client.request(request.method, f"/api/{path}",
```

```python
@app.websocket("/ws")
async def ws_bridge(ws: WebSocket):
    await ws.accept()
    try:
        up = await websockets.connect(PRO_WS, max_size=None, ping_interval=30)
    except Exception as e:
        ...
        await ws.close(code=1013)

    async def client_to_pro():

            await up.send(msg)
    async def pro_to_client():

            await ws.send_text(msg)
    t1 = asyncio.create_task(client_to_pro())
    t2 = asyncio.create_task(pro_to_client())
    await asyncio.wait({t1, t2}, return_when=asyncio.FIRST_COMPLETED)
    ...cancel + close...
```

### 设计要点

- **单例 `httpx.AsyncClient`**：连接池复用，比每次新建快。
- **只透传 3 个响应头**：避免 hop-by-hop 头（`transfer-encoding` 等）破坏客户端。
- **WS 是裸 pump**：不做协议解析，一比一转发。任一方向断开就整体关闭（`FIRST_COMPLETED`）。
- **`/health` 会真的去探上游**，返回 `upstream_status`——比只回 `{"ok":true}` 有用。

### 审查视角

1. **`max_size=None`**：WS 帧无上限，客户端可以发 1 GB 帧打爆内存。
2. **无鉴权、无鉴源**：`127.0.0.1` 绑定降低风险，但任何本机进程（包括恶意网页的 DNS rebinding）都能调 `/api/workspace/execute`（见第 6 节）。
3. **`/api/{path:path}` 与 `/{page}` 路由冲突风险**：`/{page}` 里显式排除了 `ws` 和 `api*`，否则 FastAPI 的匹配顺序会让 `/api/xxx` 落到页面路由返回 404。
4. **没有超时**：`_client` 的 `timeout=30.0` 是总超时，但上游卡在下游等待时（比如 LLM 流式），WS 没超时机制——连接会一直挂着。
5. **502 的错误文案把内部异常直接拼进响应**（`f"...{e}"`），泄露内网地址/栈信息。

## 3. LLM 层：`brain/llm.py`

### 3.1 配置加载（单例的隐患）

```python
def __new__(cls):
    if cls._instance is None:
        cls._instance = super().__new__(cls)
        cls._instance._initialized = False
    return cls._instance

def __init__(self):
    if self._initialized:
        return
    self._initialized = True
    self._load_config()

def _load_config(self):
    from core.config import set_config, Config
    config_path = str(Path(__file__).parent.parent / "config" / "config.json")
    config = Config.from_file(config_path)
    set_config(config)          # ← 全局副作用
    self._client = AsyncOpenAI(api_key=config.llm.api_key, base_url=config.llm.base_url)
    self._model = config.llm.model
```

**`_load_config` 里调 `set_config`** 是隐蔽的全局副作用：谁先 new 了 LLM，谁就决定了全局配置。如果先 new 了别的东西再改配置，LLM 会用旧值。

### 3.2 关掉 thinking（延迟优化的关键一行）

```python
extra_body={"thinking": {"type": "disabled"}},
```

deepseek-flash 默认开思维链，对话生成会被 reasoning 吃掉 token。关掉后首字延迟显著下降。

### 3.3 流式

```python
stream = await self._client.chat.completions.create(
    model=self._model, messages=messages, stream=True,
    extra_body={"thinking": {"type": "disabled"}},
)
async for chunk in stream:
    choices = getattr(chunk, "choices", None)
    if not choices:
        continue
    delta = getattr(choices[0], "delta", None)
    text = getattr(delta, "content", None) if delta else None
    if text:
        yield text
```

`choices` 可能为空（有些 provider 的作用域 chunk），必须 `getattr` + 判空，否则首次流就崩。

### 3.4 Function Calling

```python
result = {"content": message.content or "", "tool_calls": [],
          "reasoning_content": getattr(message, "reasoning_content", None)}
if message.tool_calls:
    for tool_call in message.tool_calls:
        result["tool_calls"].append({
            "id": tool_call.id,
            "name": tool_call.function.name,
            "arguments": json.loads(tool_call.function.arguments or "{}"),
        })
```

### 审查视角

1. **`json.loads(tool_call.function.arguments)` 无 try**。模型输出 `{"x": 1,`（截断）时抛 `JSONDecodeError`，整个 tool call 崩溃 → 上层若没兜住，这轮对话失败。
2. **`max_tokens=2048` 默认值**，带思考时 reasoning 会吃光预算返回空正文（注释里承认过）。调用方必须显式给足。
3. **单例 + `_load_config` 在 `__init__`**：改配置后需要显式 `reload()`，但 `set_config` 已被调用两次（一次全局、一次 reload），容易不一致。
4. **`raise` 而非降级**：`chat()` 失败直接抛，上层 `handle_chat_send` 的宽 `except` 会回一条 `[错误] LLM调用失败`。用户看到的是技术错误而不是"我卡住了"。

```python
def sheet_context(max_age_s: float = 60.0) -> Dict[str, str]:
    s = latest_sheet(max_age_s)
    if not s:
        return {"b64": "", "meta": ""}
    t0, t1 = s.get("window", [0, 0])
    return {
        "b64": s["b64"],
        "meta": (f"最近 {s.get('span', 0):.1f} 秒的 {s.get('n', 0)} 帧桌面画面"
                 f"（九宫格按时间顺序排列，角标 #序号 +偏移秒；t0={t0:.0f}~t1={t1:.0f}）"),
    }
```

### 按需带图的三个开关（延迟设计）

```python
_SCREEN_KW = ("画面","屏幕","桌面","窗口","截图","九宫格","看到","图上","图里",
              "这个界面","我在干","在干嘛","在做什么","刚才那","监视","盯着")
_IMAGE_KW  = ("截图","画面","图上","图里","九宫格","这个界面","这个窗口",
              "长什么样","看这张","分析这张")
_want_screen = any(k in content for k in _SCREEN_KW)
_want_image  = any(k in content for k in _IMAGE_KW)
```

- `_want_screen` → 允许回答"我在干嘛"（用 ATG 文字，不出图）
- `_want_image` → 才真的附九宫格（多模态推理多 3–6 秒）

**这是性能设计伪装成功能设计**：两个开关名字看起来像功能判断，实际是为了省掉 3–6 秒。

### 审查视角

1. **`max_age_s=20`** 的帧可能还是"上一帧画面"——用户问"我现在在干嘛"，画面是他 19 秒前的状态。
2. **九宫格是"最近 N 帧"的拼图**，不带绝对时间，模型只能按角标算相对顺序。
3. **`b64` 直接塞 prompt**，base64 数据在内存里至少存两份（buffer + messages），大图时内存峰值明显。
4. **采集线程 + asyncio** 混用。`frame_pipeline` 里若有 `time.sleep` 而不是 `asyncio.sleep`，会拖慢主循环（见 07 文档）。

## 5. 工具层：`brain/tools.py`（1,439 行）

### 5.1 单例 + 延迟注册

```python
def _register_base_tools(self) -> None:
    self._tools = {
        "start_realtime_dialog": self.start_realtime_dialog,
        "send_message": self.send_message,
        "add_context": self.add_context,
        "save_memory": self.save_memory,
        "search_memory": self.search_memory,
        "memory_remember": self.memory_remember,
        "video_find": self.video_find,
        ...
        "pet_move": self.pet_move,
        "avatar_expression": self.avatar_expression,
    }

def _ensure_arm_tools_registered(self) -> None:
    if self._arm_tools_registered:
        return
    self._arm_tools_registered = True
    if self.is_arm_available():
        self._tools.update({...arm_*...})
        logger.info("[BrainTools] 机械臂工具已注册")
    else:
        logger.info("[BrainTools] 机械臂不可用，跳过注册 arm_* 工具")
```

**机械臂工具栏是延迟注册的**：没硬件就不注册，模型看不到 `arm_*` 工具，自然不会乱调。日志里那句"机械臂不可用，跳过注册"每次启动都有。

### 5.2 工具定义的两种来源

- `get_tool_definitions()` → OpenAI function schema（给 LLM 的 `tools=`）
- `self._tools[name]` → 实际可调用对象（executor 用）

两者必须同步：schema 里有的名字，`_tools` 里必须能取到，否则 `tool_calls` 回来时 `KeyError`。

### 审查视角

1. **`_ensure_arm_tools_registered` 只跑一次**。硬件热插拔（先启动后插 USB）后工具永远不会注册，除非重启。
2. **1,439 行一个类**。新增工具要改 3 处（注册表、方法、schema），漏一处就是运行时错。
3. **工具方法直接 `await` 硬件**，没有统一超时。串口卡住会挂住整轮对话。
4. **`get_brain_tools()` 若在 import 期被调用**，会触发硬件探测（串口枚举），拖慢启动。

## 6. 工作区执行：`brain/workspace.py`（最危险的一段）

### 6.1 所谓"安全检查"

```python
DANGEROUS_PATTERNS = [
    "rm -rf /", "format ", "mkfs", "shutdown", "reboot", "init 0", "init 6",
    ":(){:|:&};:", "dev/null", "> /etc/", "chmod 777 /",
    "curl.*|.*sh", "wget.*|.*sh",
]

def _check_safety(self, content: str) -> tuple[bool, str]:
    content_lower = content.lower()
    for pattern in DANGEROUS_PATTERNS:
        if pattern.lower() in content_lower:
            return False, f"安全限制：检测到危险操作 '{pattern}'"
    if len(content) > MAX_SCRIPT_SIZE:
        return False, f"脚本过大：{len(content)} > {MAX_SCRIPT_SIZE} 字节"
    return True, ""
```

### 这段代码的问题（面试级样本）

| 问题 | 说明 |
|---|---|
| **`"curl.*|.*sh"` 是字面量不是正则** | `in` 做子串匹配，`curl.*|.*sh` 这串字面量几乎不可能出现在脚本里 → **这条规则 100% 失效** |
| **黑名单天然漏** | `rm -rf /tmp`（不加空格）、`rm -fr /`、`Remove-Item -Recurse -Force C:\`、`os.remove` 全都不在表里 |
| **只查内容不查意图** | 任何 Python 脚本天然能 `subprocess.run(["rm","-rf","/"], shell=False)`，黑名单查不到 |
| **`"format "` 带空格** | `format(c)` 这种正常的 Python 字符串格式化会被误杀（只要后面有空格） |
| **`"dev/null"` 被禁** | 正常的 `> /dev/null` 重定向（无害）被拦，说明规则是"抄来的" |
| **PowerShell 完全不覆盖** | 项目明明支持 `.ps1`，但黑名单里没有一条 PS 语法 |

### 6.2 执行

```python
process = await asyncio.create_subprocess_exec(
    *cmd,
    stdout=asyncio.subprocess.PIPE,
    stderr=asyncio.subprocess.PIPE,
    cwd=cwd,
    env={**os.environ, "PYTHONUNBUFFERED": "1", "PYTHONIOENCODING": "utf-8"},
    creationflags=create_flags,
)
stdout_bytes, stderr_bytes = await asyncio.wait_for(process.communicate(), timeout=timeout)
```

- `create_subprocess_exec`（不是 `shell=True`）+ 参数列表 → 避免了命令注入
- `wait_for` + `process.kill()` → 有超时
- `CREATE_NO_WINDOW` → 不弹黑框
- `_smart_decode`：UTF-8 → GBK → Latin-1 三级兜底

### 审查视角

1. **`os.environ` 全量透传**：API key（`config.json` 里的）如果以环境变量注入，子进程全拿得到。
2. **`cwd=self.root`**，但脚本可以通过 `..` 访问任意路径（cwd 不是沙箱）。
3. **无网络隔离、无文件系统隔离、无资源限制**（CPU/内存）。
4. **`process.kill()` 只杀父进程**，脚本 `subprocess.Popen` 出来的子进程会成为孤儿继续跑。
5. **HTTP 端点 `/api/workspace/execute` 无鉴权** → 本机任意进程可 RCE（以运行后端用户的权限）。

## 7. 任务执行器与内在动机

| 组件 | 作用 | 关键风险 |
|---|---|---|
| `task_executor.py` | 异步队列（concurrency=1、queue_size=50、优先级、重试） | 单并发 → 长任务堵住后续；队列满时的丢弃策略未定义 |
| `intrinsic_reward.py` | 好奇心/探索/学习进度三值 + 自我更新 | 数值只用于显示，不影响决策；"学习进度"无真实数据源 |
| `unified_brain.py` | B 路线空壳（日志："UnifiedBrain shell initialized (B-route: no direct connection)"） | 名字暗示统一大脑，实际不接线，容易误导 |

### 审查视角

1. **`concurrency=1`**：一个跑 60 秒的视频任务会阻塞所有后续任务，用户以为"它不理我了"。
2. **`queue_size=50` 满时**：看实现是丢弃还是阻塞。若阻塞，`put` 在事件循环里等 → 卡死。
3. **`intrinsic_reward` 的 `SelfUpdateModule`** 名字很危险，实际只是调参；没有任何自修改代码路径（这是好事，但名字误导）。

## 8. 前端两套并存的现实

| | `ui/*.html` | `backend/frontend` |
|---|---|---|
| 形态 | 4 个单文件（65–85 KB），内联 CSS/JS | React + Vite，`dist/` 有产物 |
| 可否构建 | 不需要 | **不能**：缺 `types.ts`、`index.css`、`package.json`、`vite.config.ts`、`tsconfig`、`tailwind.config`、`index.html` |
| 谁在用 | 根 `server.py`（18090） | 18080 的 SPA（桌宠加载的就是它） |
| 改哪里 | 直接编辑 HTML | 改 `src/` 后**无法重新构建**，只能改 `dist/` 里的压缩产物 |

`backend/frontend/src/` 里有 17 个从 sourcemap 还原的 `.tsx/.ts`（`App.tsx`、`PetMode.tsx`、`useLive2D.ts` 等），可读但不可编译。

### 审查视角

1. **两套前端都在跑**，UI 改动不同步 → 控制台和桌宠行为不一致。
2. **`dist/` 是唯一可部署产物**，但源码不可构建 → 任何前端改动都是"改压缩代码"，下次谁再 `npm run build` 就全部丢失。
3. **`ui/` 四个单页各 65–85 KB**，Tailwind/CDN 全部内联或外链，首屏依赖外网（Live2D CDN 挂了桌宠立绘就没了）。
4. **`<title>Active AI Pro</title>`** 还留在 `dist/index.html` 里，品牌没改干净。
