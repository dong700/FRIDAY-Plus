# 源码解析 02：记忆与心智（TFGR / Mind / ATG / OpenViking）

> 这是项目的技术含量所在。四套结构分工明确，**不是互相替代，而是不同时间尺度**：

| 结构 | 尺度 | 存什么 | 谁写 | 谁读 |
|---|---|---|---|---|
| `chat_history.json` | 分钟级 | 原话 | `_save_chat_message` | 上下文、复读闸门 |
| **ATG** | 小时级（区间） | "9:20–12:00 在写报告" | 视觉/前台/文本 | prompt 的【屏幕观察】 |
| **TFGR** | 天级（点 + 计划） | 事实/推断/故事/意图/模式/提醒 | 对话 + 模型 `<memory>` | `digest` 注入、`due` 叫醒 |
| **OpenViking** | 月级（语义） | 上述内容的向量索引 | `sync_tfgr` | `find` 语义召回 |

## 1. TFGR 数据模型

```python
@dataclass
class TFEvent:
    id: str
    ts: float
    kind: str                       # memory / belief / story / intent / pattern / event ...
    text: str
    source: str = "system"
    end_ts: Optional[float] = None  # 区间事件（ATG 沉淀）才有
    entities: List[str] = field(default_factory=list)
    refs: List[str] = field(default_factory=list)
    meta: Dict[str, Any] = field(default_factory=dict)
    confidence: float = 1.0
    basis: List[str] = field(default_factory=list)
```

```python
MENTAL_KINDS = ("belief", "story", "intent", "pattern")   # 模型推断出来的
USER_KINDS   = ("memory",)                                 # 用户明确让记的

KIND_WEIGHT = { ... }                      # 每类的基础权重
MENTAL_HALF_LIFE_DAYS = float(os.getenv("FRIDAY_MEM_HALF_LIFE", "14"))
PIN_BOOST    = 1.00    # 明确要求「记住这个」
DUE_BOOST    = 1.50    # 有明确时间点
NEGATE_FACTOR = 0.55   # 被用户否定过，重要度打折
```

**`MENTAL_KINDS` vs `USER_KINDS` 的分界是整套系统的伦理底线**：模型自己推的（belief/intent）永远标"我推断"，用户说的（memory）标"他让记"。注入时标签不同，清理时保护级别不同。

`meta` 里会被写入的键（全是隐式约定，没有 schema）：

| 键 | 写入点 | 含义 |
|---|---|---|
| `pin` | `remember` | 钉住，清理时保护 |
| `due_at` | `remember` | 到点时间戳 |
| `done` / `done_at` / `done_note` | `mark_done` | 提醒已处理 |
| `last_hit` | `touch` | 最近被注入，衰减起点 |
| `last_inject` | `digest` | 最近注入，供粘性 + 负反馈定位 |
| `negated` | `penalize_recent` | 被否定过的时间戳 |
| `deleted` | `delete` | 软删除 |

## 2. `importance`：一条记忆值不值得被想起（423–444）

```python
def importance(self, e: TFEvent, now: Optional[float] = None) -> float:
    now_ts = now or time.time()
    score = KIND_WEIGHT.get(e.kind, 0.35)
    score += 0.25 * min(1.0, max(0.0, float(e.confidence)))
    if e.entities:
        score += min(0.15, 0.05 * len(e.entities))
    if e.meta.get("pin"):
        score += PIN_BOOST
    if e.meta.get("due_at"):
        score += DUE_BOOST
    last = float(e.meta.get("last_hit") or e.ts)
    age_days = max(0.0, (now_ts - last) / 86400.0)
    score *= 0.5 ** (age_days / max(1.0, MENTAL_HALF_LIFE_DAYS))
    if e.meta.get("negated"):
        score *= NEGATE_FACTOR
    return round(score, 3)
```

### 计分顺序为什么不能换

1. **先加后乘**：pin / due 是"绝对加成"，衰减是"整体打折"。先乘后加会让一条 3 年前的提醒永远排第一。
2. **衰减起点是 `last_hit` 不是 `ts`**：被反复用到的记忆衰减慢，这是"常用即重要"的工程近似。
3. **否定系数最后乘**：确保被否定的即使 pin 了也会降级（0.55 足够把它压到同批之下，但不会消失）。

### 数值感受（14 天半衰期）

| 场景 | 分数 |
|---|---|
| 用户让记、置信 1.0、1 个实体、3 天前 | 0.9(kind) + 0.25 + 0.05 + 1.0 = 2.2 → ×0.5^(3/14)=0.86 → **1.89** |
| 模型推断 belief、置信 0.6、今天 | 0.6 + 0.15 = 0.75 → **0.75** |
| 同上，但被否定过 | 0.75 × 0.55 = **0.41** |
| 一条普通 event、30 天前 | 0.4 × 0.5^(30/14)=0.23 → **0.09** |

### 审查视角

1. **`last_hit` 只在 `digest` 里被 `touch` 更新**。也就是说"被注入"就算"被用到"——哪怕模型根本没引用它。这会让注入次数多的记忆自我强化（富者愈富）。
2. **`e.confidence` 没有下限校验**。`penalize_recent` 里做了 `max(0.1, ...)`，但模型写 `<memory confidence=-1>` 会直接进库，`importance` 里被 `max(0.0, ...)` 兜住，不崩但语义脏。
3. **`round(score, 3)` 在排序时会产生大量并列**，`digest` 的 `_rank` 用 `-ts` 和 `id` 兜底，所以结果稳定但**时间序压过了语义**。

## 3. `digest`：注入用的长期记忆摘要（590–682）

```python
def digest(self, max_items: int = 8, max_chars: int = 1200,
           now: Optional[float] = None, query: str = "",
           exclude_texts: Optional[List[str]] = None) -> str:
    now_ts = now or time.time()
    query = (query or "").strip()
    excluded = [_norm(x) for x in (exclude_texts or []) if (x or "").strip()]
    with self._lock:
        items = [e for e in self._events if not e.meta.get("deleted")]
    if not items:
        return ""

    picked: List[TFEvent] = []
    seen = set()
    shown: List[str] = list(excluded)

    def take(ev: TFEvent, dedup: bool = False) -> None:
        if ev.id in seen or len(picked) >= max_items:
            return
        body = _norm(ev.text)
        if dedup and _near_dup(body, shown):
            return
        seen.add(ev.id)
        picked.append(ev)
        shown.append(body)

    def _score(ev: TFEvent) -> float:
        score = self.importance(ev, now_ts)
        if query:
            score += 0.6 * _query_overlap(query, ev.text)
        last_inj = float(ev.meta.get("last_inject") or 0)
        if now_ts - last_inj <= INJECT_STICKY_S:
            score += STICKY_BOOST
        return score

    def _rank(ev: TFEvent):
        return (-_score(ev), -ev.ts, ev.id)

    # 1) 到点/快到的提醒（最重要，不参与去重）
    for e in self.due(window_s=DUE_LEAD_S, now=now_ts):
        take(e)
    # 2) 带明确时间点的计划
    for e in sorted([x for x in items if x.meta.get("due_at") and not x.meta.get("done")],
                    key=lambda x: float(x.meta["due_at"])):
        take(e)
    # 3) 用户明确让记的事
    for e in sorted([x for x in items if x.kind in USER_KINDS], key=_rank):
        take(e)
    # 4) 钉住的推断（和 OpenViking 已展示过的去重）
    for e in sorted([x for x in items if x.meta.get("pin") and x.kind not in USER_KINDS],
                    key=_rank):
        take(e, dedup=True)
    # 5) 余下的推断
    for e in sorted([x for x in items if x.kind in MENTAL_KINDS], key=_rank):
        take(e, dedup=True)

    lines: List[str] = []
    used = 0
    for e in picked:
        self.touch(e.id, now_ts)
        if e.kind in MENTAL_KINDS:
            e.meta["last_inject"] = now_ts
        ...
        src = "他让记" if e.kind in USER_KINDS else "我推断"
        line = f"{due_txt}{src}·{when}: {e.text[:90]}"
        if lines and used + len(line) > max_chars:
            break
        lines.append(line)
        used += len(line)
    return "\n".join(lines)
```

### 五层漏斗的设计意图

```
层1 到点提醒     ← 宁可重复，不可漏（不参与 dedup）
层2 带时间的计划 ← 按时间先后，不按重要度（未来越近越先）
层3 用户让记的   ← 用户权威 > 模型推断
层4 钉住的推断   ← 参与跨来源去重（OV 已展示就不重复）
层5 其余推断     ← 重要度 + query 相关 + 粘性
```

**注意层 1、2、3 都不参与 `dedup`**（`take(e)` 不带 `dedup=True`）。这是刻意的：重复总比漏掉好，而推断重复才是噪音。

### 打分三件套

| 项 | 作用 | 缺陷 |
|---|---|---|
| `importance` | 底分 | 见上一节 |
| `+0.6 × _query_overlap` | 和当前这句话相关 | 纯字面重合，同义改述命中不了 |
| `+STICKY_BOOST`（10 分钟内注入过） | 防两条相近推断每轮互换 | 会让"空转记忆"赖着不走 |

### 输出格式

```
【已到点】他让记·1天前: 交房租
【还有2天】我推断·3天前: 他大概在赶项目，周末也没休
他让记·5天前: 我不吃辣
```

`【已到点】/【还有N小时】/【还有N天】` 前缀让模型可以直接引用时间，不用自己算。

### 审查视角

1. **`max_chars` 只对 `lines` 累加，`take` 阶段不知道长度**。10 条 90 字的记忆 = 900+ 字符，可能超预算；`break` 后 `picked` 里剩余条目的 `touch` 和 `last_inject` **已经被写了**（循环在写之前就 break 了吗？——不，`touch` 在 `if lines and used + len(line) > max_chars: break` **之前**执行）。结果是：**没被注入的记忆被标记为"刚注入过"**，下一轮粘性加成，进一步挤占预算。
2. **全表遍历**：每次对话都遍历 800+ 事件，`importance` 里还有 `float()` 转换。800 条 × 每轮 = 可接受，但 10 万条时会明显卡。
3. **`due(window_s=DUE_LEAD_S)` 在锁外调用 `due()`（内部再拿锁）**，两次加锁之间状态可变，极端情况下同一条被 take 两次（有 `seen` 兜住，不重复，但计数会偏）。
4. **`_query_overlap` 对中文按单字**，"我"、"的"这种高频字会虚抬所有记忆的相关度。应该用 2-gram 或停用词表。

## 4. 提醒的完整生命周期

```
用户："10天后提醒我交报告"
  │
  ├─ _parse_reminder → {text, due_at=now+10d}
  ├─ tfgr.remember(text, due_at, source="chat")
  │     └─ meta = {pin: True, due_at: ...}
  │     └─ 同文去重：已存在未完成且 due 布尔相同 → 更新而不是追加
  │
  ├─ 每轮对话：digest 层1/2 带上它（带【还有N天】）
  │
  ├─ Mind._next_timeout：due_next_ts → sleep 到那一刻
  ├─ Mind._select_trigger：due() 命中 → Trigger("到点提醒：...")
  │     └─ 6 小时内不重复提醒（_due_notified）
  │
  ├─ 说出口后两条关闭路径：
  │     ① Mind：mark_done("mind_say")
  │     ② 对话回复命中：_reply_mentions ≥ 0.4 → mark_done("chat_reply")
  │
  └─ mark_done 后：不再进 due()，但记录保留（事后可查）
```

### 源码：`remember` 的去重分支（528–556）

```python
# 同一件事说两遍只留一条（重复的提醒会让「到点提醒」刷屏）
body_norm = _norm(body)
with self._lock:
    for e in self._events:
        if e.meta.get("deleted") or e.meta.get("done"):
            continue
        if bool(e.meta.get("due_at")) != bool(due_ts):
            continue
        ...
```

`bool(due_at)` 比较是精髓：**"有时间的"和"没时间的"永远算两条**。所以"提醒我交报告"+"明天提醒我交报告"会并存（前者 pin、后者定时），这符合直觉。

### 审查视角

1. **关闭路径 ② 的 40% 阈值太松**（见 01 文档第 9 节）。误标为 done 后，用户再也不会被提醒——**这是最严重的记忆 bug 类型：静默丢失**。
2. **`mark_done` 只写 `meta`，不删记录**。`digest` 层 4/5 仍可能把它当普通推断注入（因为它 `kind` 是 `memory`，进层 3）。所以"已完成"的提醒还会出现在 prompt 里，模型可能又问一遍。层 3 没有过滤 `done`。
3. **`due()` 的 `window_s=DUE_LEAD_S`**（提前量），意味着"还有 30 分钟"就进层 1 标【已到点】——只要 `due_at <= now + window`。文案和事实不符。
4. **`_due_notified` 只存在内存**，重启后 6 小时窗口清零 → 重启会立刻再提醒一次。

## 5. 负反馈：`penalize_recent`（463–496）

```python
def penalize_recent(self, user_text: str, window_s: float = 1800,
                    max_items: int = 3, factor: float = 0.6,
                    now: Optional[float] = None) -> List[str]:
    text = (user_text or "").strip()
    if not text:
        return []
    explicit = bool(NEGATION_RE.search(text))
    now_ts = now or time.time()
    changed: List[str] = []
    with self._lock:
        cands = [
            e for e in self._events
            if e.kind in MENTAL_KINDS and not e.meta.get("deleted")
            and now_ts - float(e.meta.get("last_inject") or 0) <= window_s
        ]
        if not cands:
            return []
        cands.sort(key=lambda e: -float(e.meta.get("last_inject") or 0))
        hit = [e for e in cands if _query_overlap(text, e.text) >= 0.3]
        target = hit[:max_items] if hit else (cands[:2] if explicit else [])
        for e in target:
            e.confidence = max(0.1, round(float(e.confidence) * factor, 2))
            e.meta["negated"] = now_ts
            changed.append(e.id)
        if changed:
            self._persist()
    return changed
```

### 三种情况（代码里写得很清楚）

| 用户说的 | 行为 | 原因 |
|---|---|---|
| "不是这样，我是说周三" （有字面重合） | 只罚重合度 ≥0.3 的，最多 3 条 | 精准 |
| "你记错了 / 我没说过"（显式否定但无重合） | 罚最近注入的 2 条 | 有指向但没具体内容 |
| "不对"（泛否定） | **不动** | 避免误伤（"不对，是 3 点不是 4 点"会错杀别的） |

### 审查视角

1. **`NEGATION_RE` 是关键词正则**。"不对"在中文里既可否定也可转折（"不对，你刚才说的那个挺好"），误判会永久降权正确记忆。
2. **降权是永久的**（`negated` 只写不删，`confidence × 0.6` 每次累乘）。用户三次说"不是"，一条真事实就变 0.1，再也浮不上来。**没有"重新确认后恢复"的路径**。
3. **`window_s=1800` 依赖 `last_inject`**，而 `last_inject` 只在 `digest` 里写。如果这一轮走的是"OV 命中"而不是 digest，推断没被标注入 → 用户否定时找不到候选 → 负反馈静默失效。
4. **`cands[:2]` 可能罚错**。用户说"你记错了"时，最近注入的 2 条可能一条都不相关。

## 6. 整理与清理：`consolidate` / `prune`

```python
# consolidate（684+）
# 1) 7 天内高度相似（difflib ≥ 0.9）的推断合并到更早那条，置信度取 max
# 2) 48 小时后的推断才参与合并（新鲜的不动，避免刚说的两句话被合并）
# 3) 带 due_at 的计划一条都不合（不同时间点是两件事）
# 4) 用户让记的（USER_KINDS）不合并
```

```python
# prune（731+）
# 保护：pin / due_at / USER_KINDS
# 淘汰：超过 TTL 且 importance 低于阈值的推断
# 软删除：meta["deleted"]=True，不物理删（可回溯）
```

### 审查视角

1. **`consolidate` 是 O(n²)**，800 条 = 32 万次 `difflib`，实测会卡 2–5 秒。它被谁调用？如果挂在定时任务里且在主线程，会周期性卡顿。
2. **合并后的 `text` 取更早那条**，可能丢掉后来补充的细节。没有"合并摘要"。
3. **`prune` 只看 importance，不看"是否被用户问过"**。一条从没被注入但很旧的推断会被清掉——合理；但一条被注入 50 次、每次都被无视的也会被清掉——也合理。问题在于 `touch` 把"注入"当"使用"，导致**被无视的记忆反而不被清理**。
4. 全部 `_persist()` 是**全量重写 JSONL**（见 01 文档的同步 I/O 问题）。

## 7. Mind：什么时候该说话

### 7.1 事件模型

```
Event    : kind + text + source            （发生了什么）
Hook     : kind(at/idle/on) + due + match + note   （什么条件下醒来）
Trigger  : reason + refs                   （这次为什么醒）
HookSpec : 模型写在回复里的 <<...>> 解析结果
```

`Mind` 是一个 `while True` 的事件循环：`_next_timeout()` 算睡多久 → 醒 → `_select_trigger()` 挑一个理由 → `_think()` 生成 → `_should_speak()` 五道闸 → 说。

### 7.2 `_next_timeout`（1009–1028）

```python
def _next_timeout(self) -> float:
    now = time.time()
    deadlines = []
    with self._lock:
        for h in self._hooks:
            if h.kind == "at":
                deadlines.append(h.due - now)
            elif h.kind == "idle":
                deadlines.append((self._last_activity + h.due) - now)
    try:
        from brain.tfgr import get_tfgr
        due_ts = get_tfgr().due_next_ts(now=now)
        if due_ts:
            deadlines.append(due_ts - now)
    except Exception:
        pass
    if deadlines:
        return min(self.IDLE_WAKE, max(0.5, min(deadlines)))
    return self.IDLE_WAKE
```

**三个下限保护**：`max(0.5, ...)` 防忙等（过期钩子返回负数）；`min(IDLE_WAKE, ...)` 防睡太久错过事件；`IDLE_WAKE` 兜底轮询。

### 7.3 `_select_trigger`（1030–1069）

优先级：**到点提醒 > 到期钩子 > 事件钩子 > 有 pending 事件 > None**。

关键在 `_due_notified`：

### 7.4 `_should_speak`：五道闸（808–839）

```python
def _should_speak(self, text: str, trigger: "Trigger") -> Tuple[bool, str]:
    if not text:
        return False, "空"
    if _is_meta_silence(text):
        return False, "旁白式沉默（不想说就该真的输出空）"
    for prev in reversed(self._recent_says):
        if _too_similar(text, prev):
            return False, f"和上一句太像：{prev[:24]}"

    reason = (trigger.reason or "").lower()
    user_initiated = any(k in reason for k in ("用户", "对话", "回答", "chat"))
    if self._ignored_streak >= 2 and not user_initiated:
        return False, "连着两次主动说话都没被回应，先等用户开口"

    is_question = ("？" in text) or ("?" in text)
    if is_question and self._last_say_question and not user_initiated:
        return False, "上一句已经在问了，别再追问同一个事"

    if not user_initiated:
        kind, proc, title = self._focus_now()
        if kind == "work":
            return False, f"他在工作软件里（{proc or title[:12]}），先不打断"
    return True, "ok"
```

| 闸 | 拦截什么 | 用户原话对应 |
|---|---|---|
| 1 空文本 | 输出空 | — |
| 2 旁白式沉默 | `（不打扰）` 这种"假装沉默" | "不想说就别说，别发括号" |
| 3 太像 | 换说法复读 | "别复读" |
| 4 连续两次没回应 | 自嗨追问 | "别抢麦" |
| 5 重复提问 + 工作软件 | 打断写代码 | "我在忙别烦我" |

### 7.5 压话机制

工作软件里想说不能说 → `_defer_say` 存进 `_deferred` + 挂一个 `on=work.end` 钩子。退出工作态时 `work.end` 事件唤醒，再判断要不要说。

### 审查视角

1. **`_is_meta_silence` 是正则匹配**，模型用别的括号写法（`[沉默]`、`*安静*`）就漏。这是"靠字符串约定约束模型"的通病。
2. **`_too_similar` 阈值 0.62/2-gram 0.55**，同义改述（"在忙吗" vs "忙不忙"）抓不到。
3. **`_ignored_streak` 只有 `note_user_message` 重置**，语义事件（比如用户点了表情）不解。用户在看但不打字，会被当成"无视"。
4. **`_focus_now()` 每轮调 `sense()`**，`_watch_foreground` 另外每 6 秒调一次，两处轮询没共享缓存。
5. **`_deferred` 无上限**。用户连续工作 8 小时、模型每小时想说一句，退出时一次全判断——可能连发多条。

## 8. ATG：活动时序图

### 8.1 节点与边

```python
@dataclass
class ActivityNode:
    id: str
    description: str          # "在写代码"（具体描述，不分类）
    task_context: str = ""    # "实现登录功能"（稳定任务层）
    owner: str = "user"
    t_start: float = 0.0
    t_end: Optional[float] = None      # None = 进行中
    status: ActivityStatus = ActivityStatus.ONGOING
    interrupt_by: Optional[str] = None # 被谁打断
    resume_of: Optional[str] = None    # 恢复自谁
    context_snapshot: str = ""         # 打断时的上下文（目标记忆）
    entities: List[str] = field(default_factory=list)
    related_facts: List[str] = field(default_factory=list)
    source: str = "unknown"
    confidence: float = 0.5
    expected_duration_s: float = 1800.0
```

边类型（Allen 区间代数 + 中断恢复）：

```
BEFORE / OVERLAPS / CONTAINS / INTERRUPT / RESUME / ENABLE / PRODUCE / INSTANCE_OF / CAUSAL
```

### 8.2 增量观察（`observe_activity`）

新信号到达时：

```
与现有 ongoing 比较：
  描述相似 + 时间连续  → 合并（延长 t_end）
  描述不同 + 时间重叠  → OVERLAPS 边（并发）
  描述不同 + 看着像打断 → 旧活动 PAUSED，新活动 INTERRUPT 边
检查 paused：
  信号暗示恢复 → RESUME 边，旧活动 RESUMED
```

阈值：

```python
self.merge_similarity_threshold = 0.6    # 描述相似度 > 0.6 → 合并
self.interrupt_gap_threshold = 30.0      # 间隔 > 30s 且描述不同 → 可能中断
self.auto_complete_timeout_s = 120.0     # 120s 无更新 → 自动完成
self.vision_debounce_window_s = 15.0     # 视觉去抖窗口
```

### 8.3 纠错（`apply_correction`）

用户说"那不是自拍" → `apply_correction("自拍", corrected_to="在玩手机", suppress_s=600)`：

- 记录 `{term, corrected_to, until, note}`
- 抑制期内，命中 `term` 的描述被重命名或抑制
- 序列化时附澄清说明

**这是"语言对视觉的 top-down 修正"**，是整个项目里少见的、有认知科学依据的机制。

### 审查视角

1. **`merge_similarity_threshold=0.6` 用的是字面相似度**，"在写代码" 和 "在调试代码" 相似度约 0.5 → 不合并，产生两个碎片活动。
2. **`auto_complete_timeout_s=120` 太短**。用户静坐看代码 10 分钟不切窗，活动会被"自动完成"，然后下一帧又开一个新活动 → 一天下来 50 个"在用电脑"节点。
3. **`vision_debounce_window_s` 曾经漏定义**（代码注释里记了这次事故：每次视觉场景都抛 `AttributeError`，去抖从未生效，静态画面被切成碎片链 → 幻觉）。这是"构造函数漏字段"的经典事故。
4. **`corrections` 只是内存列表**，重启全丢。用户纠正过的错误认知第二天会复活。
5. **`owner` 字段默认 `"user"`**，多用户场景下没有隔离校验，A 的活动可能被当成 B 的。

## 9. OpenViking：语义检索与沉淀

### 9.1 `find`（99+）

```
query → Ollama 本地 embedding（nomic-embed-text，768 维）→ OV 向量检索
      → 取 topK → 字面重排（避免 embedding 在中文短句上的不稳定）
      → 返回 [{text, uri, score}]
```

### 9.2 `sync_tfgr`（175+）：两级沉淀

```
重要节点（pin/due/高重要度）  → 单条写入 OV（/mem/<id>.md）
同一类的其余节点              → 按天汇总（/tfgr/<YYYY-MM-DD>.md）
断点：ov_sync.json 记录已同步的 id / 日期，避免重复
```

两级设计的原因：单条保证精确召回，按天汇总保证"整体印象"能被检索到。

### 审查视角

1. **OV 挂了对话仍能进行**（`find` 异常被 catch），但注入质量静默下降，用户只感觉"它变笨了"。
2. **`sync_tfgr` 是全量覆盖还是增量？** 代码用 `ov_sync.json` 做断点，但当天汇总是**重写整篇**——意味着当天晚些时候的同步会覆盖早上的内容，如果拼接逻辑有 bug 就会丢。
3. **URI 是 `_ov_label` 的唯一信息源**，格式耦合（见 01 文档第 8 节）。
4. **embedding 维度写死 768**。换模型（比如换成 1024 维）需要重建索引，没有版本字段。

## 10. 一次"记忆注入"的完整时序（把上面串起来）

```
用户："我昨天说的那个报告，你还记得吗"
  │
  ├─ penalize_recent："报告" 和最近注入的推断重合？→ 可能降权（误伤风险）
  ├─ _parse_reminder：无触发词 → 不记
  ├─ _brain_quick_decide：短句 + 无搜索线索 → 快速跳过
  │
  ├─ ov_memory.find("我昨天说的那个报告") 
  │     └─ 命中 /mem/xxx.md 和 /tfgr/2026-11-10.md
  │     └─ _ov_label → "[11-10 当天汇总]" "[11-09 他让记]"
  │
  ├─ tfgr.digest(query="我昨天说的那个报告", max_items=10,
  │              exclude_texts=[OV 已展示的])
  │     ├─ 层1 due：无
  │     ├─ 层2 计划：无
  │     ├─ 层3 用户让记：报告相关的那条（query 加权后第一）
  │     ├─ 层4/5 推断：排除 OV 已展示
  │     └─ 每条 touch + last_inject
  │
  ├─ _blocks 拼接（10 块）
  ├─ _build_chat_messages → system prompt 里的【长期记忆】
  └─ LLM 回答时能看到"他让记·昨天: 周五交报告"
```
