# 07｜部署陷阱与审查方法：那些"逻辑看着对、一上线就炸"的问题

> 这篇不是问题清单（那是 `05_问题清单.md`），而是**方法 + 实例**：
> 教你怎么系统性地找出"本地能跑、部署就死"的问题，并给出本项目 35 个真实样本。
> 每条格式：**症状 → 代码 → 为什么看着对 → 部署时怎么炸 → 怎么查 → 怎么改**。
> 其中 E5 / E6 / E7 已于 2026-11-11 修复，保留在此作为事故档案与回归用例。

## 第一部分：六种检查法

### 检查法 1：把"本地跑过"逐条翻译成环境假设

代码能跑，是因为它**隐含依赖了 8 件事**。逐个问"换台机器还成立吗"：

| 隐含假设 | 本项目里的例子 | 换机器会怎样 |
|---|---|---|
| 有 D 盘 | `D:/FRIDAY/data` 写死 | 无 D 盘 → 数据写到失败 → 日志被吞 → 进程"启动了但什么都不做" |
| 当前目录是 backend | `Path("data")`、`Path("ui")` | 从桌面双击启动 → 找不到文件 |
| 控制台是 UTF-8 | 中文日志 | GBK 控制台 → `UnicodeEncodeError` 直接崩 |
| 端口空着 | 18080/18090/18095 | 上次没退干净 → `[Errno 10048]` |
| Ollama 已起 | embedding 11434 | 检索静默降级，用户只感觉"变笨" |
| OpenViking 已起 | 18095 | 同上 |
| 有网 | Live2D CDN、Tavily | 立绘空白、搜索失败 |
| 是 Windows | `CREATE_NO_WINDOW`、WMI | Linux 上 `creationflags` 参数直接 TypeError |

**审查动作**：`grep -rn "D:/\|D:\\\\\|C:/" backend/` 一次就能把环境假设全列出来。

### 检查法 2：找"同步原语出现在 async 函数里"

```
危险关键词：time.sleep / threading.Lock().acquire / requests.get / open(...).read()
                  / subprocess.run / .join() / socket.recv
```

**判定规则**：只要它在 `async def` 的调用链上，就是事件循环阻塞。本项目命中：

- `_safe_write_json` 里的 `time.sleep`（被 async 路由调用）
- `_json_io_lock` / `_chat_save_lock` 是 `threading.Lock`
- TFGR 的 `_persist()` 全量同步写盘

### 检查法 3：找"跨线程/跨协程共享的可变状态"

```
危险模式：模块级 list/dict 被多线程 append；单例 __new__ 无锁；全局 event loop 引用
```

本项目：`manager.active_connections`（list，async 单线程内安全，但 `broadcast` 里删除元素会跳过）、`BrainTools._instance`（无锁单例，两个线程同时首次调用会 new 两次）。

### 检查法 4：找"看起来有保护、实际没生效"的代码

这是最隐蔽的一类。本项目有两个教科书样本：

```python
# 样本 1：黑名单里塞正则，用 in 匹配 → 永远不命中
DANGEROUS_PATTERNS = ["curl.*|.*sh", "wget.*|.*sh"]
if pattern.lower() in content_lower:   # ← 字面量匹配
```

```python
# 样本 2：限流用 len % 5，但 len 被截断成常量 500
if len(history) > 500:
    history = history[-500:]
...
if len(history) % 5 == 0:   # 500 % 5 == 0，永远为真
```

**审查动作**：看到"阈值/比例/间隔"就手算一遍边界值（0、1、上限、上限+1）。

### 检查法 5：沿着"失败路径"走一遍

正常路径能跑不代表失败路径能跑。对每个 `try/except` 问：

1. except 里做了什么？只 `pass` → 失败被伪装成成功。
2. except 之后变量还在吗？`raise last_err` 且 `last_err=None`。
3. 失败后资源释放了吗？文件句柄、子进程、锁。
4. 失败后**状态一致**吗？写了一半的 JSON、注册了一半的工具。

本项目典型案例：`_bind_console_to_log` 的 `except Exception: pass` → 日志起不来时，你连"为什么日志起不来"都看不到。

### 检查法 6：把部署当"新用户第一次运行"演练

关掉所有已有进程，换一个干净目录，从 `start_pet.vbs` 开始。只看三件事：

1. 有没有任何**弹窗/黑框/中文乱码**？
2. 30 秒内日志有没有新增？
3. 打开页面，发一句话，气泡有没有出来？

90% 的部署问题在这 3 步内暴露。

## 第二部分：30 个真实实例

### A. 启动与进程（1–6）

#### A1. 先 import 后重定向 → 日志永远进不了文件

```python
# 错误顺序（会被这段代码的作者自己纠正过）
from api.server import app
_bind_console_to_log()
```

**为什么看着对**：两行都在，功能都调用了。
**部署时怎么炸**：`core/logger.py` 在 import 期创建 handler，绑到当时的 `sys.stdout`。之后再 dup2，handler 还指着旧 fd → 日志写到已经不存在的控制台 → 文件是空的。
**怎么查**：启动后 `ls -l D:/FRIDAY/logs/plus_backend.log`，看 mtime 是不是刚刚。
**怎么改**：`_bind_console_to_log()` 必须在 `from api.server import app` **之前**（现在是这么写的，注释也标了）。

#### A2. 包级 re-export 制造隐藏依赖

```python
# backend/brain/__init__.py（已修）
from .scheduler import Scheduler      # ← 模块删了，这里没删
from .goal import GoalEvaluator
```

**为什么看着对**：`scheduler.py` 删了，`grep scheduler` 已经搜不到引用。
**部署时怎么炸**：`import brain` → `ImportError`；而实际报错点是 `from brain.task_executor import ...`（任何一个 `brain.*` 子模块 import 都会先执行 `brain/__init__.py`）。**报错行号和真实原因完全不在一个文件**。
**怎么查**：`python -c "import brain"` 单独试；AST 依赖扫描要**额外扫包 `__init__.py` 的 re-export**。
**怎么改**：删 re-export；`__all__` 同步。

> 这是本次修剪实际踩到的坑，导致后端启动失败一次。

#### A3. `os.chdir` 是全局的

```python
os.chdir(BACKEND_DIR)
```

**为什么看着对**：保证相对路径能找到文件。
**部署时怎么炸**：任何库用相对路径读自己的资源（模板、字体、证书）都会找错；而且它影响整个进程，多线程下改 cwd 是竞态。
**怎么查**：`grep -rn "open(\"\|Path(\"" backend/` 看有多少相对路径。
**怎么改**：短期接受（单进程单入口），长期改成全部用 `Path(__file__).parent` 绝对路径。

#### A4. 端口被占 → 进程静默退出

```
ERROR: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 18080)
```

**为什么看着对**：uvicorn 会打日志。
**部署时怎么炸**：日志是 `log_level="warning"`，而这条恰好是 ERROR 会打；但如果外层是 `start_pet.vbs` 无窗口启动，用户什么都看不到，只看到"桌宠不动"。
**怎么查**：`netstat -ano | findstr :18080`；`Get-NetTCPConnection -LocalPort 18080`。
**怎么改**：启动前探测端口，占用则先杀旧进程或换端口（`FRIDAY_PLUS_BACKEND_PORT`）。

#### A5. VBS 无窗口启动 → 报错无处可见

```vbs
' start_pet.vbs
CreateObject("WScript.Shell").Run "powershell -WindowStyle Hidden -File ...", 0, False
```

**为什么看着对**：隐藏窗口是为了不打扰用户。
**部署时怎么炸**：Python 的 traceback 全进虚空；用户只看到"双击没反应"。
**怎么查**：必须有文件日志（`run_server.py` 的 dup2 就是为此）。
**怎么改**：任何无窗口启动的进程，第一件事是把 stdout/stderr 接到文件。

#### A6. `python.exe` 从 .ps1 重定向长驻 → "拒绝访问"

```
python.exe : 对路径的访问被拒绝
```

**为什么看着对**：`> log.txt 2>&1` 是最常见的日志写法。
**部署时怎么炸**：PowerShell 5 下重定向 + 长驻子进程会偶发权限错误（句柄继承问题）。
**怎么查**：换成 `Start-Process -RedirectStandardOutput` 也复现 → 确认是 shell 层问题。
**怎么改**：不要在 shell 层重定向，进程内部 `dup2`（当前方案）。

### B. 编码与文件（7–12）

#### B1. GBK 控制台 + 中文日志 = 崩溃

```python
logger.info("[Brain] 不说话的闸门: 好奇心0.31<0.6")
```

**为什么看着对**：日志用中文可读性好。
**部署时怎么炸**：Windows 控制台默认 GBK（cp936），`"闸"` 在某些 cp936 变体里编码失败 → `UnicodeEncodeError` → logging 内部异常 → 进程崩。
**怎么查**：`chcp` 看代码页；`python -c "print('闸')"` 试。
**怎么改**：`PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1`（`run_server.py` 已设）+ 日志文件用 utf-8 打开。

#### B2. BOM 让 .ps1 解析错乱

```
# 注释里写中文，文件保存为 UTF-8 with BOM
```

**为什么看着对**：UTF-8 是正确编码。
**部署时怎么炸**：PowerShell 5 把 BOM-less UTF-8 当 ANSI 读 → 中文注释变乱码 → 引号配对错 → `ParserError: 字符串缺少终止符`。带 BOM 反而正常。
**怎么查**：`Format-Hex file.ps1 | Select-Object -First 1` 看前 3 字节是不是 `EF BB BF`。
**怎么改**：.ps1 只用 ASCII（当前 `start_plus_backend.ps1` 的头注就是这么写的："ASCII only on purpose"）。

> 本次会话中用它筛日志就撞过一次 `字符串缺少终止符`。

#### B3. Windows 文件锁 + 原子写

```python
os.replace(tmp, target)   # 目标文件正被另一个进程打开 → PermissionError
```

**为什么看着对**：`os.replace` 文档说"原子"。
**部署时怎么炸**：Windows 上目标文件被任何进程以非共享方式打开（杀毒软件扫描、编辑器、另一个 Python 的 `open`）时，`replace` 抛 `PermissionError`。Linux 上不会。
**怎么查**：`handle.exe target.json` 或资源监视器看谁占着。
**怎么改**：重试 + 退避（当前方案）；读方全部短开短关，不长期持有句柄。

#### B4. `tempfile.NamedTemporaryFile` 在异常云盘上无限重试

```python
with tempfile.NamedTemporaryFile(...) as f:   # ← 本项目明确禁用
```

**为什么看着对**：官方推荐写法。
**部署时怎么炸**：Python 3.12 `TMP_MAX=2^31`；某些云盘/虚拟盘过滤驱动让 `O_EXCL` 创建持续返回"已存在" → 库内部循环重试 → CPU 100% + 事件循环焊死 → 所有请求超时。
**怎么查**：CPU 单核打满 + 无日志输出 + 所有 HTTP 超时，三点同时出现。
**怎么改**：uuid 文件名 + 有限次重试（`_safe_write_json` 的注释记了这次事故）。

#### B5. 日志编码混写

```python
# 一半代码用 logging（handler 设了 utf-8），一半直接 print（走控制台 GBK）
print("[debug] 中文")
```

**为什么看着对**：都能看到输出。
**部署时怎么炸**：print 走 GBK 崩；且两种输出混在同一文件里，一半 utf-8 一半 GBK → `tail` 时乱码。
**怎么查**：`file plus_backend.log`；`tail` 看是否有乱码段。
**怎么改**：统一走 logger；禁止 `print`。

#### B6. 长路径（>260 字符）

```python
filepath = Path("D:/FRIDAY/data") / "..." / 很长的名字
```

**为什么看着对**：`pathlib` 处理路径很稳。
**部署时怎么炸**：Windows 默认 `MAX_PATH=260`，超过就 `OSError: [Errno 2]`；项目里的视频产物名带时间戳 + 中文标题，很容易超。
**怎么查**：`Get-Item` 报"路径过长"。
**怎么改**：启用长路径策略（注册表 `LongPathsEnabled=1`），或截断文件名。

### C. asyncio 与并发（13–19）

#### C1. `time.sleep` 在事件循环里

```python
def _safe_write_json(...):          # 普通函数
    ...
    _time.sleep(min(1.0, 0.1 * (2 ** attempt)))

# 调用点
async def some_route():
    _safe_write_json(path, data)    # ← 阻塞整个 loop
```

**为什么看着对**：函数是同步的，sleep 当然用 `time.sleep`。
**部署时怎么炸**：写失败重试 5 次，最长阻塞 1.5 秒。这期间**所有** WS 心跳、所有对话、所有广播全停。用户感受："卡了一下"。
**怎么查**：在事件循环里加 slow-callback 监控（`asyncio.get_running_loop().slow_callback_duration`）。
**怎么改**：改 async + `asyncio.sleep`，或 `await asyncio.to_thread(...)`。

#### C2. 同步函数里 `asyncio.create_task`

```python
def _save_chat_message(msg):
    ...
    asyncio.create_task(_streaming_write_recent_to_viking(...))
```

**为什么看着对**：调用点都在 async 上下文里，能跑。
**部署时怎么炸**：只要有**一处**从线程池/回调/同步启动路径调用它 → `RuntimeError: no running event loop`；若外层还有宽 `except`，就是静默不写。
**怎么查**：`grep -n "create_task" ` 然后看每个调用点的上下文。
**怎么改**：传 `loop` 进来，或用 `asyncio.run_coroutine_threadsafe`，或让函数本身 async。

#### C3. `create_task` 不保存引用 → 任务被 GC

```python
asyncio.create_task(_avatar_back_to_idle())
```

**为什么看着对**：任务启动就行。
**部署时怎么炸**：事件循环只持弱引用；任务在 await 之前被 GC → 静默不执行；异常也只会打 "Task exception was never retrieved"。
**怎么查**：日志里搜 "never retrieved"。
**怎么改**：存进 `self._tasks: set`，`add_done_callback` 里移除。

#### C4. `threading.Lock` 保护 async 临界区

```python
with _json_io_lock:          # threading.Lock
    for attempt in range(retries):
        ...
        _time.sleep(...)
```

**为什么看着对**：锁能防并发写。
**部署时怎么炸**：持锁的协程 sleep 1 秒 → 另一个协程 `with lock` 阻塞事件循环 → 死等到锁释放 → 所有请求停 1 秒。极端情况两个协程互相等（若锁被线程持有且线程在等 loop）→ 永久卡死。
**怎么查**：`grep -n "threading.Lock\|Lock()"`，逐个看它是否被 async 函数使用。
**怎么改**：async 路径用 `asyncio.Lock`；同步锁只保护纯同步函数（不 sleep）。

#### C5. 广播串行 await

```python
for connection in self.active_connections:
    await connection.send_text(raw)
```

**为什么看着对**：逐个发最直观。
**部署时怎么炸**：一个客户端卡住（浏览器标签休眠、网络抽风）→ 整条广播链停 → 对话的后续广播全排队 → 用户看到"话说一半不动了"。
**怎么查**：多开几个前端，其中一个用调试器暂停 JS，看其他前端是否也卡。
**怎么改**：并发发送 + 单连接超时；失败即摘除。

#### C6. 断连不清理 → 僵尸连接

```python
except Exception:
    pass          # ← 不 disconnect
```

**为什么看着对**：异常吞掉不影响主流程。
**部署时怎么炸**：僵尸永远留在列表里，每次广播都白等一次异常 → 广播越来越慢。
**怎么查**：`/api/brain/status` 若返回连接数，看是否只增不减。
**怎么改**：except 里 `disconnect(connection)`。

#### C7. 无心跳

**为什么看着对**：反代层设了 `ping_interval=30`。
**部署时怎么炸**：后端自己不发 ping，中间 NAT/防火墙 5 分钟无流量就掐连接，而 Python 端不知道 → 半开连接。
**怎么查**：空闲 10 分钟后发消息，看是否必须重连才恢复。
**怎么改**：服务端定时 `send ping`，或客户端定时发心跳并在超时后重连。

#### C8. `asyncio.Event` 跨线程 set

```python
def trigger_brain_analysis():     # 可能在线程里被调
    _brain_analysis_trigger.set() # Event 绑定的是某个 loop
```

**为什么看着对**：`Event.set()` 看起来线程安全。
**部署时怎么炸**：`asyncio.Event` 不是线程安全的；跨线程 set 可能丢唤醒（waiter 列表在另一个 loop 上）。
**怎么查**：日志里"触发了但没分析"偶发。
**怎么改**：`loop.call_soon_threadsafe(event.set)`。

#### C9. 队列满时的行为没定义

```python
queue_size=50
```

**为什么看着对**：有上限就不会爆内存。
**部署时怎么炸**：满时是 `put_nowait` 丢任务，还是 `await put` 阻塞？前者静默丢，后者卡死生产者（可能在对话路径上）。
**怎么查**：压测 60 个任务，看第 51 个的行为。
**怎么改**：显式定义丢弃策略 + 告警。

### D. 网络与安全（20–24）

#### D1. CORS `*` + `allow_credentials=True`

```python
app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_credentials=True, ...)
```

**为什么看着对**：本地开发方便。
**部署时怎么炸**：浏览器规范禁止 `*` + credentials 组合，实际行为是**退回不允许**；某些客户端库会静默不带头 → 鉴权失败。更危险的是：任何网页都能跨域读本机 API。
**怎么查**：DevTools Network 看 `Access-Control-Allow-Origin`。
**怎么改**：明确列 `http://127.0.0.1:18090`。

#### D2. 无鉴权的执行端点 = RCE

```
POST /api/workspace/execute   {"content": "脚本内容"}
```

**为什么看着对**：只绑 `127.0.0.1`，外网进不来。
**部署时怎么炸**：本机任何进程（含恶意网页通过 DNS rebinding、Electron 里的第三方脚本）都能 POST → 以当前用户权限执行任意代码。
**怎么查**：`curl -X POST 127.0.0.1:18080/api/workspace/execute -d '{...}'` 直接验证。
**怎么改**：token + Origin 校验 + 危险操作二次确认。

#### D3. 密钥明文在仓库

```json
// backend/config/config.json
{"llm": {"api_key": "sk-..."}}
```

**为什么看着对**：本地项目，方便。
**部署时怎么炸**：截图、发群、传 GitHub（Pro 已经上传过）→ key 泄露 → 被刷爆。
**怎么查**：`grep -rn "sk-\|api_key" --include=*.json .`
**怎么改**：环境变量 + 启动时校验；仓库里放 `config.example.json`。

#### D4. 502 响应回显内部异常

```python
return JSONResponse({"error": f"Pro 后端没起或连不上：{e}"[:200]}, status_code=502)
```

**为什么看着对**：方便调试。
**部署时怎么炸**：`e` 里可能带内网地址、端口、甚至栈片段；如果页面被投屏/共享，等于泄露拓扑。
**怎么查**：故意停后端，看返回体。
**怎么改**：对外只回"上游不可用"，详情进日志。

#### D5. `max_size=None` 的 WS

```python
up = await websockets.connect(PRO_WS, max_size=None, ...)
```

**为什么看着对**：防止大帧被拒（比如图片 base64）。
**部署时怎么炸**：任何客户端可以发 GB 级帧 → 内存爆。
**怎么查**：发一个 100MB 的 JSON。

#### E5. 只改小时没改分钟 → 提醒落在"现在这一分"

```python
    ...
else:
```

**状态**：2026-11-11 已修复，并同时补了 `N 分钟后` 与"只说时段不给日期→按今天算"两个缺口。

#### E6. 共用模板的主动消息被"太像"闸全拦


**为什么看着对**：防复读，阈值看着合理。
**部署时怎么炸**：主动消息常用同一模板——"提醒你一下：喝水" vs "提醒你一下：吃药"，去标点后 8 个字里有 7 个相同，相似度 0.875 → **第二条直接不说**。用户以为"它忘了提醒"，实际是被自己的闸拦了。
**怎么查**：跑 `原理库/05_mind.py` 最后的"回归验证"段。
**怎么改**：比较前剥掉固定模板前缀（`_dedup_key`）；或对 `kind=="reminder"` 的文本跳过相似度检查。
**状态**：2026-11-11 已修复（`brain/mind.py::_dedup_key`，`_should_speak` 里改用去前缀后再比）。

#### E7. 取模限流配截断，满额后恒真

```python
if len(history) > 500:
    history = history[-500:]
...
if len(history) % 5 == 0:          # 满 500 后长度恒为 500 → 500 % 5 == 0 恒真
    asyncio.create_task(_streaming_write_recent_to_viking(history[-5:]))
```

**为什么看着对**："每 5 条同步一次"，取模是最直白的写法。
**部署时怎么炸**：前 500 条正常（每 5 条一次），一旦历史满 500 条，**每条消息都触发一次全量同步**。1000 条消息下同步次数 600 vs 正常 200，写入量翻 3 倍；如果同步走网络，"聊得越久越卡"但没人会怀疑到这行。
**怎么查**：手算边界——把变量的完整取值范围（1…500、501、501+）走一遍，别只看中间值。
**怎么改**：独立计数器（`_viking_sync_counter`），与列表长度彻底解耦。
**状态**：2026-11-11 已修复，并把"取快照"挪进锁内。

## 第四部分：怎么在面试里讲这些（话术）

> **问：你做过最难的 bug 是什么？**
>
> "删掉五个死模块后，后端起不来，报 `No module named 'brain.scheduler'`。
> 我用 AST 扫了全项目的 import 图，确认没有任何文件 import 它，入度是 0。
> 真正的原因在 `brain/__init__.py`——它做了包级 re-export，任何 `import brain.xxx` 都会先执行包初始化。
> 这件事让我把依赖扫描从'扫模块内部'改成'扫模块内部 + 扫包 `__init__` 的 re-export + 扫动态 import 字符串'。
> 后来我把这条写进了团队的审查清单第一条。"

> **问：你怎么保证代码在别人机器上也能跑？**
>
> "我把'本地能跑'拆成 8 个隐含假设：盘符、cwd、编码、端口、外部服务、网络、OS、权限。
> 每写一段依赖环境的代码，就问这 8 条还成不成立。
> 比如这个项目的日志初始化，就同时踩了'盘符写死 D:'和'控制台 GBK'两条——
> 结果是日志起不来、异常被 `except: pass` 吞掉，进程看起来在跑但什么都不做。
> 这类问题本地永远复现不了，只能靠假设清单去推。"

> **问：你见过最隐蔽的 bug 是什么？**
>
> "一个'每 5 条消息同步一次'的功能，写的是 `if len(history) % 5 == 0`。
> 逻辑完全正确——直到上面三行有个 `history = history[-500:]`。
> 满 500 条之后，长度恒为 500，`500 % 5 == 0` 恒真，于是每条消息都触发一次同步。
> 性能问题不会报错，只会让 VPS 的写入量涨 100 倍。
> 这类 bug 的通用查法是：看到取模，就把变量的取值范围从头到尾走一遍。"

## 第五部分：把检查变成脚本

```python
# risk_scan.py —— 放到仓库根目录，CI 里跑
import re, sys
from pathlib import Path

RULES = [
    ("HIGH", r"time\.sleep\(", "同步 sleep：确认不在 async 调用链上"),
    ("HIGH", r"create_task\((?![^)]*\b_)", "create_task 可能没保存引用"),
    ("HIGH", r"allow_origins=\[\"\*\"\]", "CORS 全开"),
    ("HIGH", r"shell\s*=\s*True", "shell=True 有注入风险"),
    ("HIGH", r"except\s+Exception\s*:\s*\n\s*pass", "吞异常"),
    ("MED",  r"len\([^)]+\)\s*%\s*\d+\s*==", "取模限流：检查变量是否被截断"),
    ("MED",  r"D:/", "硬编码 D 盘"),
    ("MED",  r"threading\.Lock\(\)", "线程锁：确认没在 async 里持锁 sleep"),
    ("MED",  r"open\([^)]*\)\.read\(\)", "同步读文件"),
    ("LOW",  r"print\(", "用 print 而不是 logger"),
]

def scan(root="."):
    bad = 0
    for p in Path(root).rglob("*.py"):
        if "__pycache__" in str(p):
            continue
        for i, line in enumerate(p.read_text("utf-8", errors="replace").splitlines(), 1):
            for level, pat, msg in RULES:
                if re.search(pat, line):
                    print(f"{level:4s} {p}:{i}  {msg}\n      {line.strip()[:110]}")
                    bad += 1
    print(f"\n共 {bad} 处命中")
    return 1 if any(True for _ in [0]) and bad else 0

if __name__ == "__main__":
    sys.exit(scan(sys.argv[1] if len(sys.argv) > 1 else "."))
```

> 这个脚本只能抓"形"，抓不到"意"。它存在的意义是**把注意力引导到高风险行**，剩下的判断还得人做。
