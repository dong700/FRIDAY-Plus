## 1. 进程与启动

### 1.1 四个进程

| 进程 | 端口 | 入口 | 职责 |
|---|---|---|---|
| 后端 | 18080 | `backend/run_server.py` | FastAPI 真身：HTTP + WS + 全部业务 |
| 页面/反代 | 18090 | 根目录 `server.py` | 服 `ui/` 四个单页；`/api` 转发到 18080；`/ws` 双向桥接 |
| 桌宠窗 | — | `electron/main.js` | Electron 加载 `http://127.0.0.1:18080/?pet=1` |
| 上下文库 | 18095 | `openviking-server` | 本地语义检索（embedding 走 Ollama 11434） |

为什么桌宠走 18080、控制台走 18090：桌宠只要"对话 + 立绘"，控制台要"四个页面 + 反代"，两者 userData 不同，可以同时开。

### 1.2 启动链

```
start_pet.vbs
  ├─ 先跑 start_plus.vbs（保证 18090 和控制台窗口）
  ├─ 18080 没监听 → powershell start_plus_backend.ps1
  │      └─ python -u run_server.py
  │             ├─ os.dup2(日志文件, 1/2)   ← 先接日志，再 import
  │             └─ from api.server import app; uvicorn.run(ws="wsproto")
  └─ electron.exe electron/main.js --url=http://127.0.0.1:18080/?pet=1 --port=18080
```

`run_server.py` 里有两个"踩过坑"的细节，值得背下来：

1. **先 `dup2` 再 import**：logger 在 `api.server` 导入时初始化，如果先 import，handler 会绑到旧 stdout，日志永远进不了文件。
2. **`ws="wsproto"`**：环境的 websockets 16 与旧 uvicorn 握手不兼容，不指定会连不上。

### 1.3 根 `server.py` 只做三件事

```
GET  /            → ui/index.html
GET  /<page>      → ui/{atg,tfgr,status}.html
/api/*            → httpx 原样转发 18080
WS   /ws          → websockets 连 18080/ws，双向 pump
```

**坑**：它是"反代"不是"网关"，没有鉴权、没有限流；`/api` 的异常一律 502，前端看不出是后端挂了还是路由写错。

## 2. 协议层：一条消息怎么走

### 2.1 WS 事件表（前端 ↔ 后端）

| 方向 | type | 说明 |
|---|---|---|
| ↑ | `chat.send` | 用户发消息，payload 可带 `content` / `image` / `client_msg_id` |
| ↓ | `chat.send_result` | 本轮结果（success/content 或 error） |
| ↓ | `chat.message` | 追加一条消息（用户/AI 都走它，前端按 id 去重） |
| ↓ | `mind.thinking` / `mind.delta` / `mind.end` | 流式：开始思考 / 增量文本 / 结束 |
| ↓ | `avatar.*` | `thinking` / `speaking` / `speaking_end` / `action` / `idle_action` / `proactive` |
| ↓ | `brain.status` / `brain.reasoning` | 动机值、推理日志 |
| ↑↓ | `workspace.*` / `executor.*` / `skill.*` / `pet.move` | 工作区、执行器、技能、桌宠位置 |

### 2.2 一次对话的 12 步（`handle_chat_send`，729→1403）

```
1  保存用户消息 + 广播 chat.message                 765-770
2  负反馈：用户否定 → 最近注入的推断降权             774-781
3  重置心智"被无视"计数                             783-788
4  规则解析提醒 → tfgr.remember()，命中就跳过执行器    798-812
5  快速决策（要不要搜索/要不要跑任务），一次模型调用    823-850
6  记忆检索：本地 substring + Viking（默认关）        852-913
7  组装材料块 _blocks                                955-1035
     ├─ 刚记下的提醒
     ├─ 最近 3 条回复（别复读）
     ├─ 10 分钟内重复问题提示
     ├─ OpenViking 语义命中（带日期/来源标签）
     ├─ 图片/搜索/工具/屏幕观察
     └─ tfgr.digest(query=当前消息, 排除 OV 已展示的)
8  _build_chat_messages：system prompt + 材料          119
9  可选：机械臂 / 表情 / 头像工具 Function Calling      1040-1209
10 流式生成 → mind.delta；失败回退一次性 chat          1228-1298
11 刚说过闸门：相似度 ≥0.9 重写                       1307-1322
12 提醒闭环 mark_done → 结构化记忆落库 → 广播 chat.message
```

### 2.3 为什么第 7 步要"分块"

`_build_chat_messages` 的 system prompt 里写死了一条规则：

> 「他正在看的视频」≠「他给你读的稿子」。

因为材料来源混成一坨时，模型会把"屏幕观察"当成用户口述。分块 + 每块带来源名，是在**用 prompt 结构对抗模型的混淆倾向**。

## 3. 提示词与上下文组装

### 3.1 system prompt 的骨架（`_build_chat_messages`, 119）

| 段 | 作用 | 常见坏味道 |
|---|---|---|
| 你是谁 | 桌宠立绘 = 本人；没有"另一个大脑" | 写太抽象，模型仍会推给"视觉模块" |
| **不可推翻的自我边界** | 5 条硬事实：谁、屏幕上哪个是、视频里的不是、没身体、不许改口 | 加得越晚越容易被长上下文冲掉 |
| 当前时间 | 精确到秒 + Unix 时间戳 | 时区没写（依赖系统本地时区） |
| 材料来源 | 六类来源 + 不许混用 | 来源名和块标题必须逐字一致 |
| 对话原则 | 简短、不用 markdown、别编造工具结果 | 与前端气泡宽度耦合，改 UI 要同步改这里 |
| 结构化输出 | `<memory>` JSON：atg + tfgr | JSON 容错全靠 `load_memory_json` |
| 时间轴钩子 | `<<after/idle/on>>` | 语法解析 310 行，见 4.3 |

### 3.2 材料块的预算（实测）

一次普通对话：

```
[MemInject] ov=6 digest_lines=10 blocks=5 chars=1724
```

- OV 命中：最多 6 条 × 240 字，带 `[11-08 当天汇总]` / `[11-10 我推断]`。
- TFGR 摘要：最多 10 条 / 1,200 字，顺序是「到点提醒 > 带时间计划 > 他让记 > 钉住推断 > 相关推断」。
- 重复问题块、最近 3 条回复块：各 1 块，共约 300 字。

**坑**：块之间没有全局去重，只做了 "OV ↔ TFGR 推断" 这一对；`memory_context`（本地 substring）和 OV 仍可能重复。

## 4. 解析专题：五个解析器

这一节是"最小原型"最多的地方——解析逻辑最独立，最适合拿来练手。

### 4.1 时间解析 `_parse_when`（2841）

**输入**：一句中文。**输出**：时间戳 / None。

决策顺序（顺序本身是设计）：

```
① 相对量：N 天后 / N 小时后        → 直接返回
② 日偏移：大后天 → 后天 → 明天 → 今天/今晚
③ 周几：  下周三 / 周三            → 覆盖 ② 的日期
④ 月日：  11月25日                 → 覆盖 ②③
⑤ 几号：  20号（本月过了顺延下月）  → 只在前面都没命中时
⑥ 钟点：  15:30 / 三点 / 三点半 / 下午三点 → 只改时分
⑦ 约束：  算出时间 ≤ 现在 → +1 天
```

**实测表**（基准 2026-11-10 11:14，周二）：

| 输入 | 结果 | 备注 |
|---|---|---|
| 下周三下午三点提醒我开会 | 11-18 15:00 | 中文数字钟点 |
| 10天后提醒我交实习报告 | 11-20 11:14 | 相对量保留当前时分 |
| 20号上午提醒我交材料 | 11-20 09:00 | "上午"无钟点默认 9 点 |
| 明天上午九点半提醒我 | 11-11 09:30 | "半" = 30 分 |
| 今晚八点提醒我看直播 | 11-10 20:00 | "今晚"要当 PM 标记 |
| 3小时后提醒我关火 | 11-10 14:14 | |
| 记得提醒我买牛奶 | None（due 为空，只钉住） | 没有时间 |

**最小原型**（去掉无关分支，能独立运行）：

```python
import re
from datetime import datetime, timedelta

CN = {"一":1,"二":2,"两":2,"三":3,"四":4,"五":5,"六":6,"七":7,"八":8,"九":9,"十":10}

def when(raw, now=None):
    now = now or datetime.now()
    m = re.search(r"(\d+)\s*(?:天)\s*(?:后|以后|之后)", raw)
    if m:
        return now + timedelta(days=int(m.group(1)))
    base = None
    if "明天" in raw: base = now + timedelta(days=1)
    elif "今天" in raw or "今晚" in raw: base = now
    m = re.search(r"(下)?(?:周|星期)([一二三四五六日天])", raw)
    if m:
        target = "一二三四五六日".index(m.group(2).replace("天","日"))
        ahead = (7 - now.weekday()) + target if m.group(1) else (target - now.weekday()) % 7
        base = (now + timedelta(days=ahead)).replace(hour=9, minute=0)
    if base is None:
        return None
    hh, mm = base.hour, base.minute
    tm = re.search(r"(\d{1,2})\s*[点:：]\s*(\d{1,2})?", raw)
    cn = re.search(r"([一二两三四五六七八九十]{1,3})\s*[点时]", raw)
    if tm:
        hh, mm = int(tm.group(1)), int(tm.group(2) or 0)
    elif cn:
        hh, mm = CN.get(cn.group(1), hh), 0
    if any(k in raw for k in ("下午","晚上","今晚")) and hh < 12:
        hh += 12
    dt = base.replace(hour=hh, minute=mm, second=0, microsecond=0)
    return dt + timedelta(days=1) if dt <= now else dt
```

**边界坑（都能现场演示）**：

- `"3天后"` 会被相对量分支吃掉，永远到不了"3号"分支——顺序就是语义。
- `"下个月" / "过几天" / "这两天"` 只在 `_REMIND_DAYS` 里被认成"有时间"，但 `_parse_when` **没有对应分支**，结果 `due_at=None`：只钉住、不会到点唤醒。这是当前最容易漏的一类。
- `"12月31日"` 跨年判断用 `(month, day) >= (now.month, now.day)`，12 月问 1 月会顺延到下一年，符合直觉；但 `"2月30日"` 会 `ValueError` 被捕获返回 None。
- 正则不认 `"半"` 以外的中文分钟（如"三点二十"），只认 `"三点半/一刻/三刻"`。
- `"下午三点"` 中没有 AM/PM 时 `"三点"` 会被当成 15:00 还是 3:00，取决于有没有"下午/晚上/今晚"——`"三点提醒我"` 在凌晨会算成 03:00，第二天。

### 4.2 提醒识别 `_parse_reminder`（2981）

三层过滤，缺一层就会误判：

```python
1 触发词：提醒 / 记住 / 记得 / 别忘了 / 别忘 / 到时候
2 排除反问："你还记得吗" / "记不记得…？"
3 必须有祈使（"提醒我/帮我记/记住…"）或（有时间 + "提醒"）
4 以"的/吗/？"结尾且没有时间 → 不算（"提醒我一下这段代码是干嘛的"）
```

**坑**：`"记住这个函数名"` 会被当成提醒（命中"记住"）；`"记得提醒我"` 与 `"你还记得吗"` 的分界全靠正则的 6 字窗口，长句容易漏。

### 4.3 钩子解析 `parse_hook_specs`（`brain/mind.py:187`，约 310 行）

模型在回复末尾留：

```
<<after=120 note=过两分钟问问进度>>
<<idle=600 note=用户很久没动了>>
<<on=phone.boot note=手机开机了>>
```

解析产物 `HookSpec(kind, seconds, match, note, raw)`，再进 `MindRuntime.add_hook`。

**为什么 310 行**：要兼容模型自由发挥——引号、全角、缺 note、多个钩子混在一行、和其他标记嵌套。**这是"解析要防御模型"的典型样本**：输入不是用户，是另一个概率模型。

**坑**：`after=0` / 负数 / 超大值没有统一上限；`on=` 的 match 是子串匹配（`_matches`），`on=work` 会命中 `work.start` 和 `work.end`。

### 4.4 结构化记忆 `<memory>`

链路：`StreamFilter`（流式过滤）→ `extract_memory`（截 `<memory>…</memory>`）→ `load_memory_json`（容忍 ```json 包裹）→ `apply_memory`（写 ATG / TFGR）。

**坑**：JSON 截断（模型没写完就被截流）只能返回 None，不报错；`atg` 与 `tfgr` 混写时没有字段级校验，`kind` 非法值会被 `record_thought` 静默忽略。

### 4.5 OpenViking 标签 `_ov_label`（2945）

把 `viking://resources/friday/tfgr/2026-11-08.md` 变成 `[11-08 当天汇总]`；`mem/<id>.md` 则回查 TFGR 拿 `kind` 和 `ts`，变成 `[11-10 我推断]` / `[11-10 他让记]`。

**价值**：模型终于能区分"今天刚记的"和"两周前的旧推断"，减少把旧判断当现在事实。

**坑**：`get(id)` 是 O(n) 线性查；文档被删/事件被 prune 后只能落到 `[旧记录]`。

## 5. TFGR：记忆的四个问题

`brain/tfgr.py`（1,014 行）回答四个问题：**记什么、多重要、什么时候想起来、什么时候删**。

### 5.1 数据结构

```python
@dataclass
class TFEvent:
    id, ts, kind, text, source
    end_ts, entities, refs, confidence, basis
    meta: dict          # pin / due_at / done / last_hit / last_inject / negated
```

`kind` 分两类：

- `MENTAL_KINDS = (belief, story, intent, pattern)`：模型自己的推断；
- `USER_KINDS = ("memory",)`：用户明确让记的事。

**分开存的原因**：注入时必须标来源，否则模型会把自己的猜测当用户亲口说的。

### 5.2 重要度 `importance`（423）

```python
score  = KIND_WEIGHT[kind]          # memory 1.00 / intent 1.00 / belief .85 / story .55
score += 0.25 × confidence
score += min(0.15, 0.05 × 实体数)
score += 1.00 if pin
score += 1.50 if due_at
score *= 0.5 ** (age_days / 14)     # last_hit 起算的半衰期
score *= 0.55 if negated
```

**设计点**：`due_at` 的 1.5 是最重的一项——"10 天后提醒你"比今天所有推断都重要；`last_hit` 让"从没被想起来"的推断自然沉底。

### 5.3 注入 `digest`（590）

分层挑人，不是全局排序：

```
1 到点/快到的提醒（6 小时窗口）        ← 不参与去重，宁重不漏
2 带明确时间、还没完成的计划
3 USER_KINDS（他让记）
4 钉住的推断（和 OV 已展示的去重）
5 其余推断，按「重要度 + 0.6 × 当前问题字面重合 + 0.08 粘性」
```

**为什么要有粘性**：`touch()` 每次更新 `last_hit`，两个分数接近的推断会每轮互换位置，prompt 来回抖动。10 分钟内 +0.08 让刚注入的先站住。

**最小原型**（30 行，能解释整个分层思想）：

```python
def digest(items, now, query="", budget=10):
    picked, seen = [], set()
    def take(e, dedup=False):
        if len(picked) >= budget or e.id in seen:
            return
        seen.add(e.id); picked.append(e)
    for e in sorted((x for x in items if x.due_at and x.due_at <= now + 6*3600),
                    key=lambda x: x.due_at):
        take(e)                                   # 1 到点
    for e in sorted((x for x in items if x.kind == "memory"),
                    key=lambda x: -importance(x, now)):
        take(e)                                   # 2 他让记
    for e in sorted((x for x in items if x.kind in MENTAL),
                    key=lambda x: -(importance(x, now) + 0.6 * overlap(query, x.text))):
        take(e, dedup=True)                       # 3 推断
    return picked
```

**坑**：`digest` 每次遍历全量事件（当前 780+ 条），每轮对话一次；事件到 2,000 上限时是 2,000 次遍历 + 多次 `SequenceMatcher`，还没做分桶/索引。

### 5.4 清理：`consolidate`（684）与 `prune`（731）

| 函数 | 规则 | 保护 |
|---|---|---|
| `consolidate` | 7 天内 difflib ≥0.9 的跨表述合并；置信度取高 +0.03 | 带 `due_at` 的一条都不合（不同时间点是两件事） |
| `prune` | 噪声类先删；超上限按 `(噪声优先, importance 升序, ts)` 删 | `pin` / `due_at` 不受 TTL 影响；有 `due_at` 的最后才动 |

### 5.5 提醒生命周期（这一轮补的）

```
remember(text, due_at)  → meta.pin + meta.due_at
due()                   → 6 小时窗口内、未 done
digest                  → 【已到点】/【还有X天】排最前
Mind 到点唤醒            → 说出口 → mark_done("mind_say")
聊天回复命中              → 汉字重合 ≥40% → mark_done("chat_reply")
```

**坑**：`_reply_mentions` 用"汉字集合重合度"判断，短提醒（"交报告"）三个字里出现两个就算命中，可能误标完成。

## 6. Mind：事件驱动的"什么时候开口"

### 6.1 六个数据结构

```python
Event(kind, text, source)         # 外界/内部发生的事
Hook(kind, due, match, note)      # at / idle / on 三种时间轴钩子
Trigger(reason, hooks)           # 这次醒来的原因
HookSpec                        # 解析后的钩子
StreamFilter                    # 流式过滤 <memory> / <<hook>>
MindRuntime                     # 单例：事件队列 + 钩子 + 去重 + 说话判断
```

### 6.2 主循环

```
_next_timeout()      → 最近的钩子 / 下一条 due，二者取小（最短 0.5s）
_select_trigger()    → 到点提醒优先 → 到期钩子 → 待处理事件
_think(trigger)      → 组装上下文 → 流式生成 → 过滤标记
_should_speak()      → 社交判断（见下）
_emit(mind.delta/chat.message)
```

### 6.3 `_should_speak` 的四道闸（808）

1. 旁白式沉默（`（不打扰）`）→ 拦掉，真想沉默就输出空；
2. 和 `_recent_says` 里任一句 `_too_similar` → 拦掉；
3. 连续两次主动说话没被回应 → 闭嘴等用户；
4. 用户在工作软件里 → 压着，等 `work.end`。

`_too_similar`（608）：difflib ≥0.62 或 2-gram 交集 ≥0.55。**0.62 很激进**——同一主题换角度也会被拦，这是"宁可少说"的取舍。

### 6.4 两套机制的收口

这一轮删掉了 `brain_main_loop` 里的 `proactive_dialog`，现在：

- **Mind**：唯一有权主动生成消息的地方；
- **brain_main_loop**：只算动机、更新状态、跑表情，日志打真实闸门。

面试可以这么讲：*"两个循环同时存在时，问题不是谁对，而是没有一处能回答'它为什么说话'。我把说话权收敛到 Mind，另一个循环降级为状态机。"*
